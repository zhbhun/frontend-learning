# 分享与嵌入

看板默认只有登录后的站点成员能看——未登录访客打开看板地址只会得到 404。要把数据给到成员之外的人（读者、客户、公众、内部 wiki 的读者），Plausible 提供三种对外可见性方式：**公开可见性**把整个看板放到固定地址上，**分享链接（shared links）**生成带随机令牌、可设密码的只读链接，**嵌入看板（embed dashboard）**则建立在分享链接之上，把看板装进 iframe 嵌到任意网页。三者都在站点设置的 **Visibility** 页管理——本地实例为 `http://localhost:8000/test.local/settings/visibility`，页面上对应 Public dashboard、Shared links、Embed dashboard 三个区块。

三种方式共享同一条授权规则：站点公开或持有有效分享链接的访客按「public」角色访问，只能读看板、看不到账号下其他站点、改不了任何设置（v3.2.1 源码 `AuthorizeSiteAccess` 核对）。**CE v3.2.1 全部可用**：社区版没有订阅计费，团队被视为始终处于试用状态，可用功能为全集减去 Sites API 与 SSO，Shared Links 与 Site Segments 均在列（`lib/plausible/teams.ex` 的 `on_trial?` CE 分支与 `lib/plausible/teams/billing.ex` 的 `allowed_features_for`）。

| 方式 | 地址形态 | 访问门槛 | 可否撤销 | 适用场景 |
| --- | --- | --- | --- | --- |
| 公开可见性 | `<基址>/<域名>`（如 `http://localhost:8000/test.local`），固定且可猜测 | 无，任何人可访问 | 关闭开关即恢复私有 | 公开透明页（如放在页脚的「本站统计」） |
| 分享链接 | `<基址>/share/<域名>?auth=<随机令牌>`，地址不可猜测 | 知道链接即可；可加密码 | 删除链接即 404，立即生效 | 给客户、合作方看只读看板，不占成员名额 |
| 嵌入看板 | 由分享链接加参数生成的 iframe 代码 | 跟随底层分享链接（不能带密码） | 撤销底层分享链接即失效 | 内部 wiki、产品后台、Notion 等页面内嵌 |

## 公开可见性

公开可见性是站点级开关：打开后，看板地址本身（`/<域名>`）对任何人可见，无需登录、无需令牌。这是官方公开演示看板 [plausible.io/plausible.io](https://plausible.io/plausible.io) 使用的机制。

**操作路径**（本地实例可照做）：打开 `http://localhost:8000/test.local/settings/visibility`，在 **Public dashboard** 区块打开开关，文案显示「Make stats publicly available on `http://localhost:8000/test.local`」。表单实际提交到 `POST /sites/test.local/make-public`（v3.2.1 路由核对）。**证据**：开一个无痕窗口直接访问 `http://localhost:8000/test.local`，未登录也能看到完整看板；回到设置关闭开关，再刷新无痕窗口即变为 404。

两条边界决定它只适合「真正想公开」的场景：

- **地址可猜测**。公开地址就是站点域名本身，任何知道域名的人都能拼出来，所以它不是「只给特定的人看」的手段——那是分享链接的用途。
- **公开的是整个看板**。来源、页面、目标转化全部可见，不能只公开部分报表；想限定数据范围，用分享链接的「Limit to segment」（见下节）。

官方文档提到的典型用法是把公开地址放在网站页脚或 About 页，作为透明度声明。

## 分享链接

分享链接解决「只给特定的人看，又不想加成员」的问题：每条链接带一个随机令牌，持有者免登录看该站点的只读看板；看不到账号下其他站点，也不占团队成员名额（团队成员与角色见 [团队与站点管理](?path=/docs/team-sites--docs)）。

**操作路径**：Visibility 页 **Shared links** 区块 → **Add shared link**，弹窗里三个选项：

- **Name**：仅自己可见的备注名，访问者看不到。
- **Password**：可选密码保护。**密码只在创建时设置一次，之后无法查看、修改或移除**，忘了只能删除链接重建（官方文档原文警告）。访问者输对密码后获得一个 24 小时有效的 cookie，期间免输（v3.2.1 `StatsController` 源码注释核对）。
- **Limit to segment**：把链接限定到某个已保存的细分，访问者可以在此之上叠加筛选，但不能移除底层细分。细分的创建见 [筛选与细分](?path=/docs/filtering-segments--docs)；给不同客户各发一条限定其流量切片的链接，是「多客户共用一个站点」的标准做法。

创建后得到形如 `http://localhost:8000/share/test.local?auth=<随机令牌>` 的地址。列表中每条链接旁的**铅笔**图标可改名或解除细分限制（密码不能改），**垃圾桶**图标即撤销。

**证据**（本地可完整复现）：创建一条无密码链接，无痕窗口打开可免登录看到看板；再建一条带密码链接，无痕窗口先看到密码页，输对密码进入看板；删除其中一条后刷新对应窗口，页面变为 404。撤销之所以立即生效，是因为每次访问分享链接都会查库确认链接仍然存在（v3.2.1 `StatsController#shared_link` 核对）；被删除的链接返回 404，密码 cookie 也随之失效。分享链接页面带 `x-robots-tag: noindex, nofollow` 响应头，不会被搜索引擎收录。

## 嵌入看板

嵌入不是独立功能，而是「分享链接 + iframe」：嵌入地址就是分享链接的 URL 追加 `embed=true` 等参数，看板以嵌入式布局渲染，随附的脚本负责把 iframe 自动撑到内容高度。

**操作路径**：先按上节创建一条分享链接（**必须不设密码**——嵌入表单的提示原文为「only public shared links without password can be embedded」，密码保护的链接嵌入后浏览器直接显示 "refused to connect"），然后在 Visibility 页 **Embed dashboard** 区块：粘贴分享链接 → 选 **Theme**（Light / Dark / System）→ 可选填 **Background**（自定义背景色，可填 `transparent` 让看板融入宿主页背景）→ 点 **Generate embed code**，复制文本框中的代码贴进目标网页。

生成的代码结构（v3.2.1 `assets/js/app.js` 核对，本地实例下的样子）：

```html
<iframe plausible-embed src="http://localhost:8000/share/test.local?auth=<令牌>&embed=true&theme=light" scrolling="no" frameborder="0" loading="lazy" style="width: 1px; min-width: 100%; height: 1600px; color-scheme: auto;"></iframe>
<div style="font-size: 14px; padding-bottom: 14px;">Stats powered by <a target="_blank" style="color: #4F46E5; text-decoration: underline;" href="https://plausible.io">Plausible Analytics</a></div>
<script async src="http://localhost:8000/js/embed.host.js"></script>
```

三个部分各司其职，理解后就能排查一切嵌入问题：

- **iframe**：`src` 是分享链接 URL 加参数。分享链接页面本身就不带 `x-frame-options` 响应头（服务端渲染时移除，允许被嵌）；`embed=true` 让看板切换为嵌入布局（v3.2.1 `StatsController` 核对）。`height: 1600px` 只是初始值。
- **`embed.host.js`**：基于 iframe-resizer，按内容实际高度持续调整 iframe（`heightCalculationMethod: 'taggedElement'`），所以宿主页不需要自己算高度。这个脚本被剥掉，iframe 就会停在 1600px 或被截断。
- **署名行**：「Stats powered by Plausible Analytics」字样随嵌入代码一起生成。

嵌入 URL 的完整参数速查（追加在分享链接 URL 之后）：

| 参数 | 取值 | 作用 |
| --- | --- | --- |
| `embed` | `true` | 启用嵌入布局（生成器自动附加） |
| `theme` | `light` / `dark` / `system` | 看板主题；`system` 跟随访客系统偏好 |
| `background` | CSS 颜色值，如 `%23F9FAFB`（即 `#F9FAFB`）或 `transparent` | 看板背景色；留空用主题默认背景 |
| `width` | `manual` | 关闭默认的限宽居中（默认约 `max-width: 1024px; margin: 0 auto`，官方文档口径），看板改为填满 iframe 宽度，由宿主容器控制布局 |

**证据**：把生成的代码贴进任意一个 HTML 文件用浏览器打开，即可看到内嵌看板随窗口缩放自适应高度；在分享链接 URL 上手动追加 `&width=manual` 再对比，可观察到限宽居中和填满容器两种布局的差别。撤销只需删除底层分享链接，嵌入处随即 404。分享链接上的「Limit to segment」限定同样贯穿到嵌入，适合做按客户切片的嵌入式报表。需要完全自定义外观时，官方建议改用 [Stats API](?path=/docs/stats-api--docs) 自建看板，而不是继续给 iframe 套样式。

## 常见问题

- 发给别人的「分享链接」打开后要求登录或直接 404。
  检查发出去的地址形态：看板本身的地址是 `/<域名>`，分享链接是 `/share/<域名>?auth=<令牌>`。从看板地址栏直接复制的 URL 不是分享链接——站点仍私有时它对非成员就是 404。去 Visibility → Shared links 创建真正的分享链接再发。
- 嵌入的看板高度不对：出现内部滚动条，或底部大片空白。
  先确认 `<script src=".../js/embed.host.js">` 还在页面里且未被拦截（构建工具的 HTML 清洗、宿主页 CSP 都可能剥掉它）。iframe 初始高度固定 1600px，靠这个脚本按内容自动调整；脚本缺失就只剩滚动条或空白。另外不要给 iframe 自己写 `height` 样式覆盖，宽度方向的调整用 `width=manual` 参数而不是 CSS。
- 撤销分享链接后，旧链接和嵌入了它的页面会怎样？
  立即全部失效：每条分享链接的每次访问都会查库确认链接存在，删除后旧链接返回 404，嵌入了它的 iframe 同样显示错误页。带密码的链接撤销后，访问者手里的 24 小时免密 cookie 也一并作废（cookie 只在链接存在时有用）。
- 分享链接的密码忘了，想找回或改成新密码。
  做不到——密码在创建后无法查看、修改或移除，这是官方文档明确的设计。处理方式只有一个：删除旧链接，新建一条并设置新密码，再把新地址发给访问者。

## 总结回顾

摘要：

Plausible 看板默认私有，对外可见性由站点设置 Visibility 页的三个区块承载：公开可见性把看板放到 `/<域名>` 的固定地址供任何人访问，适合公开透明页；分享链接用随机令牌生成不可猜测的只读地址，可叠加密码保护和细分限定，适合定向给客户或合作方；嵌入看板把无密码分享链接加上 `embed=true`、`theme`、`background`、`width=manual` 等参数装进 iframe，配合 `embed.host.js` 按内容自动撑高，适合内部 wiki 与产品内嵌。三者的访问者都是只读的 public 角色，不占成员名额；撤销路径分别是关闭开关、删除链接（旧地址立即 404）、删除底层分享链接。CE v3.2.1 源码核对确认三种能力在社区版全部可用。

一句话：

> 选方式的判断依据只有一个：给「所有人」看用公开可见性，给「特定的人」看用分享链接，给「另一个页面里的读者」看用嵌入——而嵌入永远建立在一条无密码分享链接之上。

知识要点：

- 三种对外可见性方式各自的地址形态、访问门槛和撤销方式是什么？
- 公开看板地址为什么不适合「只给特定的人看」的场景？
- 分享链接的密码保护有什么不可恢复的限制？访问者输对密码后的免密时长是多少？
- 「Limit to segment」对分享链接的访问者允许什么、禁止什么？
- 嵌入代码中 `embed=true`、`theme`、`background`、`width=manual` 参数和 `embed.host.js` 脚本各自负责什么？为什么分享链接必须不设密码才能嵌入？
- 撤销一条分享链接后，旧链接、嵌入页面和已发放的密码 cookie 分别表现为什么？
