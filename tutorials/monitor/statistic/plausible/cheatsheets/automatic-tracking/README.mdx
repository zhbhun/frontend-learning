# 自动追踪

除了 pageview，出站链接点击、文件下载、404 页面访问和表单提交这些常见行为可以不写一行 JS 就进入看板。Plausible 提供两种开启方式：**站点设置里的开关**（改动自动生效，不需要动站点代码）和**经典脚本变体**（换一个脚本文件名）。两种方式上报的是同一批事件，事件也遵循同一条规则：先注册为 Goal，才会出现在看板的 Goals 区块。

```mermaid
flowchart LR
  A[页面上的行为<br/>链接点击 / 表单提交 / 404] --> B{追踪如何开启}
  B -->|站点设置开关| C[站点专属片段自动捕获]
  B -->|脚本变体| D["script.+ 扩展名.js 自动捕获"]
  C --> E[POST /api/event]
  D --> E
  E --> F{已注册 Goal?}
  F -->|是| G[看板 Goals 区块]
  F -->|否| H[事件照收但不显示]
```

| 行为 | 事件名（即 Goal 名） | 携带属性 | 站点设置开关 | 经典脚本变体 |
| --- | --- | --- | --- | --- |
| 出站链接点击 | `Outbound Link: Click` | `url`（目标地址） | 有 | `outbound-links` |
| 文件下载 | `File Download` | `url`（文件地址） | 有 | `file-downloads` |
| 404 页面 | `404` | 页面地址在 `u` 字段 | 有（站点安装区） | 无（一行手动调用） |
| 表单提交 | `Form: Submission` | 无（按页面区分） | 有（新站点默认开） | 无 |

## 快速上手

最小闭环：给已接入的页面换上带扩展的脚本文件名，点一次出站链接，事件就到看板。

1. 前提：本地实例运行中且站点 `test.local` 已创建（见[本地实例](?path=/docs/local-instance--docs)），页面已接入脚本（见[接入脚本](?path=/docs/script-setup--docs)）。
2. 把接入片段里的 `script.local.js` 换成组合变体（本地演示需要 `.local`；真实站点去掉它）：

   ```html
   <script defer data-domain="test.local" src="http://localhost:8000/js/script.file-downloads.local.outbound-links.js"></script>
   ```

3. 打开页面，点击一个指向外部站点的链接。浏览器 Network 面板能看到 `POST /api/event` 返回 202，请求体里 `n` 为 `Outbound Link: Click`。
4. 打开 `http://localhost:8000/test.local/settings/goals`，添加 Custom event 目标 `Outbound Link: Click`；回到看板，Goals 区块出现这条转化记录。

用站点设置开关时跳过第 2 步（片段不变）和第 4 步（开关自动注册 Goal）。

## 扩展机制

两种开启方式覆盖的行为相同，差别在配置位置和 Goal 注册：

- **站点设置开关**：站点设置 → General → Tracking → Default tracking，可开关出站链接、文件下载、表单提交；改动自动生效，不需要更新站点上的片段；打开时自动注册对应 Goal，关闭时自动移除。新版站点专属片段（`pa-<id>.js` + `plausible.init()`）也可用 init 选项控制，例如 `formSubmissions`、`fileDownloads.fileExtensions`。
- **经典脚本变体**：文件名按字母序组合，形如 `script.file-downloads.local.outbound-links.js`（顺序写错会得到 404）。经典变体只有 `file-downloads` 和 `outbound-links` 两个自动追踪扩展；404 用一行手动调用，表单提交没有经典变体。事件需手动注册 Goal。

下面的实例用经典变体演示（开关编译在站点专属片段里，沙箱无法复现）；行为与载荷在两种方式下一致。先在对照组下点击四个元素，再切换到扩展组合重复一遍：

<Canvas of={AutomaticTracking.Interactive} />
<Controls of={AutomaticTracking.Interactive} />

| 读者操作 | 可观察证据 |
| --- | --- |
| 对照组下点击四个元素 | 只有「模拟 404 页面」产生事件——它是手动调用，不是扩展行为 |
| 切到扩展组合后点出站链接、下载链接 | 读数出现 `Outbound Link: Click` / `File Download`，载荷 `p.url` 为链接地址 |
| 提交表单 | 两种变体都无事件——表单追踪只有开关和 init 选项，没有经典变体 |

注意：实例在本地实例不可达时会显示「加载失败」，先启动本地实例再操作；扩展的 document 级监听装入后无法摘除，切回对照组后链接点击仍可能上报，重新加载本页复位。

## 出站链接

点击指向其他域名的链接时，扩展上报 `Outbound Link: Click` 事件，`url` 属性记录目标地址。适合回答「读者从哪些页面离开、去了哪里」。

看板中点击该 Goal 可按来源、页面、地区、设备下钻；用 Filter → Property → `url` 的 contains 可以按域名或关键词聚合（例如所有指向 `github.com` 的点击）。隐藏真实目标的联盟链接（cloaked affiliate links）需要单独的自定义追踪写法，见官方指南。

## 文件下载

点击以常见文件扩展名结尾的同域链接时，扩展上报 `File Download` 事件，`url` 属性记录文件地址。默认追踪的扩展名：

`.pdf` `.xlsx` `.docx` `.txt` `.rtf` `.csv` `.exe` `.key` `.pps` `.ppt` `.pptx` `.7z` `.pkg` `.rar` `.gz` `.zip` `.avi` `.mov` `.mp4` `.mpeg` `.wmv` `.midi` `.mp3` `.wav` `.wma` `.dmg`

边界要记三条：只统计发生在已追踪页面上的点击（别人直接分享的文件直链不算）；文件在外部域名（如 CDN）时归入出站链接点击，不算下载；点击落在 SVG 元素内部时不追踪。新版片段可用 `plausible.init({ fileDownloads: { fileExtensions: ['pdf', 'js'] } })` 整体覆盖默认清单。

## 404 页面

404 追踪的机制不同：不是换脚本，而是在站点的 404 模板里加一行手动调用，让每次错误页访问上报一个 `404` 事件：

```html
<script>document.addEventListener('DOMContentLoaded', function () { plausible('404'); });</script>
```

然后在站点设置添加 Custom event 目标 `404`（逐字符一致，不含空格）。之后看板 Goals 区块出现该目标，点击它能看到哪些 URL 触发了 404、访客从哪个来源来——这就是坏链修复清单。新版站点设置的站点安装区有对应开关，打开时自动注册该 Goal、关闭时自动移除，但模板里的这行调用仍然需要。测试方法：访问一个不存在的路径，先看 realtime 或 Network 里的 `/api/event` 请求。

## 表单提交

开关打开后（新站点默认开启），脚本自动监听全站表单的 submit 事件，所有表单提交归到同一个目标 `Form: Submission`，不需要逐表单配置。事件不带表单名等属性：同一个表单出现在多个页面时，按页面路径或来源过滤来区分；要单独追踪某个表单，用 tagged events 给它标注独立事件名（被标注的表单不会再计入 `Form: Submission`），见[自定义事件](?path=/docs/custom-events--docs)。表单提交没有经典脚本变体，只能用开关或 init 的 `formSubmissions` 选项开启。

## 常见问题

- 脚本加载成功，但点链接、下载文件都没有任何事件
  本页或站点运行在 localhost / 127.0.0.1：tracker 默认忽略这类页面的事件（控制台有 `Ignoring Event: localhost` 警告）。本地演示换带 `.local` 的变体；生产站点用真实域名不受影响。
- 事件已发送（HTTP 202），看板里却看不到
  绝大多数是 Goal 未注册：经典变体方式需要在站点设置手动添加同名 Custom event 目标，注意事件名逐字符一致（大小写、空格）。开关方式自动注册，若仍没有，检查开关是否保存成功。
- 组合变体文件名返回 404
  扩展名必须按字母序拼接，例如 `script.file-downloads.local.outbound-links.js`；写错顺序服务端找不到对应文件。
- 点击下载链接没有产生 `File Download`
  依次检查：文件扩展名是否在默认清单；链接是否指向外部域名（归入 `Outbound Link: Click`）；点击目标是否是 SVG 内部元素（不追踪）。

## 总结回顾

摘要：

自动追踪覆盖四种常见行为：出站链接点击（`Outbound Link: Click`，带 `url`）、文件下载（`File Download`，带 `url`）、404 页面（404 模板里手动调用 `plausible('404')`）和表单提交（`Form: Submission`，不带属性）。开启方式有两种——站点设置开关（自动生效、自动注册 Goal，表单提交只能用它或 init 选项）和经典脚本变体（按字母序组合文件名，只有 `file-downloads` 与 `outbound-links`，Goal 需手动注册）。无论哪种方式，事件都要注册为 Goal 后才会出现在看板 Goals 区块，且都计入事件量。

一句话：

> 自动追踪 = 开关或脚本变体替你写 `plausible(...)`，事件显示的前置条件仍然是注册 Goal。

知识要点：

- 四种自动追踪行为各自的事件名和携带属性是什么？
- 站点设置开关和经典脚本变体在配置位置、Goal 注册上有什么差别？
- 为什么表单提交在经典脚本变体下永远不会产生事件？
- 事件发送成功但看板不显示，先检查什么？
