# 安装

本课把 Phaser 4 装进一个 TypeScript + Vite 项目并跑通第一个实例。安装有三条途径：npm（官方项目创建器或手动安装）、CDN script 标签、Phaser Launcher 桌面应用。它们的起点不同，终点一致——项目里有一个可 `import` 的 `phaser` 模块，或页面上有一个全局 `Phaser` 变量。装没装好，只用一件事判断：能否引导出一个能渲染的 `Phaser.Game` 实例，并用 `Phaser.VERSION` 核对版本号。

本课只解决“装上并跑起来”。`Phaser.Game` 配置项的含义是 [1.2 创建游戏](?path=/docs/game-config--docs)的主题，场景写法是 [1.3 场景生命周期](?path=/docs/scene-lifecycle--docs)的主题。

| 关键事实 | 值 | 回查要点 |
| --- | --- | --- |
| npm 包名 | `phaser` | 官方发布；TypeScript 类型内置在包内（`types/phaser.d.ts`） |
| 本手册锁定版本 | 4.2.1 | 仅用 Phaser 4（4.x 线）；安装后核对版本号以 4 开头 |
| 官方项目创建器 | `npm create @phaserjs/game@latest` | 交互式生成官方模板项目 |
| 打包器入口 | `dist/phaser.esm.js` | Vite 等按包的 `exports` 自动选取，无需配置 |
| 浏览器构建 | `dist/phaser.min.js` | CDN / `<script>` 引入，暴露全局 `Phaser` |
| 免费桌面工具 | Phaser Launcher | 官方入门应用，下载页 `phaser.io/download` |
| 渲染器默认 | `Phaser.AUTO` | 优先 WebGL，不可用时回退 Canvas |

## 快速上手

官方项目创建器一条命令生成完整项目，这是官方推荐的起点：

```bash
# 交互式创建 Phaser 4 项目（模板、TypeScript 等按提示选择）
npm create @phaserjs/game@latest my-game

cd my-game
npm install
npm run dev
```

可观察结果：终端输出本地开发服务地址（默认 `http://localhost:5173/` 一类），浏览器打开后看到模板游戏在运行、控制台无报错。到这一步安装即完成；想理解每一步在做什么，继续往下读。

## 安装途径

三条途径的差异只在“Phaser 从哪里来、项目由谁搭”：

- **npm**：Phaser 是 `node_modules` 里的一个依赖，项目结构和构建由你（或创建器）用 Vite 等工具掌握。适合真实项目和本手册全部后续课程。
- **CDN**：Phaser 是页面上一个 `<script>` 标签带来的全局变量，没有构建步骤。适合快速试验和单文件演示页。
- **Phaser Launcher**：官方免费桌面应用，项目、编辑器和素材管理一体化。适合不想先碰命令行的起步方式。

无论哪条途径，最终验证方式相同：见下文「验证安装」一节。

### npm 安装

两种做法，选其一：

**创建器生成（推荐）**：`npm create @phaserjs/game@latest` 生成官方模板项目，依赖、脚本和示例场景都已配好，`npm install` 后直接 `npm run dev`。快速上手一节展示的就是这条路。

**手动安装**：在已有项目里自己装：

```bash
npm install phaser
```

装完核对版本：

```bash
npm ls phaser
# └── phaser@4.2.1
```

版本号记录在 `package.json` 的 `dependencies` 里；本工作区锁定 `4.2.1`。代码中这样引入：

```ts
import Phaser from 'phaser';
// 或按需引入具名导出
import { Game, AUTO, VERSION } from 'phaser';
```

`phaser` 包同时提供默认导出和具名导出，两种写法都可以。类型定义内置在包内（`types/phaser.d.ts`），TypeScript 直接可用，不需要再装第三方类型包。

### CDN 引入

不搭工程时，用 `<script>` 标签直接加载浏览器构建，得到全局变量 `Phaser`：

```html
<script src="https://cdn.jsdelivr.net/npm/phaser@4.2.1/dist/phaser.min.js"></script>
<script>
  console.log(Phaser.VERSION); // "4.2.1"
</script>
```

要点：

- URL 中的版本号建议写全（`phaser@4.2.1`），不要用 `phaser@latest` 之类的浮动引用，避免引擎升级悄悄改变游戏行为。
- 压缩版用于生产（`phaser.min.js`）；调试时可换成未压缩的 `phaser.js`。
- UMD 构建把工厂挂在全局 `Phaser` 上，CommonJS/AMD 环境同样可用；ESM 场景则引用 `dist/phaser.esm.min.js`。
- 具体可用的 CDN 域名与最新版本号以官方下载页 [phaser.io/download](https://phaser.io/download) 为准。

### Phaser Launcher

Phaser Launcher 是官方免费桌面应用（下载页 `phaser.io/download`），内置项目模板、代码编辑器和媒体浏览器，新建项目后点运行就能本地预览，不需要命令行。它适合零配置起步和素材管理；深入用法在 [6.2.1 Phaser Launcher](?path=/docs/phaser-launcher--docs)展开。用 Launcher 创建的项目同样可以转回 npm + Vite 工作流，两条路不冲突。

## TypeScript + Vite 项目

不想用官方模板时，用 Vite 的 TypeScript 模板从零搭一个，两步装好：

```bash
# 1. 生成 Vite + TypeScript 项目
npm create vite@latest my-game -- --template ts
cd my-game

# 2. 安装 Phaser
npm install phaser
```

清空 `src/main.ts`，换成最小引导（完整讲解见下一节）：

```ts
import Phaser from 'phaser';

new Phaser.Game({
  type: Phaser.AUTO,
  width: 800,
  height: 450,
  backgroundColor: '#1d2a44',
  scene: {
    create() {
      this.add.text(400, 225, `Phaser ${Phaser.VERSION} 已启动`).setOrigin(0.5);
    },
  },
});
```

然后启动本地开发服务：

```bash
npm run dev
```

Vite 之所以开箱即用，是因为 `phaser` 包的 `exports` 字段把 `import` 条件指向 `dist/phaser.esm.js`（ESM 构建），开发服务直接按原生 ESM 加载，不需要任何额外配置。`npm run build` 产出生产包，构建优化是 [6.1.2 生产构建](?path=/docs/production-build--docs)的主题。

## 验证安装

安装是否成功，用一个最小引导来判定。三个可核对信号：

1. **控制台无报错**——模块能解析、能实例化。
2. **画面渲染出来**——`backgroundColor` 生效、`create` 回调里的文本可见。
3. **版本号正确**——`Phaser.VERSION` 输出的字符串以 `4` 开头，且与 `npm ls phaser` / CDN URL 中的版本一致。

## 最佳实践

- **途径选择**：真实项目和长期维护选 npm + Vite（本手册后续课程的范例都跑在这条线上）；一次性试验、教学演示页选 CDN script 标签；想先绕开命令行再选 Launcher。三者的验证方式相同，切换成本主要在项目结构，不在引擎。
- **版本要锁定**：`package.json` 写精确版本（如 `4.2.1`）或 `~4.2.1` 范围；CDN URL 写全版本号。Phaser 4 的 4.x 内升级也可能改行为，升级前先看仓库 CHANGELOG（见参考资料）。
- **验证先于开发**：装完先跑最小引导并核对 `Phaser.VERSION`，再开始写游戏逻辑。环境问题越早暴露，排查范围越小。

## 常见问题

- 装到的不是 Phaser 4，教程代码对不上
  运行 `npm ls phaser`（CDN 则看 URL）核对版本号以 `4` 开头。网络上大量存量教程和示例基于 Phaser 3，API 与 4.x 不完全兼容；本手册只对照 4.x，排查时优先用官方文档和 labs 示例（见参考资料）。
- 编辑器报 `Cannot find module 'phaser'` 或类型缺失
  确认 `phaser` 真的装进了当前项目的 `node_modules`（`npm ls phaser` 能找到），然后重启 TS 语言服务 / 开发服务。Phaser 4 类型内置在包内，不需要也不应该再装第三方类型包；类型缺失通常只是安装不完整或服务缓存了旧状态。
- CDN 页面报 `Phaser is not defined`
  检查 `<script src="...">` 是否放在使用 `Phaser` 的代码之前、URL 版本号与文件名拼写是否正确、网络面板里脚本是否真的加载成功。UMD 构建只有加载成功后才会创建全局 `Phaser`。

## 总结回顾

摘要：

Phaser 4 的安装有三条途径：npm（官方创建器 `npm create @phaserjs/game@latest` 或手动 `npm install phaser`）、CDN script 标签（`dist/phaser.min.js` 暴露全局 `Phaser`）和 Phaser Launcher 桌面应用。npm 路线配 TypeScript + Vite 开箱即用，因为包的 `exports` 已把 `import` 指向 ESM 构建，类型也内置在包内。无论哪条路，安装成功的判定标准一致：引导一个最小 `Phaser.Game`，看到背景与文本渲染、控制台无报错，且 `Phaser.VERSION` 与安装时锁定的版本一致。

一句话：

> 装没装好只看一件事：`Phaser.VERSION` 报出正确版本，且最小 `Phaser.Game` 能渲染出画面。

知识要点：

- 官方项目创建器命令是什么？
- 手动 npm 安装后如何核对装到的版本？
- CDN 引入用哪个构建文件、暴露什么全局变量？为什么版本号要写全？
- 为什么 Vite + TypeScript 不需要任何额外配置就能用 Phaser？
- 安装成功的三个可核对信号是什么？
- `Phaser.AUTO` 落到 WEBGL 还是 CANVAS 由什么决定？
