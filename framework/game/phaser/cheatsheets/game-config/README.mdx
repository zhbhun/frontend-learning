# 创建游戏

`new Phaser.Game(config)` 是 Phaser 的唯一入口:一条配置对象决定游戏分辨率多大、画布挂到哪个 DOM 节点、用 Canvas 还是 WebGL 渲染、背景什么颜色;其中 `scale` 部分交给 Scale Manager,决定画布在父容器里如何缩放与居中。本课讲清每个常用字段的默认值与影响,再用可切换缩放模式的实例核对三个量之间的关系——游戏分辨率(`gameSize`)、屏幕显示尺寸(`displaySize`)与缩放系数(`zoom`/`displayScale`)。读完本课,改任何一个配置你都能预测画布会怎样变化;出问题时,也知道用哪两个读数定位。

| 字段 | 默认值 | 回查要点 |
| --- | --- | --- |
| `type` | `Phaser.AUTO` | 渲染器类型;boot 后 `game.config.renderType` 是实际生效值 |
| `width` / `height` | `1024` / `768` | 游戏分辨率,数字或 `'100%'`;坐标系、摄像机、输入都基于它 |
| `parent` | `undefined` | 父容器,元素或其 id;不写挂到 `document.body`,`null` 表示自己管理画布插入 |
| `canvas` | `null` | 复用已有 canvas 元素,Phaser 不再自建 |
| `backgroundColor` | 黑色 | 接受 `'#141a26'`、`'#08f'`、`0x141a26` |
| `transparent` | `false` | 透明背景;`true` 时忽略 `backgroundColor` |
| `antialias` | `true` | 纹理缩放/旋转时平滑插值;像素风设 `false` |
| `pixelArt` | `false` | 像素艺术快捷方式,等价于 `antialias: false` + `roundPixels: true` |
| `scale.mode` | `Phaser.Scale.NONE` | 缩放模式,决定画布如何适配父容器 |
| `scale.zoom` | `1` | 画布整体放大倍数,或 `Phaser.Scale.MAX_ZOOM` |
| `scale.autoCenter` | `Phaser.Scale.NO_CENTER` | 画布在父容器内的居中方式 |
| `scale.expandParent` | `true` | 允许把父级/`body` 的高度 CSS 撑到 `100%` |
| `scale.min` / `scale.max` | `0`(不限) | 显示尺寸的缩放下限/上限,如 `{ width: 320, height: 180 }` |

## 快速上手

一个最小闭环:写好 config,注册一个场景,页面上就会出现一块 640×360 的深色画布。

```ts
import Phaser from 'phaser';

new Phaser.Game({
  type: Phaser.AUTO,           // 优先 WebGL,不可用则退回 Canvas
  width: 640,                  // 游戏分辨率宽(游戏像素)
  height: 360,                 // 游戏分辨率高
  backgroundColor: '#141a26',  // 画布背景色
  parent: 'game',              // 挂到 <div id="game"></div>;不写则挂到 body
  scene: {
    create() {
      // 场景内容;首个场景自动启动
    },
  },
});
```

`scene` 接受场景类、场景配置对象或它们的数组;场景本身的编写、启动与销毁属于[场景生命周期](?path=/docs/scene-lifecycle--docs)。不写 `scale` 时模式为 `NONE`:画布按 `width × height` 的原始 CSS 尺寸显示,不缩放。

## 画布尺寸与父容器

`width`/`height` 定义的是**游戏分辨率**:游戏内坐标系、摄像机视口、输入换算都基于它,和画布在屏幕上显示多大是两回事(显示大小由 Scale Manager 决定,见下文)。取值可以是数字,也可以是 `'100%'`——百分比表示跟随父容器尺寸,前提是父容器有确定的宽高。

`parent` 决定画布插入哪里、Scale Manager 以谁为基准计算可用空间:

- **不写(undefined):** 画布追加到 `document.body`,缩放和居中都按整个页面算。
- **元素或 id 字符串:** 画布插入该容器,缩放按容器的可用空间算。容器要有 CSS 尺寸(`getBoundingClientRect` 高度为 0 时,FIT/RESIZE 等模式都算不出结果),且不要带 padding——父容器的内边距不被计入。
- **`null`:** Phaser 不接管插入,你自己在 DOM 里摆放画布;常配合 `canvas` 字段使用。

自带画布时,把现成的 canvas 元素传给 `canvas` 字段,Phaser 直接在上面创建渲染上下文。注意:`parent` 的解析与画布当前所在位置无关——就算画布已经在你的容器里,`parent` 不写时 Scale Manager 仍按 `document.body` 计算缩放,所以自带画布时通常要显式传 `parent`。配套的 `canvasStyle` 可以给画布一段自定义 CSS 字符串。

这些字段既可以直接写在 config 顶层,也可以收进 `scale: {}` 子对象(`width`、`height`、`zoom`、`parent` 等两边都接受);两个地方都写时,`scale` 里的值覆盖顶层。下文的范例就用这种方式集中组织缩放配置。

## 渲染器与背景

`type` 选择渲染器,`game.config.renderType` 在 boot 后反映实际生效的类型:

| 常量 | 值 | 行为 |
| --- | --- | --- |
| `Phaser.AUTO` | 0 | 默认。支持 WebGL 就用 WebGL,否则退回 Canvas;实际结果看 `game.config.renderType` |
| `Phaser.CANVAS` | 1 | 强制 Canvas 2D,兼容性最好、特性最少 |
| `Phaser.WEBGL` | 2 | 强制 WebGL,不支持则无法渲染 |
| `Phaser.HEADLESS` | 3 | 不渲染画面,只跑逻辑循环;用于服务器或自动化测试 |

渲染细节放在 `render: {}` 子对象(同样可平铺在顶层,嵌套覆盖顶层)。最常用的几个:`antialias`(纹理缩放平滑,默认 `true`)、`roundPixels`(整数像素绘制)、`pixelArt`(像素艺术快捷方式,会同时设置 `antialias: false` 和 `roundPixels: true`)、`transparent`(默认 `false`)。其余如 `batchSize`、`maxTextures`、`powerPreference` 属于性能与 WebGL 上下文调优,用到时查 [官方文档](https://docs.phaser.io/)。

`backgroundColor` 给画布铺底色,字符串(`'#141a26'`、`'#08f'`)和数值(`0x141a26`)都接受;`transparent: true` 时它被忽略,画布透出页面背景。注意场景摄像机自己也有 `setBackgroundColor`,设置过会盖在全局背景之上。

```ts
new Phaser.Game({
  type: Phaser.AUTO,
  width: 480,
  height: 270,
  backgroundColor: '#101828',
  render: { pixelArt: true },  // 像素风:关闭平滑插值 + 整数绘制
  scene: [MainScene],
});
```

## 缩放适配

Scale Manager 的核心机制:**canvas 的分辨率(width/height 属性)与显示尺寸(CSS)是分开的**。除 RESIZE/EXPAND 外,所有模式都保持 canvas 分辨率不变,只用 CSS `width`/`height` 把它"拉伸"到目标大小——效果等价于 `transform: scale`,但由 Phaser 直接管理。`game.scale` 上有四个尺寸对象随时可查:

| 尺寸对象 | 含义 |
| --- | --- |
| `game.scale.gameSize` | config 要的原始游戏尺寸;RESIZE/EXPAND 模式下会跟随父容器变化 |
| `game.scale.baseSize` | 写进 canvas 属性的分辨率(`gameSize` 取整后) |
| `game.scale.displaySize` | 画布的 CSS 显示尺寸 |
| `game.scale.parentSize` | 父容器的可用空间 |

派生量:`zoom` 是配置的整体倍数;`displayScale`(Vector2)≈ `displaySize / baseSize`,即这一帧画面被拉伸的实际倍率。画面发糊,多半就是 `displayScale` 远大于 1 导致的拉伸。

| 切到 `RESIZE` | 画布铺满父容器,`gameSize` 读数随之变化,角标记重新画到新四角(场景监听了 resize 事件) |
| 切到 `ENVELOP` | 画布等比放大到盖满父容器,溢出部分被裁剪,不留边 |
| 切到 `NONE` | 画布回到 `width × height` 的原始 CSS 尺寸,不受父容器影响 |
| 调整宽度/高度 | `gameSize`、`displaySize` 与纵横比同步变化 |
| zoom 切到 `MAX_ZOOM` | `zoom` 读数变成"能整数倍放进父容器"的最大倍数 |
| autoCenter 切到 `CENTER_BOTH` | NONE 模式下画布在父容器内水平垂直居中 |

### 缩放模式

七种模式(`Phaser.Scale.*` 常量)按"分辨率是否固定"分两类:

| 模式 | canvas 分辨率 | 显示尺寸 | 适用 |
| --- | --- | --- | --- |
| `NONE` | 固定 | = 分辨率 × zoom | 固定尺寸嵌入页面,缩放完全自己用 CSS 管理 |
| `WIDTH_CONTROLS_HEIGHT` | 固定 | 宽随父容器,高按纵横比 | 宽度自适应的横向布局 |
| `HEIGHT_CONTROLS_WIDTH` | 固定 | 高随父容器,宽按纵横比 | 高度自适应的纵向布局 |
| `FIT` | 固定 | 等比缩到装得下,可能留边 | 最常用:固定设计尺寸适配各种屏幕 |
| `ENVELOP` | 固定 | 等比放大盖满,溢出裁剪 | 全屏铺满不留黑边,允许裁掉边缘 |
| `RESIZE` | 跟随父容器 | 1:1 无拉伸 | 满屏画布 + 动态布局,内容要自己重排 |
| `EXPAND`(Phaser 4 新增) | 沿一轴扩展 | 铺满父容器 | 移动端任意纵横比,保持设计比例基准 |

分辨率固定的模式里,游戏内坐标永远在 `width × height` 里;RESIZE/EXPAND 则让"世界大小"本身跟随容器,场景内容必须监听 resize 重新摆放(见「运行时尺寸变化」小节)。切换模式的实验见上方实例:FIT 留边、ENVELOP 溢出、RESIZE 改变 `gameSize`,三种结果一次看全。

### zoom 与居中

`zoom` 在缩放模式之外再给画布一个整体倍数,接受数字或常量:`Phaser.Scale.NO_ZOOM`(1)、`ZOOM_2X`(2)、`ZOOM_4X`(4)、`MAX_ZOOM`(按当前父容器算出能整数倍放进的最大倍数)。像素艺术游戏常用它保证整数倍放大,避免非整数拉伸产生的碎点;它与 FIT 也可以叠加(FIT 的结果再乘 zoom)。

`autoCenter` 决定画布在父容器内怎么对齐,靠设置 canvas 的 margin 实现:`NO_CENTER`(默认)、`CENTER_HORIZONTALLY`、`CENTER_VERTICALLY`、`CENTER_BOTH`。前提同样是父容器有可计算的空间;FIT 留出的边正好配合 `CENTER_BOTH` 居中,RESIZE 这类铺满模式则没有居中可言。

兜底限制还有三组,都写在 `scale` 里:`min`/`max`(`{ width, height }`,0 表示不限)钳制显示尺寸的缩放范围;`snap` 让尺寸按步长取整;`autoRound`(默认 `false`)把显示尺寸直接取整,低性能设备上更稳,代价是可能差一两像素。

### 运行时尺寸变化

RESIZE/EXPAND 模式下父容器一变,`gameSize` 就跟着变,Phaser 不会替你重摆对象——在场景里监听 Scale Manager 的 resize 事件重新布局:

```ts
class MainScene extends Phaser.Scene {
  create() {
    this.mark = this.add.graphics();
    this.redraw();

    // 参数:gameSize、baseSize、displaySize、previousWidth、previousHeight
    this.scale.on(Phaser.Scale.Events.RESIZE, () => this.redraw());
  }

  private redraw() {
    const { width, height } = this.scale.gameSize; // 永远读当前值
    // 按新尺寸重摆标记、UI 等内容……
  }
}
```

其余运行时入口都在 `game.scale` 上:`setGameSize(width, height)` 改游戏尺寸(会派发 resize 事件),`resize(width, height)` 同时改游戏尺寸与父容器尺寸,`setZoom(value)` / `setMaxZoom()` 改缩放,`refresh()` 强制重算一次(改了容器 CSS 之后手动调它)。**缩放模式没有运行时 setter**——`mode` 在 boot 时解析,要换模式只能销毁重建 `Phaser.Game`,本课上方的实例每次切换 Controls 正是这么做的。

## 最佳实践

- **固定设计尺寸选 FIT。** 美术按一套 `width × height` 制作,FIT 等比适配所有屏幕,配 `CENTER_BOTH` 居中、`min` 保证小屏不至于缩没。绝大多数游戏的第一选择。
- **内容随屏流动选 RESIZE,但要付重排的代价。** UI 坐标、摄像机边界、输入区域都要在 resize 事件里重算;只想要铺满效果、不想重排时,先用 FIT + ENVELOP 对比再决定。
- **像素艺术用整数倍放大。** `pixelArt: true` 关平滑,配 `zoom`(或 `MAX_ZOOM`)保持整数倍缩放;小分辨率(如 320×180)放大比高分辨率缩小更保锐度。
- **父容器 CSS 先定形。** 给 `parent` 明确的宽高,不带 padding;页面级布局交给 CSS,画布内布局交给 Scale Manager,两层职责不混写。

## 常见问题

- FIT 模式画布只有一条缝或根本看不见。
  先查父容器高度:没有 CSS 尺寸的 `div` 高度为 0,FIT 就只能缩到 0。给父容器定高,或读 `game.scale.parentSize` 确认 Phaser 看到的可用空间。
- 画面整体发糊、像素风出现碎点。
  显示尺寸远大于分辨率(读 `displayScale`,大于 1 都在拉伸)。提高 `width`/`height`,或像素风下用 `zoom` 整数倍放大并确认 `pixelArt: true`。
- RESIZE 模式下对象位置错乱、点击区域偏移。
  `gameSize` 变了但内容没重摆。在场景里监听 `Phaser.Scale.Events.RESIZE` 按新尺寸重排;点击偏移还可能是自己改了 canvas 的 CSS 尺寸却没调 `game.scale.refresh()`。
- 自己传入 `canvas` 后,缩放和居中按整个页面算。
  `parent` 不写时 Scale Manager 回退到 `document.body`。自带画布时把 `parent` 一起指向画布所在的容器。
- `backgroundColor` 设了不生效。
  依次检查:`transparent` 是否为 `true`(会忽略背景色);场景摄像机是否调过 `setBackgroundColor`(会盖在全局背景上)。
- 切换 `type` 后复用同一个 canvas 报上下文错误。
  同一 canvas 只能绑定一种上下文类型(Canvas 2D 或 WebGL)。换渲染器类型时换一个 canvas 元素,或整页刷新。

## 总结回顾

摘要:

`Phaser.Game(config)` 用一条配置对象定义游戏的分辨率、父容器、渲染器与背景:`width`/`height` 是游戏分辨率而非屏幕尺寸;`parent` 决定画布插入与缩放基准;`type` 选渲染器,`render`/`backgroundColor`/`pixelArt` 控制渲染外观。缩放适配交给 Scale Manager 的七种 `scale.mode`:固定分辨率一类(NONE、FIT、ENVELOP、双轴控制)只拉伸 CSS,`gameSize` 不变;RESIZE/EXPAND 让分辨率跟随父容器,需要监听 resize 事件重排内容。`zoom`、`autoCenter`、`min`/`max` 在模式之上继续微调,运行时可用 `setGameSize`/`setZoom`/`refresh` 重算,唯独模式本身只能在 boot 前指定。

一句话:

> `width`/`height` 决定游戏里有多少像素,Scale Manager 决定这些像素在屏幕上占多大——前者改坐标世界,后者只改 CSS。

知识要点:

- `width`/`height` 与画布显示尺寸是什么关系?四个 Size 对象各自含义是什么?
- `parent` 不写、写字符串、写 `null` 三种情况行为有何不同?
- `Phaser.AUTO` 与 `game.config.renderType` 的区别?`pixelArt` 实际设置了什么?
- FIT、ENVELOP、RESIZE 三种模式分别如何影响 `gameSize` 与画面边缘?
- RESIZE 模式下内容错位时该监听什么事件、读哪个尺寸?
- 哪些缩放配置可以运行时改,哪个只能 boot 前定?
