# 精灵与图像

Sprite 与 Image 是 Phaser 里承载纹理的两个最基础显示对象:背景、道具、角色都用它们显示。本课建立两条主线判断:一是**定位模型**——`position` 是纹理上"锚点"落进世界的坐标,`origin` 决定锚点取在纹理的哪个位置(默认正中心),缩放、旋转、翻转、包围盒全部围绕这对关系展开;二是**选型判断**——Sprite 与 Image 共享几乎全部变换能力,唯一差异是 Sprite 多一个动画组件,不需要帧动画就用更轻的 Image。纹理从哪来(图片文件、图集)属于 [2.1 资源加载](?path=/docs/asset-loader--docs),本课实例用 `Graphics` + `generateTexture` 程序生成自包含纹理。

Sprite 与 Image 的变换默认值完全一致,来自两者共享的组件(Origin、Transform、Size、Flip、Visible):

| 属性 / 方法 | 默认值 | 回查要点 |
| --- | --- | --- |
| `x` / `y`, `setPosition(x, y)` | 创建时传入 | 锚点在场景中的坐标; setPosition 的 y 缺省时随 x |
| `originX` / `originY`, `setOrigin(x, y)` | `0.5, 0.5` | 锚点取在纹理内的归一化位置(0–1); y 缺省时随 x |
| `displayOriginX` / `Y`, `setDisplayOrigin(px)` | `width × origin` | 原点的像素版; 基于原生 `width`, 不随 scale 变化 |
| `scaleX` / `scaleY`, `setScale(x, y)` | `1, 1` | 等比缩放传一个参数即可; 读 `scale` 属性得到 `(scaleX + scaleY) / 2` |
| `displayWidth` / `displayHeight` | `width × scale` | 渲染尺寸; 直接赋值等于改 scale |
| `width` / `height`, `setSize(w, h)` | 纹理帧尺寸 | **只改内部逻辑尺寸, 不改渲染**; 改渲染用 `setScale` / `setDisplaySize` |
| `angle`(度), `setAngle(deg)` | `0` | 顺时针为正: 0 朝右, 90 朝下, ±180 朝左 |
| `rotation`(弧度), `setRotation(rad)` | `0` | 与 `angle` 是同一状态的两种单位, 改一个另一个同步 |
| `flipX` / `flipY`, `setFlip(x, y)` | `false` | 绕纹理中线镜像; 纯渲染开关, 不改坐标与物理 body |
| `visible`, `setVisible(bool)` | `true` | `false` 跳过渲染但仍处理 update |
| `alpha`, `setAlpha(v)` | `1` | 0–1 整体不透明度; tint / 混合见 [2.2.5 深度与视觉状态](?path=/docs/depth--docs) |

派生坐标读取(与 origin / scale / 旋转联动,均返回真实计算值):

| 方法 | 含义 |
| --- | --- |
| `getTopLeft()` / `getTopRight()` / `getBottomLeft()` / `getBottomRight()` | 四个角的坐标 |
| `getTopCenter()` / `getBottomCenter()` / `getLeftCenter()` / `getRightCenter()` | 四边中点坐标 |
| `getCenter()` | 渲染中心, 与 origin 无关 |
| `getBounds()` | 轴对齐外接矩形 `Rectangle`(x, y, width, height) |

## 快速上手

一个最小闭环:纹理就绪 → 创建对象 → 链式设置定位与变换 → 渲染。

```ts
class Demo extends Phaser.Scene {
  preload() {
    // 自包含纹理:Graphics 画完烘焙成普通纹理;真实项目走 this.load.*,见 2.1.1
    const g = this.make.graphics();
    g.fillStyle(0x60a5fa, 1);
    g.fillRect(0, 0, 96, 96);
    g.generateTexture('tile', 96, 96);
    g.destroy();
  }

  create() {
    // x, y 是"锚点"的世界坐标;origin 默认 0.5,即锚点取在纹理中心
    const img = this.add.image(360, 200, 'tile');
    img.setOrigin(0, 0).setScale(2).setAngle(45); // 左上角对齐 (360, 200),放大一倍,顺时针转 45°
    const actor = this.add.sprite(360, 200, 'tile'); // 需要帧动画的角色用 Sprite,其余用 Image
  }
}
```

记住一条:**改任何变换属性,`x` / `y` 都不动;动的是纹理相对锚点的渲染与派生坐标。**后面的实验台会反复验证这一点。

## 定位:position 与 origin

Phaser 的定位只有一件事要记牢:**`x` / `y` 指向的是锚点(anchor),锚点取在纹理的哪个位置由 `origin` 决定**。`origin` 是归一化值(0–1),默认 `(0.5, 0.5)`——纹理正中心。所以 `add.image(100, 100, 'tile')` 的效果是"纹理中心落在 (100, 100)",而不是很多引擎习惯的"左上角落在 (100, 100)"。

- `setOrigin(0, 0)`:锚点取左上角,`x` / `y` 从此指左上角——做瓦片、贴边 UI 常用。
- `setOrigin(1, 1)`:锚点取右下角,适合"从右下角对齐"的定位。
- `setOrigin(0.5, 1)`:底边中心,角色站在地面上最常用。
- `setOrigin(x)` 只传一个参数时 y 随 x;两轴可以不同。
- 像素版:`displayOriginX = originX × width`,想要"锚点距左缘 12px"这类精确偏移用 `setDisplayOrigin(12, 0)`。

改 origin 时 `x` / `y` 不变、渲染偏移:锚点从中心挪到左上角,画面上纹理会向右下移动半个图。需要"无论 origin 如何都拿到四角/中心真实坐标"时,用 `getTopLeft()` 等派生方法——它们按 display 尺寸与 origin 现算,与锚点选择无关。

## 尺寸:scale 与 displaySize

改对象大小有三组入口,只有两组真的改渲染:

- **`setScale(x, y?)`——按倍数。**`setScale(2)` 两轴各放大一倍;`setScale(2, 1)` 只横向拉伸。倍数是相对纹理原生尺寸的,同一个倍率套用到不同纹理会得到不同像素尺寸。
- **`displayWidth` / `displayHeight` / `setDisplaySize(w, h)`——按像素。**`displayWidth = width × scaleX` 的双向属性:读它得到渲染尺寸,写它等于反推并修改 `scaleX`。要"把所有图标统一成 64×64"这类像素级需求,用 `setDisplaySize(64, 64)` 直接给目标值,不必自己算倍数。
- **`width` / `height` / `setSize(w, h)`——内部逻辑尺寸,不改渲染。**`setSize` 只改对象参与逻辑运算(如物理 body 尺寸基准)的内部值,纹理仍按原尺寸渲染。想让画面变大却调了 `setSize`,是最常见的"没反应"原因。

一个读数细节:`scale` 属性是特殊 setter,写它等于同时设两轴,读它返回 `(scaleX + scaleY) / 2`——两轴不一致时这个平均值没有几何含义,判断横向是否翻转拉伸要看 `scaleX` 本身。负 scale 能产生镜像,但会让读数带符号,翻转请用下一节的 `flipX` / `flipY`。

在实验台里把「缩放」从 1 调到 2 再到 0.25:displayWidth 读数走 `96 → 192 → 24`,红框同步缩放;把「原点 X」保持 0.5 时缩放围绕锚点对称进行,改成 0 后缩放只向右下延伸——缩放的方向感同样由 origin 决定。

## 翻转与旋转

**翻转:`flipX` / `flipY`(或 `setFlip(x, y)` / `toggleFlipX()`)。**镜像永远绕纹理中线进行,与 origin、scale 都无关;它是纯渲染开关——坐标、`getBounds()`、物理 body 全部不变。给角色做"朝左跑"最省事的做法就是同一张朝右纹理 + `flipX`。注意它不影响物理:碰撞体不会跟着翻,见 [3.1 Arcade 物理](?path=/docs/arcade-physics--docs)。

**旋转:`angle`(度)与 `rotation`(弧度)是同一状态的两种视图。**Phaser 用屏幕坐标系(y 向下),顺时针为正:`angle` 0 朝右、90 朝下、±180 朝左、-90 朝上;`rotation` 是同一个角的弧度值,`setAngle(90)` 与 `setRotation(Math.PI / 2)` 完全等价,改任一个另一个同步。跟关卡数据、设计稿、配置打交道用 `angle` 直观;做数学运算(速度分解、朝向插值)时用 `rotation` 配合三角函数。

旋转绕 origin 进行:在实验台里把「原点 X/Y」调回 0.5 再转「角度」,纹理绕中心十字转;改成 `0, 0` 再转,纹理绕自己的左上角(此刻正对十字)转——**origin 同时是缩放基准、旋转轴心**。旋转后 `getTopLeft()` 等返回旋转后的真实角点,`getBounds()` 返回包住四个旋转角点的轴对齐外接矩形,所以 45° 时正方形的包围盒最大(对角线 ≈ 135.8px)。

## 可见性:visible 与 alpha

- **`visible` / `setVisible(false)`:跳过渲染,对象还活着。**update 逻辑照常执行、坐标照常可读、物理 body 照常参与模拟(实验台里关掉「可见」:红框和全部读数都在);但输入命中检测会跳过不可见对象——想"隐形但可点击"做不到,要挪出交互请直接禁用输入。想"彻底移除"用 `destroy()`。
- **`alpha` / `setAlpha(v)`:0–1 的整体不透明度。**0 完全透明但仍产生渲染开销——要省性能用 `visible: false` 而不是 `alpha: 0`。WebGL 下还支持四角渐变 alpha(`setAlpha(topLeft, topRight, bottomLeft, bottomRight)`)。

tint 着色、混合模式与深度排序同属视觉状态,在 [2.2.5 深度与视觉状态](?path=/docs/depth--docs)统一讲;把对象成组挂到父节点下再统一变换,属于 [2.2.4 容器与分组](?path=/docs/containers-groups--docs)。

## Sprite 与 Image 的取舍

两类对象的变换能力(定位、origin、scale、flip、旋转、alpha、tint、输入、物理)完全一致,差异只有一条:**Sprite 多一个 AnimationState(`anims`),能播放帧动画;Image 没有,也因此更轻、API 面更小**(官方结论:不需要动画时,Image 可以在所有场合安全替代 Sprite)。Sprite 会被加入场景更新列表、每帧走一次 `preUpdate` 来推进动画,Image 不进这个列表——大量静态装饰物用 Image 是免费的性能习惯。

```ts
const logo = this.add.image(360, 60, 'logo');            // 静态:背景、UI、装饰 → Image
const player = this.add.sprite(360, 300, 'player');      // 需要 play()/anims → Sprite
player.play('run');                                       // logo 上不存在 play/anims
```

两者都能挂物理 body(`this.physics.add.image(...)` / `this.physics.add.sprite(...)`),物理本身的用法见 [3.1 Arcade 物理](?path=/docs/arcade-physics--docs)。帧动画的创建、播放控制与全局动画管理见 [2.3.1 帧动画](?path=/docs/frame-animations--docs);本课只为验证差异保留最小动画代码。

## 最佳实践

- **选型默认 Image,需要 `play()` 才升 Sprite。**官方结论:不需要动画时 Image 可在所有场合安全替代 Sprite。静态装饰、背景、UI 图标用 Image;角色、特效等多帧对象用 Sprite。两类对象可以随意混用,共享同一套变换 API。
- **按语义选 origin,而不是事后调坐标。**贴边/对齐网格的对象 `setOrigin(0, 0)`(左上角语义),站在地面上的角色 `setOrigin(0.5, 1)`(脚底语义),居中 UI 保持默认 0.5。先定 origin 再摆 `x` / `y`,坐标里的数值就是语义本身;反过来"中心锚定 + 手工加减半宽"在换素材尺寸时会全部失效。
- **改大小按像素用 `setDisplaySize`,按倍数用 `setScale`,别碰 `setSize`。**`setSize` 只改内部逻辑尺寸、不改渲染,留给物理与帧尺寸基准;统一图标规格这类需求直接给目标像素值最不容易错。
- **翻转用 `flipX` / `flipY`,不用负 scale。**flip 是纯渲染开关,scale 保持正值,`getBounds()`、物理、输入区域的读数都不被污染;负 scale 虽然也能镜像,但让 scaleX 变符号,后续所有按 scale 的计算都要额外处理。
- **角度单位跟着数据源走。**配置表、关卡数据、设计稿给的是度就用 `angle`,速度分解、朝向插值等三角运算用 `rotation`;两者是同一状态的双视图,不存在换算丢失,别在中间手工 `× Math.PI / 180` 来回搬。

## 常见问题

- **对象显示位置和预期差了"半张图"。**
  origin 默认 `(0.5, 0.5)`,`x` / `y` 指的是纹理中心而非左上角。要左上角语义就 `setOrigin(0, 0)`;要确认当前锚点读 `originX` / `originY` 或对照 `getTopLeft()` 与 `x` / `y` 的差值。
- **调了 `setSize` 画面大小没变。**
  `setSize` 只改内部逻辑尺寸(供物理 body 等使用),渲染尺寸由 scale 决定。想按像素改显示大小用 `setDisplaySize(w, h)`,想按倍数用 `setScale(n)`。
- **旋转后 `getBounds()` 变大,碰撞/布局按包围盒算出了缝。**
  `getBounds()` 返回轴对齐外接矩形,旋转 45° 的正方形包围盒是对角线长度(约 1.41 倍边长),这是数学结果不是 bug。需要"旋转后仍贴本体"的判定,用物理 body(见 [3.1 Arcade 物理](?path=/docs/arcade-physics--docs))或按 `getTopLeft()` 等真实角点自己算。
- **`rotation = 90` 没反应或方向"反了"。**
  `rotation` 的单位是弧度,90 rad ≈ 5156°,看起来像随机角;且屏幕坐标系 y 向下,顺时针为正。想用度就写 `setAngle(90)`,两者等价。
- **打开 `flipX` 后物理碰撞位置不对。**
  flip 是渲染开关,物理 body 不参与翻转;翻转的是画面,碰撞体保持原状。需要"碰撞跟着翻转"的精确手感时要手动调 body 偏移,见 [3.1 Arcade 物理](?path=/docs/arcade-physics--docs)。
- **`alpha = 0` 了性能没变好。**
  alpha 只是不透明度,完全透明的对象仍走渲染流程。要省渲染开销用 `setVisible(false)`(直接跳过渲染)或把对象移出场景;两者语义不同,前者可随时切回。

## 总结回顾

摘要:

Sprite 与 Image 是承载纹理的两类基础显示对象,共享同一定位模型:`x` / `y` 指向锚点,`origin`(默认 0.5, 0.5)决定锚点取在纹理内的归一化位置,并有 `displayOrigin` 像素版。缩放按倍数用 `setScale`、按像素用 `setDisplaySize` / `displayWidth`,`width` / `setSize` 只改内部尺寸不改渲染;翻转 `flipX` / `flipY` 是绕中线的纯渲染开关,坐标与物理不动;`angle`(度,顺时针为正)与 `rotation`(弧度)是同一状态的双视图,旋转与缩放都绕 origin 进行;`visible` 跳过渲染但保留 update 与坐标,`alpha` 是 0–1 的不透明度。派生坐标用 `getTopLeft()` / `getCenter()` / `getBottomRight()` 等读取,`getBounds()` 给轴对齐外接矩形。两类对象唯一的能力差异是 Sprite 的 `anims` 动画组件,不需要帧动画就用更轻的 Image。

一句话:

> `x` / `y` 定的是锚点,`origin` 定的是锚点在纹理内的位置,其余一切变换(缩放、旋转、包围盒)都围绕这对关系展开。

知识要点:

- `add.image` 与 `add.sprite` 的参数是什么?两者的能力差异只有哪一条,各自适用什么场景?
- origin 默认值是多少?`setOrigin(0, 0)` 与 `setOrigin(0.5, 1)` 各对应什么定位语义?
- 按像素改渲染尺寸、按倍数改渲染尺寸分别用什么?`setSize` 为什么改不了画面大小?
- `flipX` 翻转后,`getBounds()` 与物理 body 分别变不变?为什么?
- `angle` 与 `rotation` 的单位、正方向是什么?两者什么关系?
- `visible: false` 时哪些行为保留(update、坐标、物理)、哪些停止(渲染、输入命中)?
- 需要四角/中心/包围盒真实坐标时,分别调用哪些方法?
