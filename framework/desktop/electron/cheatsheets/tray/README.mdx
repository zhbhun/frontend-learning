# 托盘

托盘是应用钉在系统里的常驻入口：一个图标活在 macOS 菜单栏或 Windows/Linux 通知区，窗口可以全关，应用继续在后台服务。Electron 的 `Tray` 是一个主进程对象——在 app `ready` 之后用 `new Tray(image)` 创建，图标（nativeImage）是它唯一的本体；交互入口有两个：`setContextMenu` 挂托盘菜单（最可靠，Linux 上几乎是唯一选择），`click` 等事件响应点按（平台差异最大的地方——macOS 设置菜单后点按被菜单接管，click 不再触发）。托盘真正的价值在「关闭到托盘」的常驻模式：窗口 `close` 拦截改写成隐藏、`window-all-closed` 不退出、退出时用 `before-quit` 标志放行——「[应用生命周期](?path=/docs/app-lifecycle--docs)」预告过的"托盘类常驻应用"，本课补全。读完你应能预测：关掉窗口后应用还活着吗、点一下托盘图标会发生什么（三个平台各不同）、为什么 Linux 应用都把功能放进托盘菜单、点托盘「退出」为什么会点不动。

关键回查项（完整语义见正文与参考资料）：

| 回查项 | 值 | 备注 |
| --- | --- | --- |
| `new Tray(image)` | 创建托盘 | 放在 `app.whenReady()` 之后；用模块级变量保住引用 |
| 图标推荐尺寸 | 16×16 + 32×32@2x | macOS 上 @2x 需 144dpi，否则高分屏发虚 |
| macOS 模板图 | 文件名以 `Template` 结尾 | 黑色 + alpha，深浅色菜单栏自动适配 |
| `tray.setContextMenu(menu)` | 挂托盘菜单，传 `null` 移除 | macOS 任何点按都弹；Windows 右键弹；Linux 主交互 |
| `tray.setToolTip(text)` | 悬停提示 | 空字符串移除 |
| `tray.setImage(image)` | 运行期换图标 | 用图标表达运行状态 |
| `tray.setTitle(title)` | 图标旁显示文字 | 仅 macOS |
| `tray.popUpContextMenu([menu, position])` | 主动弹菜单 | macOS / Windows；`position` 仅 Windows |
| `tray.destroy()` | 立即销毁托盘 | 配合 `tray.isDestroyed()` 查询 |
| `click` 事件 | 点按托盘图标 | Linux 上是“激活”，方式由桌面环境决定 |
| `right-click` 事件 | 右键 | 仅 macOS / Windows |

## 快速上手

沿用前面课程用 Forge 创建的项目（`src/index.js` + `src/index.html`，见「[安装](?path=/docs/install--docs)」），三步让应用拥有托盘。完整参考实现（托盘 + 关闭到托盘）在本课目录的 `tray-main.js`。

1. 把本课目录下的四个图标文件复制到 `src/`：`icon.png` / `icon@2x.png` 给 Windows/Linux（@2x 供高分屏自动匹配），`iconTemplate.png` / `iconTemplate@2x.png` 给 macOS（模板图，见「图标」一节）。
2. 在 `src/index.js` 里扩展 `require`、声明模块级变量，并在 `whenReady` 回调（Forge 模板已有骨架，见「[应用生命周期](?path=/docs/app-lifecycle--docs)」）里创建托盘：

   ```js
   const { app, BrowserWindow, Menu, Tray, nativeImage } = require('electron');
   const path = require('node:path');

   let tray = null; // 模块级引用，别让 Tray 落进函数局部作用域

   app.whenReady().then(() => {
     createWindow();

     // macOS 用模板图（深浅色菜单栏都清晰），其余平台用彩色图
     const iconName = process.platform === 'darwin' ? 'iconTemplate' : 'icon';
     const icon = nativeImage.createFromPath(path.join(__dirname, `${iconName}.png`));

     tray = new Tray(icon); // ready 之后创建
     tray.setToolTip('我的托盘应用');

     // 托盘菜单：同一套 Menu API（模板规则见「菜单」课）
     tray.setContextMenu(Menu.buildFromTemplate([
       {
         label: '显示主窗口',
         click: () => {
           if (BrowserWindow.getAllWindows().length === 0) createWindow();
           else BrowserWindow.getAllWindows()[0].show();
         },
       },
       { type: 'separator' },
       { label: '退出', click: () => app.quit() },
     ]));
   });
   ```

3. 在运行 start 的终端输入 `rs` 重启（主进程改动，规则见「[第一次运行](?path=/docs/first-run--docs)」），逐项核对：

   - **图标出现**——macOS 在菜单栏右上角，Windows/Linux 在通知区（找不到就展开溢出区）；
   - **悬停图标**出现「我的托盘应用」提示；
   - **macOS 上点图标直接弹菜单**——此刻你还没有监听 click，但就算监听了也不会触发，「托盘菜单」一节解释原因；
   - **点「退出」**——`npm start` 进程结束，图标消失：菜单项 click 在主进程执行，`app.quit()` 走完整退出链。

## 创建托盘：new Tray

`Tray` 是主进程里的 EventEmitter（`require('electron')` 解构出来），一个实例对应通知区/菜单栏里的一个图标。创建只要一行 `new Tray(image)`，真正要记住的是三个要点：

- **在 `ready` 之后创建。** 官方文档的所有示例都把 `new Tray` 放在 `app.whenReady().then(...)` 里——托盘依赖初始化完成的应用，跟随示例的位置写即可。
- **用模块级变量保住引用。** 官方示例把 tray 放在模块顶层。社区常见坑：把 `new Tray` 写在函数局部作用域里、没有任何变量引用它，运行一段时间后图标无故消失——垃圾回收把它收走了（这一条当前官方文档没有明文，属社区经验，但「声明模块级变量」零成本，照做即可）。
- **不需要了就销毁。** `tray.destroy()` 立即移除图标，`tray.isDestroyed()` 查询状态。适合"托盘功能可开关"的应用：关掉开关就 destroy，打开再 new 一个。

构造签名是 `new Tray(image[, guid])`：`image` 接受 NativeImage 或图片路径字符串；可选的 `guid`（UUID 格式）让图标重启后保留原位——Windows 上只在配合代码签名时有意义，入门阶段用不上。

### 图标：nativeImage 与模板图

托盘图标就是一个 nativeImage。三个常用来源：

```js
nativeImage.createFromPath(path.join(__dirname, 'icon.png')); // 从文件（最常用）
nativeImage.createFromDataURL('data:image/png;base64,...');   // 从 dataURL（图标内嵌代码）
nativeImage.createEmpty();                                    // 空图（占位）
```

`createFromPath` 的三条规则：

- **路径不存在、不可读或不是有效图片时返回空图，不报错。** 托盘位置只剩一个空白占位——排查"图标不显示"先打 `icon.isEmpty()`；
- **自动匹配 @2x**：目录里同时放 `icon.png` 与 `icon@2x.png`，引用不带后缀的路径即可，高分屏自动用高清版（支持 `@1x` 到 `@5x` 一系列后缀）；
- **格式**：PNG / JPEG 全平台，托盘场景用 PNG（透明必需）；Windows 另可从路径加载 ICO，官方建议 Windows 用 ICO 获得最佳效果。图太大时可以用 `image.resize({ width: 16 })` 缩（只给一边会保持宽高比）。

**macOS 模板图（Template Image）**是托盘图标的正确形态：黑色 + alpha 通道的单色图，macOS 据此在深浅色菜单栏之间自动反色。用法是命名约定——文件名以 `Template` 结尾（`iconTemplate.png`、`iconTemplate@2x.png`），`createFromPath` 自动识别；也可以对已有图调用 `image.setTemplateImage(true)`、用 `isTemplateImage()` 查询。两条硬边界：@2x 图必须是 144dpi，否则高分屏上发虚；打包器不得混淆或哈希文件名——名字不以 `Template` 结尾，macOS 既不变色也不用高清图（打包配置见「[打包](?path=/docs/packaging--docs)」）。

尺寸官方建议 16×16（72dpi）+ 32×32@2x（144dpi）。运行期换图标用 `tray.setImage(image)`——用图标表达运行状态（运行中 / 暂停 / 有更新）是托盘的经典用法；macOS 另有 `setPressedImage` 设置按下态。

本课目录里的四个图标文件就是快速上手复制的那几个：彩色圆环给 Windows/Linux，Template 版给 macOS。

可观察证据：快速上手——macOS 上切换系统深浅色外观，托盘图标自动反色（模板图在起作用）；故意把路径拼错，图标位置只剩空白占位，终端出现 `isEmpty` 告警。

## 托盘菜单：setContextMenu

托盘菜单和「[菜单](?path=/docs/menus--docs)」课的应用菜单、上下文菜单是同一套 `Menu` / `MenuItem` API——模板规则、role、checkbox 全部通用，本课不重讲。`tray.setContextMenu(menu)` 把一个 Menu 挂给托盘，传 `null` 移除。

关键判断：**托盘是菜单最重要的挂载形态**——三个平台把"谁响应点按"分成了三种格局：

- **macOS：菜单接管点按。** 设置菜单后，左键右键点图标都会弹出菜单；文档明文 `mouse-up` 不再触发（macOS 层面约束），click 同样不再触发（旧版文档明文、至今的通行行为）。想要"点图标做某事 + 菜单提供更多项"的形态，就不调 `setContextMenu`，改在 click 处理器里 `tray.popUpContextMenu(menu)`（见「托盘事件」一节）。
- **Windows：右键给菜单，左键给你。** 菜单只在右键时弹出，左键照常触发 click——"左键切窗口、右键弹菜单"的经典形态开箱即用。
- **Linux：菜单是唯一可靠的交互。** 托盘经 StatusNotifierItem 呈现（不可用时回落 GtkStatusIcon），点按被抽象成"激活"——何时算激活（单击还是双击）由桌面环境决定，也没有 right-click 事件。把所有功能放进菜单是 Linux 上唯一稳妥的设计。

Linux 专属边界：修改了菜单里某个 MenuItem 的属性后，**必须重新调用 `setContextMenu` 才会生效**（官方明文并附代码示例）——这是 Linux 后端与其他平台的实现差异。

菜单项的 click 同样在主进程执行：快速上手点「退出」后 `npm start` 进程结束，日志落在运行 start 的终端。

## 托盘事件：click 与平台差异

事件全景（按官方文档标注的平台收录）：

| 事件 | 平台 | 触发 |
| --- | --- | --- |
| `click` | 全平台 | 点按图标；Linux 上是"激活"，单击 / 双击由环境决定 |
| `right-click` | macOS / Windows | 右键 |
| `double-click` | macOS / Windows | 双击 |
| `mouse-down` / `mouse-up` | macOS | 按下 / 抬起；设置了菜单后 `mouse-up` 明文不再触发 |
| `mouse-enter` / `mouse-leave` / `mouse-move` | macOS / Windows | 悬停与移动 |
| `middle-click` | Windows | 中键 |
| `drop` / `drop-files` / `drop-text` 等拖放系列 | macOS | 往托盘图标上拖文件或文本 |
| `balloon-show` / `balloon-click` / `balloon-closed` | Windows | 配合遗留的 `displayBalloon` 气泡通知；新应用用 Notification 模块，见「[通知与角标](?path=/docs/notifications--docs)」 |

click 回调带 `bounds`（图标矩形，可给弹出面板定位）与 `position`（点击位置）；配对方法 `tray.getBounds()`（macOS / Windows）。相关方法还有 `tray.focus()`（仅 Windows，把焦点还给通知区）。

### 点击行为的两种形态

模拟里最值得注意的分界是 macOS：**设置了菜单，click 就不再归你**。两种经典形态由此而来：

**左键切窗口、右键弹菜单（Windows/Linux 经典）**——直接享受平台默认分工：

```js
tray.on('click', () => {
  // macOS 上设置了菜单就不会走到这里（见上一节）
  if (mainWindow.isVisible()) mainWindow.hide();
  else mainWindow.show();
});
tray.setContextMenu(menu); // 右键弹出的菜单，构建方式见「托盘菜单」
```

**左键做事、右键弹菜单（macOS 替代形态）**——放弃 `setContextMenu`，把弹菜单的时机拿回自己手里：

```js
tray.on('click', showMainWindow); // 左键：恢复主窗口
tray.on('right-click', () => {
  tray.popUpContextMenu(menu); // 右键：主动弹出（menu 用 buildFromTemplate 现成构建）
});
```

`popUpContextMenu([menu, position])` 是 macOS / Windows 的方法：传 `menu` 就弹这份（临时替代），不传弹 `setContextMenu` 设过的；`position` 仅 Windows，默认弹在图标处。配套还有 `tray.closeContextMenu()`（macOS / Windows）关闭正在显示的菜单。macOS 若需要精确的单击计数，用 `tray.setIgnoreDoubleClickEvents(true)` 忽略双击、让每次单击都触发 click。

## 关闭到托盘：常驻模式

「[应用生命周期](?path=/docs/app-lifecycle--docs)」讲过 `window-all-closed` 是应用去留的决策点，也预告过托盘类常驻应用是它的另一种选择——本节补全做法，不重讲事件链。核心判断一句话：**常驻 = 关窗不销毁 + 全关不退出 + 真退出能放行**，由四个挂点配合完成（完整参考实现在本课目录 `tray-main.js`）：

| 挂点 | 职责 |
| --- | --- |
| 窗口 `close` | `preventDefault()` + `hide()`：把"关窗"改写成"隐藏" |
| `before-quit` | 置退出标志：真退出时放行 `close` |
| `window-all-closed` | 常驻声明：任何平台都不调 `app.quit()`（对比默认惯例） |
| `activate`（macOS） | 点 Dock 图标恢复窗口（含隐藏态） |

```js
let isQuitting = false;

// 真退出的入口：托盘菜单「退出」、Cmd+Q 等所有 quit 路径都先经过这里
app.on('before-quit', () => {
  isQuitting = true;
});

mainWindow.on('close', (event) => {
  if (isQuitting) return; // 主动退出：走正常关闭
  event.preventDefault(); // 关窗按钮被拦下……
  mainWindow.hide();      // ……改写成隐藏，托盘继续常驻
});

// 常驻声明：空 handler 等于"窗口全关也不退"
// close 已被拦截，它平时很少触发，是窗口异常销毁后的最后一层保险
app.on('window-all-closed', () => {});

// macOS：Dock 图标 / activate 恢复窗口（隐藏的 show，销毁的重建）
app.on('activate', showMainWindow);

function showMainWindow() {
  if (!mainWindow || mainWindow.isDestroyed()) {
    createMainWindow();
    return;
  }
  mainWindow.show();
}
```

托盘菜单正好各用一处：「显示主窗口」调 `showMainWindow()`；「退出」调 `app.quit()`——quit 链先经过 `before-quit`（标志置位），随后逐窗 `close` 看到标志放行，窗口销毁、进程结束。「[应用生命周期](?path=/docs/app-lifecycle--docs)」里"窗口 `close` 拦截会取消整个退出"的知识点，在这里被正面利用。

**退出标志为什么不可省**：没有 `isQuitting`，点「退出」→ `app.quit()` → 窗口 `close` → 被 `preventDefault` → 退出被取消，窗口只是又隐藏了一次——"退出点不动"是托盘应用最经典的 bug。真实环境核对：

1. 关窗——窗口与任务栏条目消失、托盘还在；点托盘「显示主窗口」——窗口回来，页面状态没丢（没重建）；
2. 点托盘「退出」——进程结束；
3. 删掉 `isQuitting = true` 再点「退出」——窗口只是隐藏、进程不退（第 3 点复现 bug）；
4. macOS 上关窗后点 Dock 图标——窗口恢复。

这套写法三个平台行为一致：关窗统一变成隐藏，`Cmd+Q`、托盘「退出」都经 `before-quit` 放行——托盘常驻抹平了「应用生命周期」课里 macOS 与其他平台的关窗差异。它不是对生命周期骨架的替换：`whenReady` + `activate` + `window-all-closed` 三段式照旧保留，托盘只是往骨架里加的一个对象。打包后图标路径可能变化（asar 与资源目录，见「[打包](?path=/docs/packaging--docs)」），部署问题集中在 `createFromPath` 的入参上。

## 最佳实践

- **Linux 按"菜单优先"设计。** click 在 Linux 上是"激活"、方式由桌面环境决定，也没有 right-click 事件——功能全进托盘菜单，click 只当增强；跨平台应用按"菜单保底 + click 增强"组织。
- **图标按平台各就各位。** macOS 用 Template 模板图（16×16 + 32×32@2x，@2x 保持 144dpi），Windows/Linux 用彩色 PNG（Windows 可用 ICO）；打包配置保证文件名不被混淆或哈希。
- **引用保活。** `tray` 声明为模块级变量；可开关的托盘用 `destroy()` / `new Tray` 切换，不要反复 new 而不销毁。
- **常驻模式保留生命周期骨架。** `whenReady` + `activate` + `window-all-closed` 照旧，只改行为：`window-all-closed` 不退出、`before-quit` 置标志、`close` 拦截改隐藏。退出标志是防"退出点不动"的关键，永远配合 `before-quit` 使用。

## 常见问题

- 托盘图标不显示，或显示成空白占位
  按序排查：是否在 `app.whenReady()` 之后创建；`icon.isEmpty()` 是否为 `true`——`createFromPath` 对不存在的路径静默返回空图，打印入参核对（打包后资源路径会变，见打包课）；Linux 上部分桌面环境需要 StatusNotifierItem 支持（部分 GNOME 要装扩展才显示托盘）。
- macOS 上点了图标，click 处理器不执行
  设置了 `setContextMenu`：点按被菜单接管（`mouse-up` 明文不触发，click 同样不触发）。要点击行为就改用「托盘事件」里的无菜单形态（click + `popUpContextMenu`）。
- Windows 上左键不弹菜单
  平台行为：左键留给 click 事件，只有右键弹菜单。要左键弹菜单：不设 `setContextMenu`，在 click 处理器里 `tray.popUpContextMenu()`。
- 点托盘「退出」应用不退，窗口只是消失
  `close` 拦截没放行：必须在 `before-quit` 里把退出标志置 `true`，否则 `app.quit()` 触发的关窗被 `preventDefault` 取消（见「关闭到托盘」）。
- 运行一段时间后托盘图标自己消失了
  `Tray` 实例没有任何变量引用、被垃圾回收（社区常见坑，当前官方文档无明文）。把 `tray` 提升为模块级变量。
- Linux 上双击才触发 click，或左键行为与文档对不上
  Linux 的 click 是"激活"，单击还是双击由桌面环境决定（官方明文）。不要依赖精确的左键语义，功能放进菜单。

## 总结回顾

摘要：

托盘（`Tray`）是主进程对象，在 app `ready` 之后创建、用模块级变量保住引用，`destroy()` / `isDestroyed()` 管销毁。图标是 nativeImage：`createFromPath` 对无效路径静默返回空图（`isEmpty()` 排查）、自动匹配 `@2x` 高清版、PNG 全平台而 Windows 另可用 ICO；macOS 的正确形态是模板图——文件名以 `Template` 结尾（或 `setTemplateImage(true)`），黑色 + alpha、随深浅色菜单栏反色，代价是 @2x 必须 144dpi、打包不得混淆文件名；运行期 `setImage` 换图标表达状态。交互入口两层：`setContextMenu` 挂托盘菜单（复用 Menu API），macOS 上它接管一切点按（`mouse-up` 明文不触发、click 同样让位），Windows 只在右键弹、左键仍触发 click，Linux 上菜单几乎是唯一可靠交互（click 是"激活"、方式由环境定，改 MenuItem 后须重新 `setContextMenu`）。事件全景里 `right-click` / `double-click` 仅 macOS 与 Windows、拖放系列仅 macOS、balloon 系列是 Windows 遗留；"左键切窗口 + 右键菜单"与"无菜单 + click + `popUpContextMenu`"是两种经典形态。关闭到托盘的常驻模式由四个挂点组成：`close` 拦截改隐藏、`before-quit` 置退出标志、`window-all-closed` 不退出、`activate`（macOS）恢复窗口——退出标志缺失就是"退出点不动"的根源。

一句话：

> 托盘把"窗口即应用"改写成"应用常驻"：图标是本体、菜单是最可靠的入口、click 看平台脸色，而"关闭到托盘"就是 close 拦截成隐藏、退出时用 `before-quit` 标志放行。

知识要点：

- 托盘对象在哪个进程？什么时候创建？为什么必须模块级引用？
- `createFromPath` 对无效路径的行为是什么？图标空白时怎么排查？
- macOS 模板图是什么、怎么命名？它有哪两条硬边界？
- `setContextMenu` 之后，三个平台对左键 / 右键点按各是什么行为？
- click 在 Linux 上为什么不精确？`right-click` 事件在哪些平台存在？
- "左键切窗口、右键弹菜单"和"无菜单 + popUpContextMenu"两种形态各怎么写？
- 关闭到托盘需要哪四个挂点？退出标志为什么必要、设在哪里？
- 托盘菜单与应用菜单、上下文菜单是什么关系？Linux 上改菜单项要注意什么？
