# 基础组件

7.1 课把 gpui-kit 装进工程并装载了主题，本课开始真正用组件：按钮、输入、下拉选择、开关与勾选。全部内容基于 `gpui-kit` 0.7.1（其绑定的 GPUI 为 `gpui-pre =0.3.8` 快照，工程口径见上一课），每个组件的写法都与文档站与仓库源码逐一对过。

看懂本课只需要抓住一个分类：gpui-kit 的表单组件分三种状态模型。**无状态元素**（Button）一条 builder 链描述完即丢；**状态外置型**（Input、Select）把可变状态放在 `Entity` 里，元素只是样式外壳；**受控布尔/索引型**（Switch、Checkbox、Radio）自己不存状态，显示值由你传入，点击时把"请求的新值"交还给你写回。后面的每个小节都长在同一套共同模式上，先把它立起来。

| 组件 | 状态模型 | 一句话用途 | 文档页 |
| --- | --- | --- | --- |
| `Button` | 无状态元素 | 触发动作 | https://gpui-kit.com/component/button |
| `Input` + `InputState` | 状态外置（`Entity`） | 单行文本输入 | https://gpui-kit.com/component/input |
| `Textarea` + `TextareaState` | 状态外置（`Entity`） | 多行文本输入 | https://gpui-kit.com/component/textarea |
| `Select` + `SelectState` | 状态外置（`Entity`） | 下拉选择 | https://gpui-kit.com/component/select |
| `Switch` | 受控布尔 | 开关 | https://gpui-kit.com/component/switch |
| `Checkbox` | 受控布尔 | 勾选 | https://gpui-kit.com/component/checkbox |
| `Radio` / `RadioGroup` | 受控布尔 / 受控索引 | 单选 | https://gpui-kit.com/component/radio |

本课覆盖表单主线；这些同级组件不展开，给出入口按需查：`NumberInput`（数字步进，https://gpui-kit.com/component/number-input）、`OtpInput`（验证码输入，https://gpui-kit.com/component/otp-input）、`Combobox`（可输入联想，https://gpui-kit.com/component/combobox）、`ButtonGroup` / `DropdownButton`（按钮页内与 https://gpui-kit.com/component/dropdown_button）、`Toggle`（https://gpui-kit.com/component/toggle）、`InputGroup`（https://gpui-kit.com/component/input-group）、`Form`（https://gpui-kit.com/component/form）。

## 共同模式

所有样式组件都从 `gpui_kit::component` 及其子模块取用，初始化没有新动作——上一课的 `init(cx)` 已经装载组件层与主题，本课直接写界面即可。三件事贯穿每个组件：

**Builder 与元素 id。** 组件是 `RenderOnce` 的一次性元素，用 builder 链配置后 `.child()` 进布局。`Button::new(id)`、`Switch::new(id)` 的参数是 `ElementId`（用于状态记录与调试定位），不是显示文字；文字一律走 `.label(...)`。状态外置型则相反：`Input::new(&state)` 的参数是状态实体的引用，元素 id 默认取自状态实体。

**横切 trait。** 一批能力以 trait 形式挂在多个组件上，都从 `gpui_kit::component` 根导出，用 `use ... as _` 引入即可生效：

| trait | 方法 | 说明 |
| --- | --- | --- |
| `Sizable` | `.with_size(Size)`、`.xsmall()`、`.small()`、`.large()` | 尺寸默认 `Size::Medium`，也可传 `px(30.)` 这类自定义值 |
| `Disableable` | `.disabled(bool)` | 禁用：不可交互并套用禁用样式 |
| `Selectable` | `.selected(bool)` | 选中态（按钮、`Input` 等） |
| `ButtonVariants` | `.primary()`、`.danger()`、`.ghost()` 等 | 仅按钮族，见下一节 |

**事件回调。** 元素型回调签名统一为 `Fn(&事件, &mut Window, &mut App)`：按钮是 `on_click(Fn(&ClickEvent, ...))`，布尔组件是 `on_change(Fn(&bool, ...))`，单选组是 `on_change(Fn(&usize, ...))`。在视图方法里用 `cx.listener(|this, checked: &bool, window, cx| ...)` 包一层，就能拿到 `&mut Context<Self>` 写自身状态。状态外置型的事件不在元素上，而是从状态实体订阅（`InputEvent`、`SelectEvent`），写法在各小节给。

主题关系一句话带过（上一课已讲）：组件颜色全部按语义色取自当前 `Theme`，换主题即整体换肤；需要局部改色时用组件暴露的 `.color(...)` 一类方法覆盖，不要绕过主题硬编码样式。

## 按钮：Button

`Button` 是无状态元素，一条链写全：变体定颜色语义，尺寸定大小，`label` / `icon` 定内容，状态方法定交互，`on_click` 挂回调。

```rust
use gpui_kit::component::button::{Button, ButtonVariants as _};
use gpui_kit::component::{Disableable as _, IconName, Sizable as _};

Button::new("save")
    .primary()            // 变体，默认 Default；此处主操作色
    .small()              // 尺寸：xsmall / small / medium(默认) / large
    .label("保存")         // 显示文字；new 的参数是 id
    .icon(IconName::Check) // 图标；只给 icon 不给 label 即成图标按钮
    .disabled(!can_save)   // 禁用（Disableable）
    .loading(is_saving)    // 加载中：不可点击，普通图标自动换成 Spinner
    .on_click(|_, _, _| println!("clicked")) // Fn(&ClickEvent, &mut Window, &mut App)
```

变体由 `ButtonVariants` trait 提供，对应枚举 `ButtonVariant`：

| builder | 变体 | 用途 |
| --- | --- | --- |
| （默认） | `Default` | 普通按钮 |
| `.primary()` | `Primary` | 当前界面唯一的主动作 |
| `.secondary()` | `Secondary` | 次级操作 |
| `.danger()` | `Danger` | 删除等危险操作 |
| `.warning()` / `.success()` / `.info()` | 同名 | 语义提示色 |
| `.ghost()` | `Ghost` | 无底色，工具栏、行内操作 |
| `.link()` | `Link` | 链接外观 |
| `.text()` | `Text` | 纯文字，无内边距 |
| `.custom(v)` | `Custom(ButtonCustomVariant)` | 自定义配色 |

`.outline()` 是叠加项不是变体，可与任意变体组合出描边风格；`.compact()` 收紧内边距。要一套自己的颜色时用自定义变体，颜色从主题取：

```rust
use gpui_kit::component::button::{ButtonCustomVariant, ButtonVariants as _};
use gpui_kit::component::{ActiveTheme, Colorize as _};

let brand = ButtonCustomVariant::new(cx)
    .color(cx.theme().magenta)                    // 底色
    .foreground(cx.theme().primary_foreground)    // 文字色
    .hover(cx.theme().magenta.opacity(0.1))       // hover 底色
    .active(cx.theme().magenta);                  // 按下底色
Button::new("brand").custom(brand).label("品牌按钮")
```

内容不止文字加图标时，`.child(...)` 可以塞任意元素；`.tooltip("提示文字")` 加悬浮提示（`tooltip_placement` 指定偏好方位），`.dropdown_caret(true)` 在尾部加下拉箭头。交互状态三个：`disabled(bool)`、`loading(bool)`（`loading_icon` 可换加载图标）、`selected(bool)`（`Selectable`，用于可选中按钮）。悬停监听 `on_hover(Fn(&bool, ...))` 的参数是"是否正在悬停"。

## 输入：Input 与 Textarea

输入组件的关键模型：`InputState` 是状态本体（GPUI 0.3.8 快照里定义在 `gpui-base` 的 `input` 模块，经组件层转出口），持有文本、光标、撤销历史；`Input` 是它的样式外壳。**状态在视图构造器里创建一次并保存为字段**，渲染时用 `Input::new(&state)` 绑定。

### InputState：值、事件与写入

```rust
use gpui_kit::component::input::{Input, InputState};

struct ProfileView {
    name_input: Entity<InputState>,
}

impl ProfileView {
    pub fn new(window: &mut Window, cx: &mut Context<Self>) -> Self {
        // builder 链在创建时定型：placeholder、初始值在这里给
        let name_input = cx.new(|cx| {
            InputState::new(window, cx)
                .placeholder("输入昵称…")
                .default_value("阿宾")
        });
        Self { name_input }
    }
}

// 渲染处
Input::new(&self.name_input)
```

读值与写值走状态实体：

```rust
// 读：任意时刻
let text = self.name_input.read(cx).value();

// 写：程序化设置（清空撤销历史，且不触发 Change 事件）
self.name_input.update(cx, |state, cx| {
    state.set_value("新值", window, cx);
});
// 保留撤销历史的替换（会触发 Change）
self.name_input.update(cx, |state, cx| {
    state.replace_all("另一个值", window, cx);
});
```

输入事件从状态实体订阅，四种：`InputEvent::Change`（文本变化）、`PressEnter`（携带 `secondary` / `shift` 字段）、`Focus`、`Blur`：

```rust
use gpui_kit::component::input::InputEvent;

// 在视图构造器里（拿得到 window 与 cx 的地方）
cx.subscribe_in(&name_input, window, |this, state, event: &InputEvent, _, cx| {
    match event {
        InputEvent::Change => {
            let text = state.read(cx).value();
            println!("输入变化：{text}");
        }
        InputEvent::PressEnter { .. } => println!("回车提交"),
        InputEvent::Focus => println!("聚焦"),
        InputEvent::Blur => println!("失焦"),
    }
});
```

`state.focus(window, cx)` 程序化聚焦；单行输入还有 `.submit_on_enter(bool)`（回车作为提交而非换行）与 `.clean_on_escape()`（Esc 清空）两个创建期开关。掩码态（密码）下取值见下文掩码小节的边界说明。

### 外观：尺寸、前后缀与状态

`Input` 外壳的可选项：`.prefix(...)` / `.suffix(...)` 接任意元素（常见是图标与小按钮）；`.cleanable(true)` 在有内容时显示一键清空；`.disabled(true)` 禁用；`.readonly(true)` 只读——与禁用的区别是只读框保持正常外观、可聚焦、可选中复制，只拒绝修改。尺寸沿用 `Sizable`（`small()` / `large()`）。`.appearance(false)` 去掉默认边框底色，方便嵌进自定义容器或与其他组件拼一个复合输入。

语义内容类型用 `.content_type(InputContentType::...)` 声明，`Password`、`EmailAddress`、`TelephoneNumber` 等取值会映射到对应的无障碍角色与平台键盘习惯。

多行输入是同一套模型的兄弟：`TextareaState` / `Textarea`，事件与读写 API 一致，创建期多两个布局参数——`.rows(n)` 固定行数、`.auto_grow(min_rows, max_rows)` 随内容伸缩：

```rust
use gpui_kit::component::input::{Textarea, TextareaState};

let body = cx.new(|cx| {
    TextareaState::new(window, cx)
        .placeholder("写点什么…")
        .auto_grow(2, 8) // 最少 2 行，最多 8 行
});
// 渲染：Textarea::new(&self.body)
```

### 校验与掩码

单行 `InputState` 有三个创建期配置，作用机制相同——**拦截式**：每次编辑先过校验，不合法的文本根本进不了输入框（空串始终放行）：

```rust
use gpui_kit::component::input::{InputState, MaskPattern};

// 校验闭包：整体文本合法才接受本次编辑
let amount = cx.new(|cx| {
    InputState::new(window, cx)
        .validate(|s, _| s.parse::<f32>().is_ok())
});

// 正则约束：只允许字母数字
let code = cx.new(|cx| {
    InputState::new(window, cx)
        .pattern(regex::Regex::new(r"^[a-zA-Z0-9]*$").unwrap())
});

// 输入掩码：按模板逐位填充（9=必填数字，A=字母，#=可选数字）
let phone = cx.new(|cx| {
    InputState::new(window, cx)
        .mask_pattern("(999)-999-9999")
});

// 数字掩码：千分位 + 2 位小数
let money = cx.new(|cx| {
    InputState::new(window, cx)
        .mask_pattern(MaskPattern::Number { separator: Some(','), fraction: Some(2) })
});
```

密码输入由两半组成：状态上 `.masked(true)` 打开掩码渲染，元素上 `.content_type(InputContentType::Password)` 声明语义、`.mask_toggle()` 显示明文切换按钮。掩码态的值有边界：掩码渲染期间复制、剪切被禁，双击选中整段；`value()` 返回的是存储文本本身，而带格式化掩码（如千分位）的输入要拿去掉格式的原始值时用 `state.unmask_value()`。

## 选择：Select

下拉选择同样是"状态 + 外壳"：`SelectState<D>` 持有选项数据与选中值，`Select` 负责触发按钮与弹出菜单。泛型参数 `D` 是选项数据的委托（delegate），**数据本身即可充当委托**——`Vec<T>`、`SearchableVec<T>`（支持搜索过滤）、`SearchableVec<SelectGroup<I>>`（分组）都实现了所需 trait。

### SelectState：选项数据与选中值

```rust
use gpui_kit::component::IndexPath;
use gpui_kit::component::select::{Select, SelectState};

struct FilterView {
    lang_select: Entity<SelectState<Vec<&'static str>>>,
}

impl FilterView {
    pub fn new(window: &mut Window, cx: &mut Context<Self>) -> Self {
        let lang_select = cx.new(|cx| {
            SelectState::new(
                vec!["Rust", "Go", "TypeScript"], // 选项：Vec 即委托
                None,                             // 初始选中；Some(IndexPath::default()) 选第一项
                window,
                cx,
            )
        });
        Self { lang_select }
    }
}

// 渲染处
Select::new(&self.lang_select)
    .placeholder("选择语言…")
    .cleanable(true) // 选中后出现清除按钮
```

`String`、`SharedString`、`&'static str` 已实现 `SelectItem`（选项条目 trait），直接可用。要"显示名"与"提交值"分离的复杂条目时，自定义类型实现 `SelectItem`：必实现 `title()`（显示与无障碍播报）与 `value()`（标识值），可选覆盖 `display_title()`（触发器上的富显示）、`matches()`（搜索匹配逻辑）、`disabled()`（置灰项）。选项数据变化用 `state.set_items(new_items, window, cx)` 整体替换。

索引类型 `IndexPath` 支持 `.row(n)` 与 `.section(n)`（分组场景）。程序化读写：

```rust
// 按值设置（要求 Value 实现 PartialEq）
self.lang_select.update(cx, |state, cx| {
    state.set_selected_value(&"Go", window, cx);
});
// 或按索引设置
self.lang_select.update(cx, |state, cx| {
    state.set_selected_index(Some(IndexPath::new(1)), window, cx);
});
// 读当前选中值
let current: Option<&'static str> = self.lang_select.read(cx).selected_value().copied();
```

搜索过滤要在委托上支持：普通 `Vec` 不过滤，把数据换成 `SearchableVec::new(vec![...])` 即得增量过滤；分组则用 `SearchableVec` 装 `SelectGroup::new("组名").items([...])`。

### Select：触发器、事件与外观

选中确认是事件不是回调：`SelectEvent::Confirm(Option<Value>)`，从状态实体订阅。值为 `None` 表示选中被清除：

```rust
use gpui_kit::component::select::SelectEvent;

cx.subscribe_in(&lang_select, window, |_, state, event: &SelectEvent<_>, _, _| {
    match event {
        SelectEvent::Confirm(Some(value)) => println!("选中：{value:?}"),
        SelectEvent::Confirm(None) => println!("已清除选中"),
    }
});
```

外壳选项：`.placeholder(...)` 未选中时的占位；`.icon(...)` 触发器图标；`.title_prefix("Language: ")` 给选中标题加前缀；`.searchable(true)` 配置在 `SelectState` 创建期，会在菜单顶部放搜索框（配 `.search_placeholder(...)` 改提示文字）；`.menu_width(px(400.))` 与 `.menu_max_h(rems(10.))`（默认 20rem）调菜单尺寸；`.appearance(false)` 去壳（嵌进复合输入的常规做法）；`.disabled(true)` 禁用；`.empty(...)` 自定义空选项占位。键盘操作：Tab 聚焦，Enter、Space、Up / Down 打开菜单，Escape 关闭，选中后菜单自动收起并把焦点还给触发器。

## 开关与勾选：Switch、Checkbox、Radio

这三个组件共享同一个受控模型，先立规则再进成员：**组件自己不存状态**。`checked(...)` 传入的值决定显示什么；用户点击（或按空格）时不改自己，而是调用 `on_change` 把"请求的新值"交给你。回调里必须写回字段并 `cx.notify()`，否则界面纹丝不动——这是本课最容易踩的坑。`on_click` 是 `on_change` 的别名，两者共用同一个回调槽，链式注册时后一个覆盖前一个。

### Switch

```rust
use gpui_kit::component::switch::Switch;

// struct SettingsView { wifi_on: bool }
Switch::new("wifi")
    .label("Wi-Fi")              // 可选文字标签，默认在右侧
    .checked(self.wifi_on)       // 显示值来自你的字段
    .on_change(cx.listener(|this, checked: &bool, _, cx| {
        this.wifi_on = *checked;  // 必须写回
        cx.notify();              // 必须触发重渲染
    }))
```

`.color(cx.theme().success)` 覆盖开启态底色（默认主题 `primary`）；尺寸、禁用、tooltip、`tab_stop` / `tab_index` 都是共同模式里的老朋友。

### Checkbox

```rust
use gpui_kit::component::checkbox::Checkbox;

// struct TermsView { agreed: bool }
Checkbox::new("terms")
    .label("我已阅读并同意服务条款")
    .checked(self.agreed)
    .on_change(cx.listener(|this, checked: &bool, _, cx| {
        this.agreed = *checked;
        cx.notify();
    }))
```

与 `Switch` 的差别只在视觉（方框对勾对圆滑轨道）；标签字号用 `Styled` 的 `.text_sm()` / `.text_lg()` 一类方法调。

### Radio 与 RadioGroup

单个 `Radio` 同样受控布尔，但互斥选择请用 `RadioGroup`：选中态收拢为一个索引，回调给 `&usize`。

```rust
use gpui_kit::component::radio::{Radio, RadioGroup};

// struct PayView { pay_method: Option<usize> }
RadioGroup::horizontal("pay")      // horizontal / vertical（默认垂直）
    .children(["支付宝", "微信", "银行卡"]) // &str 自动转成带 label 的 Radio
    .selected_index(self.pay_method)          // Option<usize>
    .on_change(cx.listener(|this, index: &usize, _, cx| {
        this.pay_method = Some(*index);
        cx.notify();
    }))
```

`.child(Radio::new("x").label("…").child(说明文字))` 可逐个加入并给单条加副文案；`.disabled(true)` 整组禁用。

## 最佳实践

- **状态归属看模型选位置。** `InputState`、`SelectState` 是实体，必须在视图构造器里 `cx.new(...)` 创建一次并保存为字段；布尔与索引是普通值，放视图字段即可，不必为 `Switch` 再包一层 `Entity`。把状态创建写进 `render` 是最常见的自毁路径：每次重渲染都换一个新实体，输入内容与焦点全丢。
- **三个输入约束按目的选。** 限制字符集（只能数字、字母）用 `.pattern(...)`；业务规则（必须是合法浮点数）用 `.validate(...)`；改变呈现格式（电话分段、千分位）用 `.mask_pattern(...)`。掩码会改写用户看到的文本，取原始值记得 `unmask_value()`；前两者不改文本。
- **异步请求中用 `loading`，权限不允许才用 `disabled`。** `loading(true)` 保持按钮外观并阻断点击（图标自动换成 Spinner），适合"正在保存"；`disabled` 是语义上不可用，适合"没有可保存的改动"。
- **有默认值就传初始选中。** `SelectState::new` 的第二参传 `Some(IndexPath...)`，让状态从一开始就一致；`.placeholder` 只表达"还没选"，别拿它兼作默认值。

## 常见问题

- 点击 `Switch` / `Checkbox` / `Radio` 毫无反应，界面不变
  在 `on_change` 里写回字段并调用 `cx.notify()`。这些组件是受控的：回调参数只是"请求的新值"，组件不会自己改自己的显示，不写回就等于拒绝了这次点击。也检查一下是否同时注册了 `on_click` 与 `on_change`——两者共用一个回调槽，后注册的把前一个覆盖掉。

- 程序里 `set_value` 改了输入框，订阅端没收到 `InputEvent::Change`
  设计如此：`set_value` 静默写入并清空撤销历史。需要让订阅端感知的程序化替换用 `replace_all`（保留撤销历史，正常发事件）。

- `Select` 配了 `.searchable(true)`，输入关键字但列表不过滤
  搜索过滤由委托的 `perform_search` 实现，普通 `Vec` 没有实现它。把选项数据换成 `SearchableVec::new(vec![...])`（分组用 `SearchableVec` 装 `SelectGroup`），过滤立即生效。

- 输入框打了字，但另一处读 `value()` 总是旧值，或输入框莫名词汇清空
  先确认读的是同一个实体：`value()` 要 `state.read(cx)` 取，不能在 builder 链上找。再确认 `InputState` 没有被放进 `render`——每次重渲染新建实体，内容和焦点都会随旧实体丢弃；状态只能在视图构造器创建一次。

- 按钮点了没反应，也没有报错
  检查按钮是否处于 `disabled(true)` 或 `loading(true)`：两者都会阻断 `on_click`（loading 只是不变灰）。若回调挂在另一个组件名下（如给 `Switch` 挂了 `on_click` 又链了 `on_change`），见第一条的覆盖规则。

## 总结回顾

摘要：

gpui-kit 的表单组件按三种状态模型组织：`Button` 是无状态 builder 元素，九种变体加 `outline` / `compact` 叠加项、四档尺寸、三类图标内容与 `disabled` / `loading` / `selected` 三个交互态；`Input` / `Textarea` 把状态放在 `InputState` / `TextareaState` 实体里，`value()` 读、`set_value` / `replace_all` 写、`InputEvent` 四类事件从实体订阅，`validate` / `pattern` / `mask_pattern` 三种拦截式约束在编辑入口把关，密码与格式化掩码各有一条取值边界；`Select` 用 `SelectState<D>` 把"数据即委托"落到 `Vec` / `SearchableVec` / `SelectGroup` 上，自定义条目实现 `SelectItem`，选中结果经 `SelectEvent::Confirm` 事件交付；`Switch`、`Checkbox`、`Radio` 是受控组件，`checked` 进、`on_change` 出，必须写回并 `notify`，互斥单选用 `RadioGroup` 收拢为索引。横贯全部组件的是 `Sizable` / `Disableable` / `Selectable` 三个横切 trait 与统一的 `Fn(&事件, &mut Window, &mut App)` 回调签名，颜色一律取自 7.1 课的语义主题。

一句话：

> 先认状态模型再写代码：元素一条链写完即丢，状态外置型在构造器建实体再绑外壳，受控布尔必须把回调里的请求值写回并 `notify`。

知识要点：

- 三种状态模型分别对应哪些组件，`Button::new(id)` 与 `Input::new(&state)` 参数为何不同
- `Sizable` / `Disableable` / `Selectable` 各提供什么方法，默认尺寸是什么
- `Button` 的九种变体、`outline` / `compact` 的叠加关系，`loading` 与 `disabled` 的行为差异
- `InputState` 的创建位置、读写 API、四类 `InputEvent` 与订阅写法，`set_value` 与 `replace_all` 的事件差异
- `validate`、`pattern`、`mask_pattern` 的共同机制与各自适用场景，掩码态取值用哪个方法
- `SelectState` 的委托即数据如何体现，`Vec` 与 `SearchableVec` 在搜索上的差别，选中如何读写、结果从哪来
- 受控布尔组件的点击流程，`on_click` 与 `on_change` 为什么不能同时注册
- `RadioGroup` 如何把多个 `Radio` 收拢成一个受控索引
