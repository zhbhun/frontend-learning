# Flex 布局

GPUI 的布局发生在 `div` 上：每个 `div` 都有一个 `display` 属性，决定用哪套算法排列它的子节点。默认是块布局——子节点自上而下堆叠；调用 `.flex()` 后切换成 flexbox——子节点沿主轴排队、沿交叉轴对齐。flex 模型与 CSS flexbox 一致（底层是 taffy 布局引擎，gpui 0.2.2 锁定 taffy 0.9.0），API 则是 `Styled` trait 上的 Tailwind 风格链式方法。本课按五个问题展开：怎么启用 flex、主轴怎么定、空间怎么分（伸缩与主轴对齐）、交叉轴怎么对齐、间距怎么留，最后用嵌套组合出"侧栏 + 主内容"这类常见骨架。

本课方法签名与默认值全部核对自 crates.io 最新发布版 gpui 0.2.2（2025-10-22）的源码；入口写法沿用第 1.1 课的双口径（发布版 `Application::new().run`，git 口径 `gpui_platform::application()`），本课示例只涉及 `render` 内部，与入口无关。

| 方法组 | 默认值（0.2.2 核对） | 作用 |
| --- | --- | --- |
| `.block()` / `.flex()` / `.grid()` / `.hidden()` | `div()` 默认 `Display::Block` | 选择布局算法：块 / flex / 网格 / 不布局 |
| `.flex_row()` / `.flex_col()` / 两个 `*_reverse()` | `FlexDirection::Row`（主轴水平） | 定主轴方向 |
| `.flex_1()` / `.flex_auto()` / `.flex_initial()` / `.flex_none()` | `flex_grow: 0.0`、`flex_shrink: 1.0`、`flex_basis: auto` | 子项沿主轴伸缩 |
| `.justify_start()` … `.justify_around()` | 未设置，taffy 回退为起点对齐 | 主轴对齐 |
| `.items_start()` … `.items_baseline()` | 未设置，taffy 回退为 `Stretch`（拉伸填满） | 交叉轴对齐 |
| `.content_start()` … `.content_stretch()` | 未设置，taffy 回退为 `Stretch` | 多行在交叉轴的分布 |
| `.gap_0()` … `.gap_128()` / `.gap_x_*` / `.gap_y_*` | `0` | 子项间距（`gap_1` = 0.25rem） |
| `.flex_wrap()` / `.flex_nowrap()` | `FlexWrap::NoWrap` | 放不下时是否换行 |

## 启用 flex：display 决定布局算法

`div()` 拿到的初始样式来自 `Style::default()`，其中 `display` 字段的默认值是 `Display::Block`（gpui 0.2.2 的 `impl Default for Style`）。链式调用设置的样式都记进一个 `StyleRefinement` 精化，布局时叠加在默认样式之上——所以一个什么都没设置的 `div` 是块容器：子节点自上而下堆叠，宽度撑满父容器。

关键判断：**块布局忽略所有 flex 属性**。`flex_direction`、`items_*`、`justify_*`、`gap_*` 在块容器上全部无效——taffy 的块布局算法不读取这些字段。官方示例里每个容器都显式写 `.flex()`，不是风格装饰，而是 flexbox 的启用开关：

```rust
// 块容器：两个色块纵向堆叠、各自撑满宽度，flex 属性全部无效
div()
    .items_center() // 被忽略：块布局不读交叉轴对齐
    .child(div().h_8().bg(gpui::red()))
    .child(div().h_8().bg(gpui::blue()));

// flex 容器：两个色块横向排队，交叉轴居中生效
div()
    .flex()         // 启用 flexbox，主轴默认水平
    .items_center() // 交叉轴（这里是垂直方向）居中
    .child(div().h_8().bg(gpui::red()))
    .child(div().h_8().bg(gpui::blue()));
```

`Styled` trait 上改变 display 的方法共四个：

| 方法 | display 值 | 行为 |
| --- | --- | --- |
| `.block()` | `Display::Block` | 块布局：纵向堆叠、撑满宽度（默认） |
| `.flex()` | `Display::Flex` | flexbox 布局，本课主角 |
| `.grid()` | `Display::Grid` | CSS Grid 网格布局，第 2.3 课的主题 |
| `.hidden()` | `Display::None` | 不布局、不绘制，从界面上摘除 |

## 主轴与方向

flex 容器有两根轴：**主轴**是子项排队的方向，**交叉轴**垂直于主轴。这根绑定关系是全部对齐 API 的地基——`justify_*` 永远沿主轴分配，`items_*` 永远沿交叉轴对齐，容器尺寸怎么变都不会互换。

主轴方向由 `flex_direction` 决定，默认 `FlexDirection::Row`（水平，从左到右），与 CSS 一致。四个对应方法：

| 方法 | 方向变体 | 子项排队方向 |
| --- | --- | --- |
| `.flex_row()` | `Row`（默认） | 从左到右 |
| `.flex_col()` | `Column` | 从上到下 |
| `.flex_row_reverse()` | `RowReverse` | 从右到左 |
| `.flex_col_reverse()` | `ColumnReverse` | 从下到上 |

```rust
div()
    .flex()
    .flex_col() // 主轴转成纵向：子节点从上往下排
    .gap_2()
    .child("第一行")
    .child("第二行");
```

反向方向的语义细节：`items_start` 实际设置的是 `FlexStart`（flex 相对端）——按枚举文档的说明，它在 `RowReverse`、`ColumnReverse` 容器里等价于 `End`，其余情况等价于 `Start`；`justify_start` 设置的 `Start` 则是物理端，不随方向翻转。常规方向下两者表现一致，写反向容器时才需要区分。

## 伸缩：flex_1 与 flex_none

flex 子项沿主轴的伸缩由三个属性共同决定，默认值与 CSS 相同：

- `flex_grow: 0.0`——容器有富余空间时不放大；
- `flex_shrink: 1.0`——空间不足时按比例收缩；
- `flex_basis: auto`——初始尺寸按内容计算。

`Styled` 提供四个 shorthand 一次设齐，覆盖绝大多数场景：

| 方法 | grow | shrink | basis | 语义 |
| --- | --- | --- | --- | --- |
| `.flex_1()` | 1 | 1 | 0（父容器的 0%） | 忽略内容初始尺寸，纯按比例分空间——"弹性区" |
| `.flex_auto()` | 1 | 1 | auto | 先按内容给初始尺寸，再分富余空间 |
| `.flex_initial()` | 0 | 1 | auto | 显式写回默认：不放大、可收缩 |
| `.flex_none()` | 0 | 0 | 不修改 | 完全刚性：固定件，不放大也不收缩 |

需要更细的控制时用单项方法：`.flex_grow()` 设 grow 为 1，`.flex_shrink()` 设 shrink 为 1，`.flex_shrink_0()` 设 shrink 为 0，`.flex_basis(...)` 接受任何 `impl Into<Length>` 的初始尺寸。

最常用的搭配是"固定件 + 弹性区"：

```rust
div()
    .flex()
    .child(div().w(px(200.)).flex_none().bg(gpui::red())) // 固定 200px，绝不变形
    .child(div().flex_1().bg(gpui::blue()));              // 吃掉剩余全部宽度
```

## 对齐：items、justify 与 content

对齐分配的是**剩余空间**——容器尺寸减去内容尺寸后多出来的那部分。容器没给尺寸时高度贴着内容，剩余空间为零，任何对齐写法都看不出变化。想让对齐生效，先给容器确定尺寸：`.size_full()`、固定尺寸，或者让父级用 `.flex_1()` 分空间下来。

### 主轴对齐：justify_*

| 方法 | 实际值 | 主轴上的效果 |
| --- | --- | --- |
| `.justify_start()` | `Start` | 从起点排（默认行为） |
| `.justify_end()` | `End` | 贴向终点 |
| `.justify_center()` | `Center` | 居中 |
| `.justify_between()` | `SpaceBetween` | 两端对齐，中间均分空隙 |
| `.justify_around()` | `SpaceAround` | 每项两侧留等宽空隙 |

不写 `justify_*` 时 taffy 回退为起点对齐，所以 `.justify_start()` 大多是写给读者看的。gpui 0.2.2 没有 `.justify_evenly()`（多行分布那组有 `.content_evenly()`）。典型用法是两端布局：

```rust
// 顶栏：标题靠左、按钮组靠右
div()
    .flex()
    .items_center()    // 交叉轴（垂直）居中
    .justify_between() // 主轴（水平）两端对齐
    .child("标题")
    .child(div().flex().gap_2().child("取消").child("确定"));
```

### 交叉轴对齐：items_*

| 方法 | 实际值 | 交叉轴上的效果 |
| --- | --- | --- |
| `.items_start()` | `FlexStart` | 贴起点（随方向翻转） |
| `.items_end()` | `FlexEnd` | 贴终点（随方向翻转） |
| `.items_center()` | `Center` | 居中 |
| `.items_baseline()` | `Baseline` | 文字基线对齐 |

不写 `items_*` 时 taffy 回退为 `Stretch`：**子项在交叉轴上被拉伸填满容器**。`flex_row` 里子项自动等高、`flex_col` 里子项自动等宽，都来自这个默认。gpui 0.2.2 没有 `.items_stretch()` 方法——默认行为就是 stretch，需要显式设回时（例如先写了 `items_center` 又想要某个子项恢复拉伸）得通过 `Styled::style()` 直接改 `align_items` 字段，枚举里有 `AlignItems::Stretch` 变体可用。

两轴配合就是居中模板，官方 `hello_world` 示例的骨架：

```rust
// 容器尺寸确定（500px 见方），两轴各居中一次，内容出现在正中
div()
    .flex()
    .flex_col()
    .size(px(500.0))
    .justify_center() // 主轴（纵向）居中
    .items_center()   // 交叉轴（横向）居中
```

### 多行分布：content_*

`content_*` 只在 `.flex_wrap()` 换行产生多行后才有意义，管的是"行与行"在交叉轴上怎么分布。默认同样回退为 `Stretch`（各行拉伸分掉剩余空间）。gpui 0.2.2 提供八个方法：`.content_normal()`（清除，回到默认）、`.content_start()`、`.content_end()`、`.content_center()`、`.content_between()`、`.content_around()`、`.content_evenly()`、`.content_stretch()`。

官方 `window` 示例的按钮墙同时用了三组方法，值得整段照抄体会：

```rust
// 官方 window 示例：按钮墙——放不下就换行，整体在两根轴上居中
div()
    .flex()
    .flex_wrap()      // 一行放不下就换行
    .size_full()
    .justify_center() // 每一行内部水平居中
    .content_center() // 所有行整体垂直居中
    .gap_2()
    .child(button("Normal", ...))
    .child(button("Popup", ...));
```

## 间距：gap

`gap` 是**容器属性**：只作用于子项与子项之间，首尾项外侧不会多出空隙。默认为 0，三组方法：

- `.gap_N()`——水平垂直同时设；
- `.gap_x_N()`——恒水平，`.gap_y_N()`——恒垂直。**物理轴，不随主轴旋转**：`flex_col` 里子项之间的垂直空隙要用 `.gap_y_N()`；
- `.gap(...)`、`.gap_x(...)`、`.gap_y(...)`——自由值形式，接受任何 `impl Into<DefiniteLength>` 的值：`.gap(px(12.))`、`.gap(rems(1.))`、`.gap(relative(0.5))`。

数值后缀是 Tailwind 间距刻度：整数后缀 n 一律等于 n × 0.25rem（rem 默认 16px，即 n × 4px），另有半步 `0p5`、`1p5`、`2p5`、`3p5`。常用值：

| 方法 | 换算 |
| --- | --- |
| `.gap_0()` | 0 |
| `.gap_1()` | 4px（0.25rem） |
| `.gap_2()` | 8px（0.5rem） |
| `.gap_3()` | 12px（0.75rem） |
| `.gap_4()` | 16px（1rem） |
| `.gap_8()` | 32px（2rem） |

完整刻度到 `gap_128`（32rem）为止，中间还有 `5`–`7`、`9`–`12`、`16`、`20`、`24`、`32`、`40`、`48`、`56`、`64`、`72`、`80`、`96`、`112`，以及 `gap_px`（1px）、`gap_full`（100%）、`gap_1_2`（50%）等分数形式；没有 `gap_auto`。这些刻度与 `w_*`/`h_*`/`p_*`/`m_*` 共用同一套——尺寸单位体系（px、rems、relative、fraction 的取舍）是第 2.2 课的内容。

## 换行：flex_wrap

默认 `FlexWrap::NoWrap`：所有子项挤在一行，放不下时收缩（默认 `flex_shrink: 1.0`）乃至溢出。三个方法：

- `.flex_wrap()`——放不下就换行，换行方向跟随 `flex_direction`；
- `.flex_wrap_reverse()`——反向换行；
- `.flex_nowrap()`——显式写回单行。

换行之后各管一段：行内分布归 `justify_*`，行与行之间归 `content_*`，子项间距 `gap` 两轴都生效。上一节 window 示例的按钮墙就是完整组合；另一个细节是官方把每个按钮都写成 `.flex_none()`——按钮是刚性件，换行挤压时不该被压扁，这正好是伸缩一节"固定件"原则的官方示范。

## 嵌套布局

`child()` 挂进来的 `div` 自己也是潜在容器：再次 `.flex()` 就拥有自己的两根轴。轴向逐级独立——外层决定"这块区域怎么分"，内层决定"自己内部怎么排"，对齐、间距、伸缩各管各层的孩子，互不渗透。下面的"侧栏 + 主内容"骨架可直接放进任何 `Render` 实现（入口装配见第 1.1、1.2 课）：

```rust
use gpui::{Window, div, prelude::*, px, rgb};

struct AppShell;

impl Render for AppShell {
    fn render(&mut self, _window: &mut Window, _cx: &mut Context<Self>) -> impl IntoElement {
        // 第一层：横向 flex，占满窗口——左右分栏
        div()
            .flex()
            .size_full()
            // 侧栏：固定宽度；flex_none 保证长内容也压不变形
            // 纵向其实已被默认 Stretch 拉满，h_full 写出只为直观
            .child(
                div()
                    .flex_none()
                    .w(px(240.))
                    .h_full()
                    .bg(rgb(0x21252b))
                    .p_4()
                    .child("侧栏"),
            )
            // 主区：flex_1 吃掉剩余宽度，内部再开一个纵向 flex
            .child(
                div()
                    .flex()
                    .flex_col()
                    .flex_1()
                    .h_full()
                    .gap_3()
                    .p_4()
                    // 第二层固定件：顶栏 48px 高，内部横向排、垂直居中
                    .child(
                        div()
                            .flex()
                            .flex_none()
                            .h(px(48.))
                            .items_center()
                            .px_3()
                            .bg(rgb(0x3a3f4b))
                            .child("顶栏"),
                    )
                    // 第二层弹性件：内容区吃掉剩余高度
                    .child(
                        div()
                            .flex_1()
                            .p_3()
                            .bg(rgb(0x282c34))
                            .child("主内容"),
                    ),
            )
    }
}
```

把"主内容"换成卡片墙，就得到第二块常用积木——换行与嵌套的组合：

```rust
// 卡片墙：flex_wrap 换行 + 刚性卡片 + gap；行从顶部开始排
div()
    .flex()
    .flex_wrap()
    .flex_1()
    .content_start() // 不让默认的 Stretch 把各行拉高
    .gap_3()
    .children((0..8).map(|i| {
        div()
            .flex()       // 卡片内部也要 flex，两轴居中才生效
            .flex_none()  // 刚性卡片，换行挤压时不变形
            .w(px(160.))
            .h(px(96.))
            .items_center()
            .justify_center()
            .bg(rgb(0x3a3f4b))
            .child(format!("卡片 {i}"))
    }));
```

让布局随容器尺寸切换（窗口变窄时折叠侧栏）是容器查询，把区域等分成行列是 grid——两者都是第 2.3 课的主题；`px`、`rems`、`relative` 这些尺寸单位的选用见第 2.2 课。

## 最佳实践

- **先 `.flex()` 再谈布局。** 全部 flex 属性只在 flex 容器上生效，块容器会静默忽略它们；布局"失灵"时第一个该检查的就是容器有没有 `.flex()`。
- **刚性件 `.flex_none()`，弹性区 `.flex_1()`。** 默认 `flex_shrink: 1.0` 意味着空间不足时任何子项都可能被压缩；侧栏、按钮、图标这类固定件显式 `flex_none`，弹性区交给 `flex_1`，官方示例正是这么搭配的。
- **居中二件套：`.justify_center().items_center()`。** 各管一根轴，加上确定的容器尺寸就是任意居中；`flex_col` 换向后语义跟着互换，不必改写。
- **间距用 `gap`，不用 margin 拼。** `gap` 只出现在子项之间，首尾不产生多余空隙，省掉"首项要不要去掉 margin"的特判。
- **写对齐前先问主轴在哪。** `justify_*` 永远沿主轴、`items_*` 永远沿交叉轴、`content_*` 管多行；换 `flex_col` 后横竖语义互换，是记混的高发点。

## 常见问题

- 写了 `.flex_col()`、`.items_center()` 或 `.gap_2()`，界面毫无反应。
  先检查容器有没有 `.flex()`。`div` 默认是块容器，块布局忽略全部 flex 属性，子节点照旧自上而下堆叠；加上 `.flex()` 即可。
- `.items_center()` 想水平居中，子项却垂直居中了。
  `flex_row` 的主轴是水平的，`items_*` 管的是垂直的交叉轴；水平居中用 `.justify_center()`。容器换成 `flex_col` 后两根轴互换，答案也跟着互换。
- `.gap_x_2()` 在 `.flex_col()` 容器里没在子项之间出现空隙。
  `gap_x`/`gap_y` 是物理轴：x 恒水平、y 恒垂直，不随主轴旋转。纵向排列的项间距用 `.gap_y_2()`，或者 `.gap_2()` 一次设两轴。
- 两个 `.flex_1()` 的区域没有等分，内容长的那个更宽。
  flexbox 有"自动最小尺寸"：GPUI 默认 `overflow: Visible`，此时子项的最小尺寸按内容计算，内容的最小宽度会顶住收缩，等分随之被打破（taffy 文档明确：overflow 非 `Visible` 时自动最小尺寸才是 0）。给子项加 `.overflow_hidden()` 或 `.min_w_0()` 即可恢复严格等分。

## 总结回顾

摘要：

GPUI 的布局入口是 `div` 的 `display`：默认 `Display::Block`，块布局下子节点纵向堆叠、撑满宽度，并忽略全部 flex 属性；`.flex()` 切换成 flexbox 后，子项沿主轴排队、沿交叉轴对齐，行为与 CSS flexbox 一致。主轴方向默认 `Row`，`flex_col` 及两个 reverse 变体负责转向；子项伸缩默认不放大、可收缩、按内容起步，`flex_1` 造弹性区、`flex_none` 造刚性固定件、`flex_auto` 与 `flex_initial` 覆盖剩下两种组合。对齐分配的是容器剩余空间：`justify_*` 沿主轴（默认回退起点），`items_*` 沿交叉轴（默认回退 `Stretch` 拉伸），换行产生的多行由 `content_*` 接管；间距用 `gap` 数值刻度（n × 0.25rem）或自由值，`gap_x`/`gap_y` 恒为物理轴。任何子 `div` 都能再次 `.flex()`，轴向逐级独立，"固定侧栏 + 弹性主区、区内再分固定顶栏 + 弹性内容"就是这套机制的两层叠加。

一句话：

> `div` 默认是块容器，`.flex()` 切换成与 CSS 一致的 flexbox：伸缩与 `justify_*` 管主轴，`items_*` 管交叉轴，`gap` 管间距，`content_*` 管多行——所有这些属性只对 flex 容器生效。

知识要点：

- `div()` 默认的 display 是什么？块布局下哪些属性会被忽略、子节点表现如何？
- `.flex()` 之后主轴默认朝哪？换纵向、双向反转分别用哪个方法？
- `flex_grow`、`flex_shrink`、`flex_basis` 的默认值是什么？`flex_1`、`flex_auto`、`flex_initial`、`flex_none` 分别把它们设成什么？
- `justify_*` 与 `items_*` 各沿哪根轴？不设置时的实际行为分别是什么？
- `content_*` 什么时候才有意义？默认行为是什么？
- `gap` 的数值刻度怎么换算成像素？`gap_x`、`gap_y` 跟随主轴旋转吗？
- 换行由哪个方法控制，换行后行内分布、行间分布分别归哪组方法管？
- 为什么两个 `flex_1()` 子项可能不等分？怎么恢复严格等分？
