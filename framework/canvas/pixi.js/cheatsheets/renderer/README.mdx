# 渲染器与分辨率

PixiJS v8 的渲染配置分散在三个独立但常被一起问到的轴上：用 `preference` 在 WebGPU 与 WebGL 之间选择底层后端；用 `resolution` + `autoDensity` 让 HiDPI / Retina 屏渲染清晰、不变形；用 `resizeTo` 让画布自动跟随窗口或容器。这三项都在 `Application.init` 一次性配置，理解它们的最佳方式是看清「显示尺寸」「后备像素」「设备像素比」三者关系——读完下面的实例你会看到：调低 `resolution` 时文字和细线明显发糊，而画布的显示尺寸不变，变化的只有后备像素数。

| 配置项 | 默认值 | 作用 |
| --- | --- | --- |
| `preference` | `'webgl'` | 渲染器后端优先顺序：`'webgl'` / `'webgpu'`；传数组可限定尝试范围 |
| `resolution` | `1` | 设备像素比；HiDPI 屏设为 `window.devicePixelRatio` |
| `autoDensity` | `false` | 让 CSS 尺寸自动补偿 resolution，避免显示尺寸错位 |
| `resizeTo` | `null` | 自动跟随 Window / 元素调整画布尺寸 |
| `antialias` | `false` | MSAA 抗锯齿（与 resolution 是不同机制，见下文） |

## 渲染器后端

`Application.init` 内部调用 `autoDetectRenderer`，按 `preference` 指定的顺序尝试创建渲染器，首选不可用时自动回退到其余后端。v8 提供两个 GPU 后端：

| 后端 | 类 | 适用 |
| --- | --- | --- |
| WebGL | `WebGLRenderer` | 默认、最稳定，所有现代浏览器支持 |
| WebGPU | `WebGPURenderer` | 性能更高、更接近 GPU 原生能力，仍在成熟中，需浏览器支持 WebGPU |

默认 `preference: 'webgl'` 兼容性最好。传字符串表示「优先尝试该后端，不可用时回退其余」：

```ts
// 优先 WebGPU，不可用时自动回退 WebGL
await app.init({ preference: 'webgpu' });
```

要精确限定只尝试列出的后端（不回退到未列出的），传数组：

```ts
await app.init({ preference: ['webgpu', 'webgl'] });
```

确认运行时实际选中了哪个后端，看渲染器实例的类名，或打开 `hello: true` 让 PixiJS 在控制台打印：

```ts
await app.init({ hello: true });
// 控制台输出类似：PixiJS 8.x.x - WebGL

// 运行时判断
const name = app.renderer.constructor.name; // 'WebGLRenderer' / 'WebGPURenderer'
```

WebGPU 渲染器性能更高，但驱动和浏览器实现仍在变化，部分高级特性的行为可能与 WebGL 不同。生产环境切换到 WebGPU 前，先在目标浏览器上验证内容正确渲染——这也是本课范例固定 `preference: 'webgl'` 的原因。

## 分辨率与 HiDPI

`resolution` 是渲染器的设备像素比：它决定画布的后备存储（`canvas.width`）按多少倍数放大。默认 `1` 在普通显示器上正常，但在 HiDPI / Retina 屏（`window.devicePixelRatio` 通常为 2）上会让画面发糊——因为浏览器要把每个 CSS 像素对应的后备像素拉伸到多个物理像素上显示。

正确做法是把 `resolution` 设为 `window.devicePixelRatio`，并配 `autoDensity: true`：

```ts
await app.init({
  resolution: window.devicePixelRatio,
  autoDensity: true,
});
```

三个量的关系：

- **CSS 像素（逻辑尺寸）** — 画布在页面中的显示尺寸，即 `app.screen.width × height`。
- **设备像素（后备存储）** — `canvas.width = CSS宽度 × resolution`，决定渲染清晰度。
- **`autoDensity`** — 让 PixiJS 自动把 `canvas` 的 CSS 样式尺寸补偿回来。不开启时，`resolution > 1` 会让画布显示尺寸跟着放大、出现错位。

`antialias`（MSAA 抗锯齿）平滑的是多边形边缘，和 `resolution`（光栅化像素密度）是不同机制：调高 `resolution` 会让文字字形和小细节更清晰，而 `antialias` 只影响几何体边缘。两者可以同时开启。

## 自适应画布尺寸

`resizeTo` 让画布自动跟随一个 Window 或 HTMLElement 调整尺寸，无需手动监听 resize 事件：

```ts
await app.init({ resizeTo: window });          // 全窗口
await app.init({ resizeTo: containerEl });     // 跟随容器元素
```

容器尺寸变化时，PixiJS 自动调用 `renderer.resize()` 更新画布。`app.screen`（`Rectangle`）始终反映当前的逻辑可见尺寸，可安全用作全屏 `filterArea` 或 `hitArea`。

不用 `resizeTo` 时，手动调用 `renderer.resize(width, height)` 同步尺寸——参数是 CSS 像素尺寸；第三个可选参数可同时重设 resolution：

```ts
// 只改尺寸（参数为 CSS 像素）
app.renderer.resize(800, 600);

// 同时重设 resolution（本课实例用的方式）
app.renderer.resize(cssWidth, cssHeight, window.devicePixelRatio);
```

`resizeTo` 适合画布要填满容器的响应式场景；需要精确控制尺寸（如离屏渲染、固定分辨率，或像本课范例那样运行时切换 resolution）时用手动 `resize`。

## 最佳实践

- **HiDPI 清晰度：** 面向浏览器的应用始终配 `resolution: window.devicePixelRatio` + `autoDensity: true`；只有分辨率固定且性能敏感的离屏渲染场景才保持默认 `1`。
- **生产用 WebGL，验证后再上 WebGPU：** 默认 `'webgl'` 兼容性最好；只有在目标浏览器上验证过内容在 WebGPU 上正确渲染后，才固定 `preference: 'webgpu'`。
- **响应式用 resizeTo，精确控制用 resize：** 画布要填满容器时用 `resizeTo` 让 PixiJS 自动跟随；需要固定分辨率或运行时切换 resolution 时用手动 `resize`，两者不要同时作用于同一个画布。

## 常见问题

- **HiDPI / Retina 屏上画面发糊？**
  默认 `resolution: 1` 让每个 CSS 像素只对应一个后备像素，HiDPI 屏拉伸后变糊。把 `resolution` 设为 `window.devicePixelRatio`（通常 2）并配 `autoDensity: true` 即可恢复清晰。
- **设置了 `resolution` 后画布显示尺寸变大或变小？**
  只设 `resolution` 不开 `autoDensity` 时，画布后备存储放大但 CSS 尺寸不补偿，导致显示尺寸错位。始终把 `resolution` 和 `autoDensity: true` 配对使用。
- **`resizeTo` 设了但画布不跟随容器？**
  `resizeTo` 读取目标元素的 `clientWidth` / `clientHeight`。如果容器本身没有明确尺寸（如未设高度、`display: contents`），画布就无法跟随。确保容器有确定尺寸（用 `aspect-ratio`、`flex` 或固定高度）。

## 总结回顾

摘要：

PixiJS v8 用 `preference` 选择渲染器后端：默认 `'webgl'` 最稳定，`'webgpu'` 性能更高但仍在成熟，传字符串表示优先尝试再回退，传数组则限定尝试范围；运行时通过 `app.renderer.constructor.name` 或 `hello: true` 确认实际后端。`resolution` 是设备像素比，决定画布后备存储（`canvas.width = CSS宽度 × resolution`）的渲染清晰度——HiDPI 屏上必须设为 `window.devicePixelRatio` 并配 `autoDensity: true`，前者决定清晰度、后者保证显示尺寸不变形。`resizeTo` 让画布自动跟随 Window 或元素，`renderer.resize(w, h, resolution?)` 用于手动同步尺寸或运行时切换分辨率，`app.screen` 始终反映逻辑可见尺寸。

一句话：

> `resolution` 决定画布用多少像素渲染（清晰度），`autoDensity` 决定这些像素如何映射回显示尺寸（不变形）——HiDPI 屏上两者必须成对使用。

知识要点：

- `preference` 默认选什么后端？怎么切换到 WebGPU？
- 怎么确认运行时实际用的是哪个渲染器？
- `resolution` 和 `autoDensity` 各自影响什么？为什么必须成对用？
- 调低 `resolution` 时，后备像素和逻辑尺寸分别怎么变？
- `antialias` 和 `resolution` 平滑的是不是同一件事？
- `resizeTo` 和手动 `renderer.resize` 各适合什么场景？
