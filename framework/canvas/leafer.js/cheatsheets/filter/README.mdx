# 滤镜

LeaferJS 的 `filter` 属性是一个**可扩展的滤镜框架**：节点把自己要套用的滤镜写成一个数组，引擎按顺序逐个执行。它本身不带任何现成滤镜——2.2.9 里所有滤镜（模糊、亮度、对比度、色相……）都要先用 `Filter.register` 注册一个处理器，再把它的 `type` 写进节点的 `filter` 属性。两者缺一不可：没有注册，`type` 无人识别；没有应用，处理器不会运行。

所以滤镜永远是「两段式」配合：一段在启动时注册处理器，一段在节点上声明要用的滤镜。读完这段你就能预测——本课的第一个操作一定是「注册一个滤镜」，紧接着才是「挂到节点上、看到效果」。

需要区分的是：LeaferJS 另有一个**内置的 `blur` 属性**（一个数字，免插件），它和 `filter` 里自定义的模糊不是同一套机制。本文最后单独讲它，平时认准「`filter` 属性 + `Filter.register`」即可。

| 对象 / 输入 | 类型 | 默认 | 回查要点 |
| --- | --- | --- | --- |
| `filter`（UI 属性） | `IFilter \| IFilter[]` | `undefined` | 单对象或数组；每项 `{ type: string, visible?, ...自定义参数 }`；`visible: false` 会被引擎从生效集合剔除 |
| `Filter.register(name, processor)` | — | — | 注册名为 `name` 的处理器；`processor = { apply, getSpread }`，二者都不可省 |
| `processor.apply` | 回调 | — | `(filter, ui, worldBounds, currentCanvas, originCanvas, shape)`，在 `currentCanvas` 上画出效果；`worldBounds` 为元素世界包围盒 |
| `processor.getSpread(filter)` | `number` | — | 返回要向外扩展的渲染像素：模糊类 `>0`，颜色类返回 `0`；漏写或偏小会被裁切 |
| `import '@leafer-in/filter'` | 副作用导入 | — | 给 `Filter` 注入 `register / list / getSpread`；**不导入则 `filter` 属性无效** |
| `blur`（UI 属性，免插件） | `number` | `undefined` | 内置高斯模糊，直接 `rect.blur = 8`；详见末节 |

## 注册与应用：filter 的两段式

### Filter.register 注册滤镜处理器

`Filter` 从 `leafer-ui` 导出，但它的 `register / list / getSpread` 由 `@leafer-in/filter` 这个副作用导入注入。导入之后，`Filter.list` 是一个按名字索引处理器的空对象 `{}`，你注册什么，引擎就认识什么 `type`——2.2.9 没有任何预置项。

每个处理器只要实现两个方法：

```ts
import { Filter } from 'leafer-ui';
import '@leafer-in/filter'; // 注入 register / list / getSpread

Filter.register('blur', {
  // 在元素的离屏画布上画出效果：设 CSS filter → 重置变换 → 自拷贝 → 复位
  apply(filter, _ui, worldBounds, currentCanvas) {
    currentCanvas.filter = `blur(${filter.blur}px)`;
    currentCanvas.resetTransform();
    currentCanvas.copyWorld(currentCanvas, worldBounds, worldBounds, 'copy');
    currentCanvas.filter = 'none';
  },
  // 返回需要向外多分配的渲染像素：模糊会外溢，必须返回半径
  getSpread(filter) {
    return filter.blur;
  },
});
```

`apply` 收到六个参数，记住前四个就够用：`filter`（你在节点上写的那一项，含自定义参数）、`ui`（被滤镜作用的节点）、`worldBounds`（它的世界包围盒）、`currentCanvas`（要画出效果的离屏画布）。官方推荐的「设 CSS filter 字符串 → `resetTransform()` → `copyWorld` 把画面自拷贝一遍 → 复位」是通用模式：它用 `copy` 合成方式，让滤镜后的像素直接覆盖原像素，几乎所有颜色与模糊滤镜都能套这套壳。

`getSpread` 决定引擎要为这个元素向外多分配多少渲染像素。模糊、发光这类**会越过原图边界**的效果必须返回真实半径，否则光晕在包围盒处被一刀切平；亮度、色相这类**不改变边界**的颜色滤镜返回 `0`。

### filter 属性应用与组合

处理器注册好后，在节点上用 `filter` 属性声明要用哪些、参数是多少。写法既支持单个对象，也支持数组：

```ts
// 单个滤镜
rect.filter = { type: 'blur', blur: 4 };

// 多个滤镜按数组顺序依次合成
rect.filter = [
  { type: 'blur', blur: 4 },
  { type: 'brightness', value: 1.1 }, // 1 = 原样
  { type: 'hue', angle: 30 },          // 度
];
```

数组顺序就是合成顺序：引擎把前一个滤镜的输出当作后一个的输入，逐项自拷贝叠加。给某一项加 `visible: false`，引擎在生效前会把它剔除——既不从数组里删掉（保留参数），又不付出运行成本。下面的实例把模糊、亮度、色相三个自定义滤镜同时挂在一个四色渐变矩形上；读数里的「启用 N」会随中性值（`blur=0` / `brightness=100` / `hue=0`）自动禁用对应滤镜。

## 常用滤镜写法

绝大多数实用滤镜都是「套一层 CSS filter 函数」——`blur()` / `brightness()` / `contrast()` / `hue-rotate()` / `saturate()` / `grayscale()` / `invert()` / `sepia()` 都能直接用，区别只在 `getSpread` 要不要返回值。下面给两个代表性写法，其余照搬即可。

### 模糊 blur

模糊是少数需要 `getSpread > 0` 的滤镜：光晕会越过原图边界，返回值就是模糊半径。半径越大，渲染时要向外多分配的像素越多，这也是模糊比颜色滤镜更贵的原因。

```ts
Filter.register('blur', {
  apply(filter, _ui, worldBounds, currentCanvas) {
    currentCanvas.filter = `blur(${filter.blur}px)`;
    currentCanvas.resetTransform();
    currentCanvas.copyWorld(currentCanvas, worldBounds, worldBounds, 'copy');
    currentCanvas.filter = 'none';
  },
  getSpread(filter) {
    return filter.blur; // 漏写 → 光晕被包围盒裁平
  },
});
```

### 颜色调整 亮度 / 对比度 / 色相 / 饱和度

颜色滤镜不改边界，`getSpread` 一律返回 `0`，其余完全照搬模糊的 `apply` 壳，只换 CSS 函数和取的参数。常用映射：`brightness(0~2)`、`contrast(0~2)`、`saturate(0~2)`（`1` 为原样），`hue-rotate(0~360deg)`，`grayscale(0~1)` / `sepia(0~1)`。

```ts
Filter.register('brightness', {
  apply(filter, _ui, worldBounds, currentCanvas) {
    currentCanvas.filter = `brightness(${filter.value})`;
    currentCanvas.resetTransform();
    currentCanvas.copyWorld(currentCanvas, worldBounds, worldBounds, 'copy');
    currentCanvas.filter = 'none';
  },
  getSpread() {
    return 0; // 颜色类不扩展包围盒
  },
});
```

本课实例里的 `hue` 滤镜就是同一套壳换成 `hue-rotate(${angle}deg)`；`contrast`、`saturate`、`grayscale` 同理，按需注册即可。

## 内置 blur 属性：免插件的模糊捷径

如果你只需要一个高斯模糊、不想注册自定义滤镜，LeaferJS 还内置了一个 `blur` **数字属性**，直接挂在节点上即可，无需 `@leafer-in/filter`：

```ts
import { Leafer, Rect } from 'leafer-ui';

const rect = new Rect({ width: 200, height: 120, fill: '#ff4d4d', blur: 8 });
leafer.add(rect);
```

它的实现（`origin.setWorldBlur(blur * 缩放)` → 自拷贝 → 复位）和自定义 blur 滤镜同源，视觉效果一致，但省去了注册步骤，也无需副作用导入。选择上很直接：**单一模糊优先用内置 `blur` 属性；要组合多种效果、或需要亮度/色相等颜色调整时，才走 `filter` 属性。** 注意分属两套机制——给节点同时设 `blur: 8` 和 `filter: [{ type: 'blur', blur: 4 }]` 会各自生效、叠加模糊。

> 边界：`backgroundBlur`（背景模糊）与 `grayscale`（去色）属性在 2.2.9 虽已声明，但尚未实现——`backgroundBlur` 是空函数，`grayscale` 没有渲染入口，设置后均无视觉效果。需要去色请用自定义滤镜包一层 CSS `grayscale()`。

## 常见问题

- 设了 `filter` 却完全没有效果
  九成是忘了在入口 `import '@leafer-in/filter'`。没有这个副作用导入，`Filter` 上没有 `register / list / getSpread`，引擎遇到 `filter` 属性会被 `Plugin.need('filter')` 拦下、什么都不画。确认包已装、副作用导入已写即可。
- 模糊的光晕在边缘被「切平」
  处理器的 `getSpread` 漏写或返回了 `0`。引擎按 `getSpread` 决定要为元素向外多分配多少渲染像素，模糊这类外溢效果必须返回真实半径。把 `getSpread(filter) { return filter.blur; }` 补上。
- `backgroundBlur` / `grayscale` 属性设了没反应
  这是 2.2.9 的已知状态：二者已声明但未实现（见上节边界）。颜色去色改用自定义滤镜包一层 CSS `grayscale()`。

## 总结回顾

摘要：

LeaferJS 的 `filter` 是一个「先注册、再应用」的可扩展框架：用 `Filter.register(name, { apply, getSpread })` 注册处理器，再用节点的 `filter` 属性（单个对象或数组）声明要用哪些、参数多少，引擎按数组顺序逐项合成。`apply` 用「设 CSS filter → 重置变换 → `copyWorld` 自拷贝 → 复位」的通用模式把任意 CSS filter 函数桥接到 Canvas；`getSpread` 决定向外多分配多少渲染像素，模糊类必须返回半径、颜色类返回 0。`visible: false` 可在不删数组项的前提下让引擎跳过某项。若只需单一模糊，免插件的内置 `blur` 数字属性是更省事的捷径。

一句话：

> `filter` 属性只负责「声明要用哪些滤镜」，每个 `type` 背后必须有一个 `Filter.register` 注册的处理器，二者缺一不可。

知识要点：

- `filter` 属性和 `Filter.register` 是怎么配合的？为什么缺一个都不行？
- 一个滤镜处理器必须实现哪两个方法？各自管什么？
- `getSpread` 对模糊和颜色滤镜分别该返回什么？返回错了会怎样？
- `import '@leafer-in/filter'` 不写会怎样？
- 只想要一个高斯模糊时，比 `filter` 属性更省事的做法是什么？
- `backgroundBlur` 和 `grayscale` 属性在 2.2.9 设了为什么没效果？
