# 变换

LeaferJS 不用 CSS 那样的独立 `transform` 函数，而是把变换拆成一组**声明式属性**：位置 `x/y`、缩放 `scaleX/scaleY`、旋转 `rotation`、斜切 `skewX/skewY`。这六个属性在节点身上复合成一条**本地矩阵**，再叠加到所有祖先的矩阵上，决定节点在世界里的最终朝向与位置。六个属性各自独立、可读可写，但它们绕**哪个点**旋转/缩放，由 `around` 和 `origin` 两个锚点属性决定——这是本课最容易踩坑的地方。

先记住一句最反直觉的结论：**`rotation/scale` 默认绕节点的左上角，不是中心**。一个裸的 `new Rect({ rotation: 30 })` 会以左上角为圆心画弧线、整体甩出去；想让矩形原地自转，必须用 `around: 'center'`（或 `origin: 'center'`）把变换中心挪到中心。理解了「默认支点是左上角」和「`around` 把锚点钉在 `x/y`」，绝大多数变换结果都能提前预测。

| 属性 | 默认 | 类型 / 取值 | 回查要点 |
| --- | --- | --- | --- |
| `x`, `y` | `0` | `number` | 节点在父级本地系里的定位坐标；变换矩阵的平移分量（坐标系换算见坐标体系课） |
| `scaleX`, `scaleY` | `1` | `number`（可为负，负值翻转） | 缩放分量；`scale: n` 是同时设置两者的快捷写法 |
| `rotation` | `0` | `number`（度） | 旋转分量；**默认绕左上角**，绕中心需配 `around`/`origin` |
| `skewX`, `skewY` | `0` | `number`（度） | 斜切分量 |
| `around` | 无（按左上角定位） | `IAlign` 或 `IUnitPointData` | 变换中心 **+** 定位锚点：把该点钉在 `x/y`，旋转/缩放绕它；优先级高于 `origin` |
| `origin` | 无（= 左上角） | `IAlign` 或 `IUnitPointData` | **仅**变换中心（同 CSS `transform-origin`），不改变定位 |

`around` 与 `origin` 共用一套取值：`IAlign` 是九宫格字符串 `'top-left' / 'top' / 'top-right' / 'right' / 'bottom-right' / 'bottom' / 'bottom-left' / 'left' / 'center'`；`IUnitPointData` 是 `{ type?: 'percent' | 'px', x, y }`，如 `{ type: 'percent', x: 0.5, y: 0.5 }` 表示中心、`{ x: 30, y: 20 }` 表示距左上角 30px/20px。两者都相对节点的 box 边界（自身宽高区域）计量。

## 位置：x / y

`x/y` 是变换矩阵里的**平移分量**：在没有 `around` 时，它把节点 box 的**左上角**放到父级本地系的 `(x, y)`；设了 `around` 后，它把**锚点**放到 `(x, y)`（见下节）。它只决定「放在哪」，不改变节点的朝向或尺寸。

```ts
import { Leafer, Rect } from 'leafer-ui';

const leafer = new Leafer({ view: '#stage', fill: '#fff' });
// 矩形左上角落在父级（Leafer 根）本地系的 (80, 60)。
const rect = new Rect({ x: 80, y: 60, width: 160, height: 100, fill: '#4f7cff' });
leafer.add(rect);
```

`x/y` 总是在**父级的本地坐标系**里度量，叠加祖先变换后才得到世界坐标。本地系与世界系的换算、`translate` 命令、`getWorldPointByLocal` / `getLocalPoint` 的双向换算属于坐标体系主题，本课不重复。

## 缩放、旋转、斜切

`scaleX/scaleY`、`rotation`、`skewX/skewY` 三组属性被烘进本地矩阵的 `a/b/c/d` 四个分量，它们**不改变 `boxBounds`**（节点自身的宽高区域纹丝不动），只改变在世界里渲染出的朝向与大小。三者的支点默认都是 box 的**左上角 (0, 0)**。

```ts
// 旋转 30°：默认绕左上角，矩形会沿弧线甩向右下方，而不是原地自转。
new Rect({ x: 100, y: 80, width: 160, height: 100, rotation: 30 });

// scale: 1.5 等价于同时设 scaleX: 1.5, scaleY: 1.5；传负值可镜像翻转。
new Rect({ x: 100, y: 80, width: 160, height: 100, scale: 1.5 });
new Rect({ x: 100, y: 80, width: 160, height: 100, scaleX: -1 }); // 水平翻转

// skewX: 20 让矩形沿 X 轴倾斜（类似 CSS 的 transform: skewX）。
new Rect({ x: 100, y: 80, width: 160, height: 100, skewX: 20 });
```

- `scaleX/scaleY`：取 `1` 为原始大小，`>1` 放大、`0~1` 缩小、`<0` 翻转。只想等比缩放用快捷属性 `scale`，要单独控制轴向（如仅水平翻转）才回退到 `scaleX/scaleY`。
- `rotation`：单位是**度**（不是弧度），正值为顺时针。它只描述「转多少度」，绕谁转由 `around`/`origin` 决定，默认左上角。
- `skewX/skewY`：单位也是度，分别沿 X / Y 轴斜切；斜切会改变世界包围盒但不改 `boxBounds`。

想要「矩形原地自转 / 原地放大」，下一步就必须把支点从左上角挪走——这就是 `around` 与 `origin` 的工作。

## 变换中心：around 与 origin

两个属性都用来回答「旋转、缩放绕哪个点进行」，但 `around` 比 `origin` 多走一步、行为不同，优先级也更高（同时设置时 `around` 生效）。下面的实例用 `around` 演示：红色锚点固定钉在声明的 `(x, y)` 上，矩形绕它旋转/缩放/斜切。

### origin：只换支点，不动定位

`origin` 等价于 CSS 的 `transform-origin`：它把旋转/缩放的支点挪到指定位置，**但不改变节点的定位**——没有 `around` 时，节点 box 的左上角仍然停在 `(x, y)`，就像 `origin` 不存在一样；你只是改变了「绕谁转」。

```ts
// origin: 'center' → 绕中心旋转/缩放，但矩形左上角依旧定位在 (100, 80)。
// 视觉上矩形「在原地」自转，中心位置不变，左上角会绕中心画圈。
new Rect({ x: 100, y: 80, width: 160, height: 100, origin: 'center', rotation: 30 });
```

一句话：`origin` 只调整变换支点，节点看起来「留在原处、绕自己某一点转」。它适合「定位不变、只改旋转/缩放中心」的场景。

### around：支点 + 锚点定位（优先级更高）

`around` 在 `origin` 的基础上**多走一步**：把节点内容的 `around` 点移动到起始坐标 `(x, y)`。也就是说，`x/y` 不再定位左上角，而是定位**锚点本身**；同时旋转/缩放也绕这个锚点进行。这是「以中心点定位 + 绕中心旋转」最直接的写法。

```ts
// around: 'center' → 矩形的中心被放到 (100, 80)，并绕中心旋转 30°。
new Rect({ x: 100, y: 80, width: 160, height: 100, around: 'center', rotation: 30 });

// around: 'bottom-right' → 右下角被钉在 (100, 80)，矩形整体落在该点的左上方。
new Rect({ x: 100, y: 80, width: 160, height: 100, around: 'bottom-right' });
```

| 对比 | `origin: 'center'` | `around: 'center'` |
| --- | --- | --- |
| 变换支点 | 中心 | 中心 |
| `(x, y)` 定位的是 | box 左上角（定位不变） | 锚点本身（中心被钉在 `(x, y)`） |
| 视觉结果 | 矩形原地自转，左上角绕中心画圈 | 矩形中心固定在 `(x, y)`、整体绕中心转 |
| 同时设置时 | 被 `around` 覆盖 | 生效 |

需要**命令式地以任意一点为支点**做一次性变换时，用 `scaleOf(origin, scaleX, scaleY?)`、`rotateOf(origin, rotation)`、`skewOf(origin, skewX, skewY?)`——它们的 `origin` 既可传 `{x, y}` 像素点，也可传 `IAlign` 字符串，常用于交互式编辑（拖拽手柄缩放）。

## 最佳实践

- **「原地自转 / 原地缩放」一律先设 `around`（或 `origin`）。** 不设锚点时支点是左上角，旋转/缩放会把元素甩出去，这是最常见的「为什么转歪了」原因。中心场景用 `around: 'center'` 一步到位（定位 + 支点），无需手算偏移。
- **「以中心定位」用 `around`，「保持左上角定位、只改支点」用 `origin`。** 需要元素的某个点（中心、右下角）对齐到指定坐标，选 `around`；已经按左上角排好版、只想换个旋转中心，选 `origin`，避免位置意外漂移。
- **`around` 与 `origin` 不要同时设。** 同时设置时 `around` 优先、`origin` 被忽略；保留语义清晰，只设一个。
- **等比缩放用 `scale`，轴向缩放/翻转才用 `scaleX/scaleY`。** 需要单独翻转某一轴时记得设对应的负值分量，另一轴保持 `1`。
- **交互式「绕手柄缩放」用 `scaleOf/rotateOf/skewOf`。** 它们以任意点为支点做一次性矩阵变换，省去手动算 `around` 偏移。

## 常见问题

- 旋转后元素「飞」到了别处，不是原地自转
  支点默认是左上角，旋转自然绕左上角画弧。给元素加 `around: 'center'`（推荐，同时定位中心）或 `origin: 'center'`（保持原定位、只改支点）即可绕中心转。
- 设了 `around: 'center'`，元素整体位置变了
  这是 `around` 的预期行为：`x/y` 改为定位**锚点**（中心），而不是左上角。若你本意是「左上角定位不变、只换旋转中心」，改用 `origin: 'center'`。
- 同时设了 `origin` 和 `around`，`origin` 没生效
  `around` 优先级更高，会覆盖 `origin`。两者只设一个：要定位锚点用 `around`，只换支点用 `origin`。
- 缩放/旋转后 `boxBounds` 读数没变
  `boxBounds` 是节点**自身坐标系**的原始宽高区域，缩放/旋转/平移都不改变它（见包围盒课）。要看变换后的世界尺寸，读 `getBounds('box', 'world')`（世界 AABB，旋转后会变大）。

## 总结回顾

摘要：

LeaferJS 把变换拆成六个声明式属性：`x/y`（平移）、`scaleX/scaleY`（缩放，可用 `scale` 统一设置）、`rotation`（旋转，单位度）、`skewX/skewY`（斜切），它们烘进一条本地矩阵、再叠加祖先变换得到世界结果，且都不改变节点自身的 `boxBounds`。这六个属性默认绕 box 的**左上角**变换——这是「转歪了」的根源。`origin` 像 CSS `transform-origin`，只挪动旋转/缩放支点、不改变定位；`around` 在此基础上多走一步，把锚点钉在 `(x, y)` 上，兼顾支点与定位，优先级高于 `origin`。想要原地自转用 `around: 'center'`，想要任意点为支点的一次性变换用 `scaleOf/rotateOf/skewOf`。

一句话：

> `rotation/scale` 默认绕左上角；`around` 把锚点钉在 `x/y`（支点 + 定位），`origin` 只换支点不动定位——想让元素原地自转，先给一个 `around: 'center'`。

知识要点：

- 六个变换属性（`x/y`、`scaleX/scaleY`、`rotation`、`skewX/skewY`）各自是什么、默认值是多少？
- 为什么裸设 `rotation` 元素会「甩出去」？默认变换中心在哪？
- `around` 和 `origin` 各自做什么，同时设置时谁生效？
- 想要「以中心定位 + 绕中心旋转」和「左上角定位不变、只绕中心转」分别该用哪个属性？
- `scale` 与 `scaleX/scaleY` 的关系，怎样做水平翻转？
