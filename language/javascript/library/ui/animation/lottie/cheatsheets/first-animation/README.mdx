# 第一次播放

本课把一个 Lottie 动画从引入播放器到真正在页面里动起来跑通一遍。lottie-web 是 Lottie 在浏览器里的官方播放器，一切播放都从一次 `lottie.loadAnimation(...)` 调用开始。这个调用带三个决定一切的要素——动画渲染到哪个容器（`container`）、用什么渲染器画每一帧（`renderer`）、播放什么数据（`path` 或 `animationData`）——再加 `loop`、`autoplay` 两个决定「怎么开始」的开关。

```mermaid
flowchart LR
  call["lottie.loadAnimation(...)<br/>一次调用，全部参数"] --> c["container<br/>渲染到哪"]
  call --> r["renderer<br/>怎么画"]
  call --> p["path / animationData<br/>画什么"]
  c --> item["动画实例"]
  r --> item
  p --> item
  item --> out["容器里逐帧出现的动画<br/>loop / autoplay 决定如何开始"]
```

读完本课，你能用十几行 HTML 跑出第一个动画，并解释每个参数、排查「页面为什么是空的」。

## 快速上手

新建一个目录，放入下面两个文件：一个 HTML 页面，一份动画 JSON（直接用「动画数据」一节自制的 `first-animation.json`）。

```html
<!DOCTYPE html>
<html lang="zh-CN">
<head>
  <meta charset="UTF-8" />
  <title>第一次播放</title>
</head>
<body>
  <!-- 1. 容器：动画最终渲染进这个 div，必须有明确宽高 -->
  <div id="animation" style="width: 320px; height: 180px;"></div>

  <!-- 2. 引入 lottie-web：脚本加载后得到全局对象 lottie -->
  <script src="https://unpkg.com/lottie-web@5/build/player/lottie.min.js"></script>

  <!-- 3. 创建动画：一次调用传入三要素和两个播放开关 -->
  <script>
    lottie.loadAnimation({
      container: document.getElementById('animation'), // 容器：渲染到哪个元素
      renderer: 'svg',                                 // 渲染器：用 SVG 画每一帧
      loop: true,                                      // 到达末帧后从头再播
      autoplay: true,                                  // 数据就绪后立即播放
      path: 'first-animation.json',                    // 动画来源：JSON 的 URL
    });
  </script>
</body>
</html>
```

三个部分各做一件事：

1. `<div id="animation">` 是容器。lottie 生成的 SVG 宽高都是 100%，容器自身必须有尺寸，否则页面看起来是空的。
2. `<script src="...lottie.min.js">` 是引入。加载完成后全局多出一个 `lottie` 对象，所有 API 都挂在它上面。
3. `lottie.loadAnimation({...})` 是创建。参数齐全时它会立即开始拉取 JSON，就绪后自动播放。

`path` 的数据通过 XHR 读取，直接双击 HTML 以 `file://` 打开会失败。在文件所在目录起一个本地静态服务再访问：

```bash
python3 -m http.server 8000
# 或使用 npx serve，然后浏览器打开 http://localhost:8000
```

运行验证：页面出现一个蓝色圆点从左滑到右，约 2 秒一轮、循环往复。

## 引入方式

两种引入得到同一个 `lottie` 对象、同一套 API，差别只在对象从哪来；下文所有代码两种方式通用。

**script CDN**：适合没有构建工具的静态页面。`@5` 表示 5.x 的最新版本，脚本执行后暴露全局 `lottie`：

```html
<script src="https://unpkg.com/lottie-web@5/build/player/lottie.min.js"></script>
<script>
  lottie.loadAnimation({ /* ... */ });
</script>
```

**npm import**：适合有打包工具的项目。安装 `npm install lottie-web` 后导入默认导出，拿到的就是同一个对象：

```js
import lottie from 'lottie-web';

lottie.loadAnimation({ /* ... */ });
```

unpkg 的 `build/player/` 目录下还有 `lottie_light.min.js` 等裁剪构建（体积更小、不含表达式等特性），按体积取舍的选型依据在「性能优化」一课展开。

## loadAnimation 参数

| 参数 | 类型 | 默认值 | 作用 |
| --- | --- | --- | --- |
| `container` | DOM 元素 | 无（必填） | 动画渲染进该元素；SVG 宽高为 100%，容器需有明确尺寸 |
| `renderer` | `'svg'` \| `'canvas'` \| `'html'` | `'svg'` | 每一帧的绘制方式；三者的原理与取舍见「渲染器选型」一课 |
| `loop` | boolean \| number | `true` | 到达末帧后是否从头再播；传数字表示最多循环该次数 |
| `autoplay` | boolean | `true` | 动画数据就绪后立即开始播放 |
| `path` | string | 无 | 动画 JSON 的 URL，通过 XHR 加载；与 `animationData` 互斥 |
| `animationData` | object | 无 | 内联的动画数据对象；与 `path` 互斥，两者的取舍见「获取动画素材」一课 |
| `name` | string | `''` | 给实例命名，供 `lottie.play(name)` 等全局调用按名引用 |

本课的最小闭环只用 `path` 加载。两点边界：

- `loop` 和 `autoplay` 是**创建时**的参数：改变它们要按新参数重新调用 `loadAnimation`，这正是在下方内嵌实例里切换开关时看到的行为。
- 更细的渲染配置（如 canvas 渲染器的 context、`preserveAspectRatio`）通过 `rendererSettings` 传入，属于渲染器选型的内容。

## 动画数据

`path` 指向的是一份描述动画的 JSON：图层、形状、关键帧都写在里面，播放器只负责按帧插值并渲染。真实项目的 JSON 由 AE 导出（见「制作流程」一课），但它的骨架很简单，可以手工写一个最小的——本课的快速上手和内嵌实例用的都是下面这份：30fps、共 60 帧，一个蓝色圆点从左滑到右。


把它保存为 `first-animation.json`，就是快速上手里 `path` 指向的文件。逐层看它的结构：

| 字段 | 本课取值 | 含义 |
| --- | --- | --- |
| `v` | `"5.7.4"` | 导出时的格式版本 |
| `fr` | `30` | 帧率（帧/秒），决定 60 帧播多久 |
| `ip` / `op` | `0` / `60` | 动画的起始帧 / 结束帧（in point / out point） |
| `w` / `h` | `300` / `160` | 舞台宽高，播放时按容器等比缩放 |
| `layers` | 一个形状图层 | 图层数组，按顺序叠放绘制 |
| `assets` | `[]` | 外部图片、预合成等资源；本例没有 |

图层内部的两处关键结构：`ks` 里的 `p`（位置）标记 `"a": 1` 表示带动画，两个关键帧定义了第 0 帧在 `(60, 80)`、第 60 帧到 `(240, 80)`；`shapes` 里是一个椭圆（`ty: "el"`）加填充（`ty: "fl"`）。这份 JSON 没有用到字体、遮罩、matte 和表达式——真实素材里的这些导出特性由「制作流程」一课负责。

| 读者操作 | 可观察证据 |
| --- | --- |
| 关掉 `autoplay` | 重建后的圆点静止在第 0 帧，读数「已暂停」；再打开立即播放 |

## 常见问题

- 页面一片空白，控制台也没有报错。
  先检查容器有没有高度：lottie 生成的 SVG 宽高都是 100%，容器高度塌陷为 0 时什么都看不见。给容器显式设置 `width` 和 `height`，或让父级把它撑开。
- 动画不出现，Network 面板里 JSON 请求显示 404 或 CORS 报错。
  `path` 按 URL 规则解析，相对路径以页面地址为基准。在 Network 里核对实际请求地址，修正 `path` 的拼写和层级；JSON 与页面不同域时，把文件放到同源可访问的位置。
- 双击 `index.html` 用 `file://` 打开，动画加载不出来。
  `path` 的数据通过 XHR 读取，浏览器禁止 `file://` 页面发起这类请求。把文件放进任意静态服务器再访问，例如 `python3 -m http.server 8000` 或 `npx serve`。

## 总结回顾

摘要：

本课用一次 `lottie.loadAnimation(...)` 跑通了从引入到播放的最小闭环：script CDN 与 npm import 两种引入得到同一个 `lottie` 对象；创建调用的三要素——`container` 决定渲染到哪、`renderer` 决定怎么画、`path` / `animationData` 决定画什么——加上 `loop`、`autoplay` 两个创建时的播放开关，其中 `renderer`、`loop`、`autoplay` 不写时分别默认 `'svg'`、`true`、`true`。播放的 JSON 自身描述帧率、起止帧、图层与关键帧，本课自制的那份只有一个形状图层和一个位置关键帧。页面空白、JSON 404、`file://` 打不开三类故障，分别对应容器尺寸、`path` 解析和协议限制。

一句话：

> `loadAnimation` 的三要素——容器、渲染器、动画来源——决定动画在哪里、怎么画、画什么；`loop` 与 `autoplay` 只是创建时的开始方式，改了就要重建实例。

知识要点：

- `loadAnimation` 的核心参数有哪些，`renderer`、`loop`、`autoplay` 的默认值分别是什么？
- script CDN 与 npm import 为什么可以互相替换？
- 为什么改 `loop` 或 `autoplay` 必须重建实例？
- 一份最小的 Lottie JSON 有哪些顶层字段，各控制什么？
- 页面空白但无报错、JSON 请求 404、`file://` 加载失败，分别先检查什么？
