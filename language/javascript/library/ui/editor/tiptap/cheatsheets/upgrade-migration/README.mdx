# 升级与迁移

本课是两条迁移路线的回查入口。**v2 项目升到 v3**：破坏性变更的绝大部分是"包搬家"——包合并、改名、import 路径变化，机械替换即可；真正需要动逻辑的只有三处：命令默认值、菜单定位库（tippy.js → Floating UI）、React 渲染策略。**从其他编辑器（CKEditor 5、Slate、Quill、Lexical）迁到 Tiptap**：先按内容模型、扩展机制、UI 成本三个视角评估，再动手重建。v3 包生态的完整分层与许可结构由[是什么](?path=/docs/what-is-tiptap--docs)一课承接，本课只讲"从 v2 出发改了什么"；本手册工作区为 v3 环境，v2 写法仅作对照出现。

先列出最高频的改动，完整清单在正文各小节：

| 回查点 | v2 写法 | v3 写法 |
| --- | --- | --- |
| 撤销重做扩展 | `@tiptap/extension-history` 导出 `History` | `@tiptap/extensions` 导出 `UndoRedo` |
| 撤销重做配置键 | `StarterKit.configure({ history: false })` | `StarterKit.configure({ undoRedo: false })` |
| 菜单定位选项 | `tippyOptions`（基于 tippy.js） | `options`（基于 Floating UI） |
| React 菜单组件 | `import { BubbleMenu } from '@tiptap/react'` | `import { BubbleMenu } from '@tiptap/react/menus'` |
| `setContent` 签名 | `setContent(content, emitUpdate, parseOptions)` | `setContent(content, { emitUpdate, parseOptions })` |
| 字数统计 | `editor.getCharacterCount()` | `editor.storage.characterCount.characters()` |
| 浏览器全局变量 | UMD 构建可用 | UMD 构建已移除，改用 ESM 引入 |

## 升级清单

官方升级指南把破坏性变更分成三组，处理方式不同：**包改动**用映射表替换 import 与 `package.json` 依赖；**菜单系统**要更换定位依赖并改 prop；**API 行为变化**要回到调用点确认默认值与返回值。升级前先记住一个前提：所有 `@tiptap/*` 包要**整组一起升到 v3**——`@tiptap/pm` 保证你拿到的 ProseMirror 与 `@tiptap/core` 内部使用的是同一份，新旧混装会破坏这个约定。

### 包合并与改名

v2 时代"一个扩展一个包"的粒度在 v3 收敛：同族扩展合并为聚合包，改为具名导出。按旧包名逐组替换：

列表族六个包合并进 `@tiptap/extension-list`：

```diff
- import BulletList from '@tiptap/extension-bullet-list'
- import OrderedList from '@tiptap/extension-ordered-list'
- import ListItem from '@tiptap/extension-list-item'
- import ListKeymap from '@tiptap/extension-list-keymap'
- import TaskList from '@tiptap/extension-task-list'
- import TaskItem from '@tiptap/extension-task-item'
+ import { BulletList, OrderedList, ListItem, ListKeymap, TaskList, TaskItem } from '@tiptap/extension-list'
```

表格族四个包合并进 `@tiptap/extension-table`：

```diff
- import Table from '@tiptap/extension-table'
- import TableRow from '@tiptap/extension-table-row'
- import TableCell from '@tiptap/extension-table-cell'
- import TableHeader from '@tiptap/extension-table-header'
+ import { Table, TableRow, TableCell, TableHeader } from '@tiptap/extension-table'
```

功能扩展六个包合并进 `@tiptap/extensions`，其中 `History` 同时改名为 `UndoRedo`，该聚合包还新增了 `Selection`：

```diff
- import Focus from '@tiptap/extension-focus'
- import Placeholder from '@tiptap/extension-placeholder'
- import History from '@tiptap/extension-history'
- import Dropcursor from '@tiptap/extension-dropcursor'
- import Gapcursor from '@tiptap/extension-gapcursor'
- import CharacterCount from '@tiptap/extension-character-count'
+ import { Focus, Placeholder, UndoRedo, Dropcursor, Gapcursor, CharacterCount } from '@tiptap/extensions'
```

两个改名（含包名与导出名）：

| v2 | v3 |
| --- | --- |
| `@tiptap/extension-collaboration-cursor` 导出 `CollaborationCursor` | `@tiptap/extension-collaboration-caret` 导出 `CollaborationCaret` |
| `@tiptap-pro/extension-collaboration-history` | `@tiptap-pro/extension-snapshot` 导出 `Snapshot` |

这些扩展的现行用法与配置项不变：列表、表格见[结构扩展](?path=/docs/content-extensions--docs)，Placeholder、CharacterCount 等功能扩展见[行为扩展](?path=/docs/behavior-extensions--docs)，协作光标见协作课程。

### 菜单定位：tippy.js 换成 Floating UI

v2 用 tippy.js 给菜单定位；v3 换成 Floating UI，涉及 bubble-menu、floating-menu、drag-handle、mention（suggestion 机制）等。三步处理：

```diff
  # 依赖调整
- npm uninstall tippy.js
+ npm install @floating-ui/dom@^1.6.0
```

```diff
- // prop 与扩展选项：tippyOptions 改为 options
- <BubbleMenu editor={editor} tippyOptions={{ placement: 'top' }}>
+ <BubbleMenu editor={editor} options={{ placement: 'top', offset: 8 }}>
```

```diff
- // React / Vue 组件的 import 路径移到 /menus 子路径
- import { BubbleMenu, FloatingMenu } from '@tiptap/react'
+ import { BubbleMenu, FloatingMenu } from '@tiptap/react/menus'
```

原生 JS 不受 `/menus` 子路径影响，但 `BubbleMenu.configure()` 的定位选项同样从 tippy 配置换成了 Floating UI 的 `options`（`placement`、`offset`、`flip`、`shift` 等）。菜单的显示条件与定位策略见[菜单](?path=/docs/menus--docs)一课。

### 命令行为变化

三个命令的默认行为在 v3 有变，调用点需要复核：

- **`setContent`** 签名从位置参数改为选项对象，且默认发出 `update` 事件：

```diff
- editor.commands.setContent('<p>新内容</p>', false, { preserveWhitespace: true })
+ editor.commands.setContent('<p>新内容</p>', { emitUpdate: false, parseOptions: { preserveWhitespace: true } })
```

  选项对象支持 `emitUpdate`（默认 `true`）、`parseOptions`、`errorOnInvalidContent`。
- **`clearContent`** 默认发出 `update` 事件（v2 默认不发）。依赖"清空不触发 onChange"的逻辑要显式写 `clearContent(false)`。
- **`insertContent`** 在文档开头插入时不再拆分文本节点。依赖"插入后开头文本被拆开"行为的代码需要复核。

### 文本样式 API

`@tiptap/extension-text-style` 在 v3 扩容为文本样式家族的聚合点：

- 新增 `FontSize`、`LineHeight`、`BackgroundColor` 三个扩展，与既有的 `TextStyle`、`Color`、`FontFamily` 同包导出。
- 新增 `TextStyleKit`，一处配置整组文本样式扩展。
- `mergeNestedSpanStyles` 默认值改为 `true`：渲染 HTML 时嵌套的样式 span 会被合并，依赖嵌套 span 输出结构的代码需要复核。
- 新增 `toggleTextStyle` 命令。

家族成员的现行用法见[文本样式扩展](?path=/docs/text-style-extensions--docs)一课。

### NodeView 与 React 渲染

两处与渲染相关的行为变化：

- **NodeView 的 `getPos()` 可能返回 `undefined`**（节点尚未挂载等时机），直接拿来当数字用会出错：

```diff
  const pos = props.getPos();
- updatePos(pos);
+ if (pos !== undefined) {
+   updatePos(pos);
+ }
```

- **React 的 `shouldRerenderOnTransaction` 默认关闭**：v2 中每次事务都会重渲染使用编辑器的 React 组件，v3 不再自动重渲染。工具栏状态等依赖编辑器状态的 UI，改用 `useEditorState` 选择性订阅，或在 `onTransaction` 回调里手动更新状态。细节见 React 集成课程。

NodeView 的完整用法见[Node View 与 Mark View](?path=/docs/node-views--docs)一课。

### 移除项

| 移除项 | 处理方式 |
| --- | --- |
| UMD 构建 | 项目改用 ESM 引入（打包器 import 或 importmap）；依赖 `<script>` 全局变量的用法失效 |
| `editor.getCharacterCount()` | 改用 `editor.storage.characterCount.characters()`，可选 `{ node, mode }` 参数 |
| Placeholder 的 `considerAnyAsEmpty` 选项 | 删除该配置；空节点判定行为以现行文档为准 |

### StarterKit 变化

- v3 的 StarterKit 收编了 `Link`、`Underline`、`ListKeymap`（后续 3.x 又加入 `TrailingNode`）。升级时把单独安装的这些扩展移除，避免与 StarterKit 重复注册同名扩展。
- 撤销重做的配置键从 `history` 改名 `undoRedo`：

```diff
  StarterKit.configure({
-   history: false,
+   undoRedo: false,
  })
```

## 迁移步骤

官方升级指南给出五步顺序，每步对应清单中的小节，建议照序执行：

1. **更新依赖**：移除 UMD 用法；安装 `@floating-ui/dom`；把所有 `@tiptap/*` 包整组升到 v3，并按包映射表清理 `package.json` 里已合并/改名的旧包。
2. **更新菜单实现**：`tippyOptions` 改 `options`；框架组件 import 加 `/menus` 子路径。
3. **检查 NodeView**：为 `getPos()` 补 `undefined` 判断。
4. **更新扩展**：迁到 `@tiptap/extensions`；移除与 StarterKit 重复安装的扩展；更新文本样式配置。
5. **检查命令调用**：`setContent` 改新签名；确认 `clearContent` 默认发出 `update` 的影响。

升级完成后，v3 的新能力可以按需启用：

| 新能力 | 一句话 | 入口 |
| --- | --- | --- |
| MarkView | 像 NodeView 一样自定义标记的 DOM 渲染 | [Node View 与 Mark View](?path=/docs/node-views--docs) |
| 服务端 SSR | `element: null` 让编辑器实例在服务端 headless 运行 | [输出与静态渲染](?path=/docs/output-rendering--docs) |
| `@tiptap/static-renderer` | 无编辑器实例时输出 HTML / JSON / React / Vue | [输出与静态渲染](?path=/docs/output-rendering--docs) |
| Kit 聚合包 | `ListKit`、`TableKit`、`TextStyleKit` 一处配置一组扩展 | 结构扩展、文本样式扩展课 |
| `rewriteUnknownContent` | 把 JSON 内容里的未知节点/标记改写为编辑器可渲染的形式 | [内容与文档模型](?path=/docs/content-model--docs) |
| 其他改进 | `delete` 事件、节点与标记属性校验、事务处理性能优化 | whats-new 页 |

## 从其他编辑器迁移

从别的编辑器搬到 Tiptap 不是包替换，而是重建：官方为四个常见编辑器各有一份迁移指南，共用同一套评估框架。动手前先按存量内容定下评估结论：

| 原编辑器 | 存量内容格式 | 官方指南 |
| --- | --- | --- |
| CKEditor 5 | HTML | [migrate-from-ckeditor5](https://tiptap.dev/docs/guides/migrate-from-ckeditor5) |
| Slate | 自有 JSON | [migrate-from-slate](https://tiptap.dev/docs/guides/migrate-from-slate) |
| Quill | Delta JSON | [migrate-from-quill](https://tiptap.dev/docs/guides/migrate-from-quill) |
| Lexical | 自有 JSON | [migrate-from-lexical](https://tiptap.dev/docs/guides/migrate-from-lexical) |

评估沿三个视角展开：

- **内容模型**：存量内容是什么格式？HTML（CKEditor 5、Quill 输出侧）可以直接喂给 Tiptap 解析；Slate、Lexical 的自有 JSON 需要写一次性转换脚本。官方建议长期存储统一转成 Tiptap JSON（性能与可读性），格式细节见[内容与文档模型](?path=/docs/content-model--docs)一课。
- **扩展机制**：各家能力机制与 Tiptap 扩展系统一一对应——plugin / module / blot / node 映射为扩展，StarterKit 覆盖其中基础部分；自定义元素对应自定义扩展，复杂 UI 用 Node View。
- **UI 成本**：Tiptap 是 headless，原编辑器内置的工具栏要按命令链（`editor.chain().focus().toggleBold().run()`）加 `editor.isActive()` 状态自建；悬浮工具栏对应 BubbleMenu。做法见[菜单](?path=/docs/menus--docs)一课。

四份指南的迁移骨架也一致：安装 `@tiptap/core` + `@tiptap/starter-kit` → 转换存量内容 → 替换初始化代码 → 逐个映射插件 → 重建工具栏 → 验证内容兼容性。下面两个小节给出任务点名的两份指南的关键差异。

### CKEditor 5

CKEditor 5 与 Tiptap 同以 HTML 为内容载体，迁移成本低；差异集中在机制命名与 UI 归属：

| CKEditor 5 | Tiptap |
| --- | --- |
| Plugin（插件） | Extension（扩展） |
| 内置 Toolbar / Balloon UI | 自建菜单组件；Balloon 编辑器形态对应 BubbleMenu |
| HTML 输入输出 | HTML 可直接解析，存储建议转 Tiptap JSON |
| `Alignment` 插件 | `TextAlign` 扩展 |
| `FontColor` 插件 | `TextStyle` + `Color` 扩展（一个插件可能对应多个扩展） |

### Slate

Slate 与 Tiptap 都是框架无关的富文本框架，概念更接近，但内容格式与命令模型完全不同：

| Slate | Tiptap |
| --- | --- |
| 自有 JSON 文档结构 | Tiptap JSON；可用 `slate-html-serializer` 先转 HTML 过渡 |
| 手写 transform（`toggleMark` + `isMarkActive`） | 命令链 `editor.chain().focus().toggleBold().run()` + `editor.isActive('bold')` |
| `renderElement` 自定义元素 | 自定义 Node 扩展；复杂 UI 用 Node View（React 用 `ReactNodeViewRenderer`） |
| `renderLeaf` 行内标记 | Mark 扩展 |

## 常见问题

- **升级后报 `Cannot find package '@tiptap/extension-placeholder'`（或 history、bullet-list 等旧包名）。**
  按包映射表把 import 改到聚合包：功能扩展进 `@tiptap/extensions`（`History` 同时改名 `UndoRedo`），列表族进 `@tiptap/extension-list`，表格族进 `@tiptap/extension-table`；旧包从 `package.json` 卸载。
- **升级后菜单不再出现或定位错乱。**
  依次检查三处：`tippy.js` 是否还装着（应卸载）、`@floating-ui/dom` 是否已安装、框架组件 import 是否加了 `/menus` 子路径；同时把 `tippyOptions` 改成 `options`。
- **React 里工具栏按钮的加粗激活状态不再刷新。**
  v3 默认不随事务重渲染组件（`shouldRerenderOnTransaction` 关闭）。用 `useEditorState` 订阅需要的编辑器状态，或在 `onTransaction` 回调里手动更新，不要无脑打开全局重渲染。
- **升级后报 `editor.getCharacterCount is not a function`。**
  该方法已移除，改用 `editor.storage.characterCount.characters()`；`CharacterCount` 扩展从 `@tiptap/extensions` 引入。
- **从其他编辑器迁过来后，部分旧内容渲染不出来或结构缺失。**
  先确认存量格式：HTML 可直接解析，Slate/Lexical/Quill 的自有 JSON 必须先转换；转换后的内容对照 schema 逐个节点排查（做法见[内容与文档模型](?path=/docs/content-model--docs)一课），schema 无法表达的节点需要补自定义扩展，v3 的 `rewriteUnknownContent` 可辅助把未知节点改写为可渲染形式。

## 总结回顾

摘要：

v2 到 v3 的升级是一次以"包搬家"为主的机械变更：列表、表格、功能扩展三族包合并为聚合包，协作相关包改名，框架菜单组件移到 `/menus` 子路径；真正改变运行行为的只有三处——`setContent`/`clearContent` 的默认 `update` 行为与新签名、菜单定位从 tippy.js 换成 Floating UI（依赖、prop、import 三处联动）、React 默认不再随事务重渲染。加上 UMD 移除、`getCharacterCount` 移除和 StarterKit 的收编与配置键改名，构成完整的五步迁移顺序。从其他编辑器迁移则是另一类工作：CKEditor 5、Slate、Quill、Lexical 四份官方指南共用"内容模型、扩展机制、UI 成本"三个评估视角，HTML 类存量可直接解析，自有 JSON 类必须先转换，工具栏一律按命令链自建。

一句话：

> v2→v3 的破坏性变更九成是 import 替换，动逻辑的只有命令默认值、Floating UI 菜单和 React 渲染三处；换编辑器则先评估内容模型与扩展机制，再算 UI 重建成本。

知识要点：

- v2 的列表族、表格族、功能扩展包分别合并到了哪个包？哪两个包连同导出一起改了名？
- v3 中 `setContent`、`clearContent`、`insertContent` 的行为各有什么变化？
- 菜单从 tippy.js 迁到 Floating UI 要改哪三处？
- NodeView 的 `getPos()` 有什么新注意点？React 组件的默认重渲染策略变了吗？
- 哪些 API 在 v3 被移除，替代写法是什么？
- 官方五步迁移的顺序是什么？为什么 `@tiptap/*` 要整组一起升？
- 从其他编辑器迁移前要回答哪三个评估问题？不同编辑器的存量内容格式差异决定了什么？
