# 坐标与单位

three.js 的空间状态最终都落到四条相互独立的维度：**轴朝哪、单位多大、角度怎么算、相对谁**。右手坐标系回答“朝哪”，世界单位回答“多大”，弧度回答“角度用什么量”，局部空间与世界空间回答“相对谁”——四者各自独立，必须分开判断，再在 `renderer.render(scene, camera)` 时合到一起。

三条轴的约定固定且可观察：`+X` 向右、`+Y` 向上、`+Z` 朝向观察者（屏幕外）；右手大拇指沿任一轴，其余四指卷曲的方向就是该轴的正向旋转方向。three.js 内部统一使用弧度而不是度数，`position`、`rotation`、`scale` 都是相对父级的局部变换，需要换算到世界坐标时再走父级链。

## 快速上手

把下面的最小代码加进 `main.js`，刷新后会看到原点的三色坐标轴（红 X / 绿 Y / 蓝 Z）和一个放在 `(2, 0, 0)` 的立方体：

```js
import * as THREE from 'three';

const scene = new THREE.Scene();
scene.background = new THREE.Color('#edf3ef');

const camera = new THREE.PerspectiveCamera(50, 2, 0.1, 100);
camera.position.set(6, 5, 7);
camera.lookAt(0, 0, 0);

// 三条轴的颜色固定：X 红、Y 绿、Z 蓝。长度参数控制轴的可见范围。
scene.add(new THREE.AxesHelper(2.4));
scene.add(new THREE.GridHelper(10, 10));

const cube = new THREE.Mesh(
  new THREE.BoxGeometry(0.8, 0.8, 0.8),
  new THREE.MeshStandardMaterial({ color: '#3d73d9', roughness: 0.4 })
);
cube.position.set(2, 0, 0); // 沿 +X 放置，距离原点 2 个单位
scene.add(cube);

scene.add(new THREE.HemisphereLight('#ffffff', '#78908a', 0.9));
const key = new THREE.DirectionalLight('#ffffff', 2.1);
key.position.set(4, 6, 5);
scene.add(key);

const renderer = new THREE.WebGLRenderer({ antialias: true });
renderer.setSize(640, 320);
renderer.setAnimationLoop(() => renderer.render(scene, camera));
document.body.append(renderer.domElement);
```

| 概念或输入 | 取值 / 默认 | 改变后要注意什么 |
| --- | --- | --- |
| 坐标系 | 右手坐标系：`+X` 右、`+Y` 上、`+Z` 朝向观察者 | 切到其他引擎时要重新核对轴约定；OpenGL/WebGL 也是右手系，部分游戏引擎是左手系 |
| `AxesHelper(n)` | `n` 是轴的可见长度 | 三色固定（X 红、Y 绿、Z 蓝）；不会改变任何渲染结果，只是可视化 |
| 世界单位 | 无内置单位，`1` 就是 scene 内部的一个标量 | “1 米 / 1 厘米 / 1 像素”都是约定；模型与相机共享同一约定即可 |
| `PerspectiveCamera.fov` | 度数，常见 45–60 | 内部会换算为弧度参与投影矩阵；改它影响“近大远小”的强烈程度 |
| `rotation` / `Math.PI` | 弧度，`Math.PI / 2` 表示 90° | 写 `rotation.x = 45` 不会旋转 45 度，而是约 2578 弧度 |
| 局部 vs 世界 | `position` 是相对父级的局部值 | 同一 `(2, 0, 0)` 在不同父级下世界位置不同 |

## 右手坐标系

three.js 沿用 OpenGL / WebGL 的右手坐标系。把右手放在原点，大拇指指向 `+X`、食指指向 `+Y`，中指指向的就是 `+Z`——三条轴两两垂直。`AxesHelper` 用三色固定表达这个约定：红 = X、绿 = Y、蓝 = Z。

```js
const axes = new THREE.AxesHelper(2.4);
scene.add(axes);
// 红 = X、绿 = Y、蓝 = Z。三条轴都从原点向正方向延伸。
```

| 轴 | 颜色 | 方向（默认相机朝 -Z 时） |
| --- | --- | --- |
| `+X` | 红 | 屏幕右方 |
| `+Y` | 绿 | 屏幕上方 |
| `+Z` | 蓝 | 朝向观察者（屏幕外） |
| `-Z` | （反向） | 远离观察者，相机默认朝这里看 |

正向旋转用右手定则：大拇指沿轴正方向，四指卷曲方向就是角度增加的方向。例如 `rotation.y` 增大时，从上向下看（`+Y` 朝你），物体绕 Y 轴**逆时针**旋转。

先切到「前视」核对三色端点球：红在右、绿在上、蓝朝自己。再切到「俯视」，拖大 `rotation.y`，看橙色指针是否逆时针转。

## 单位与尺度

three.js 没有内置的物理单位。`position.set(2, 0, 0)` 中的 `2` 只是 scene 内部的标量，由相机视锥、模型尺寸和场景作者共同约定它代表什么——常见做法是把它当作“1 米”，但也可以是厘米、千米或像素。

把世界单位和屏幕像素分开看：

- **世界单位**：`position`、`scale`、`geometry` 的尺寸、相机的 `near/far` 都使用它。
- **屏幕像素**：由 `renderer.setSize()` 决定的 drawing buffer，再由 CSS 决定显示多大。

近大远小不是单位换算，而是透视相机的投影结果：相同世界尺寸的物体，离相机越远在画面里越小。要把一批物体一起放大看清楚，用 `Group.scale` 即可——相机不动时只是画面变大，并不改变“1 单位是几像素”：

```js
const group = new THREE.Group();
group.add(axes, cube);
scene.add(group);

group.scale.setScalar(2); // 整体放大；1 仍是场景标量，不是像素
```

## 角度与弧度

three.js 内部的 `rotation`、以及 `Math.atan2` 的返回值都用弧度。度数和弧度的换算通过 `MathUtils`：

```js
THREE.MathUtils.degToRad(90);  // ≈ 1.5708 = Math.PI / 2
THREE.MathUtils.radToDeg(Math.PI); // 180
```

常用对应：

| 度数 | 弧度表达式 | 近似值 |
| --- | --- | --- |
| 30° | `Math.PI / 6` | ≈ 0.524 |
| 45° | `Math.PI / 4` | ≈ 0.785 |
| 60° | `Math.PI / 3` | ≈ 1.047 |
| 90° | `Math.PI / 2` | ≈ 1.571 |
| 180° | `Math.PI` | ≈ 3.142 |
| 360° | `Math.PI * 2` | ≈ 6.283 |

注意 `PerspectiveCamera` 的 `fov` 接收的是度数；构造器内部会换算为弧度参与投影矩阵。需要直接用 `Math.cos` / `Math.sin` 等三角函数时，先确认传的是弧度。

实例默认俯视。先保持开关关闭，把意图角度调到 `90`：指针应对准 `-Z` 刻度。再打开「把度数直接写入 `rotation.y`」：同样写 `45` 会变成约 2578°，指针看起来像乱转。

## 局部空间与世界空间

`Object3D` 的 `position` / `rotation` / `scale` 都是相对**父级**的局部变换。同一个 `child.position.set(2, 0, 0)`，挂在场景根下时世界位置是 `(2, 0, 0)`；挂在已经平移到 `(1, 0, 0)` 的父级下时，世界位置变成 `(3, 0, 0)`；如果父级再绕 Y 轴转 90°，世界位置会落到另一方向。

```js
const parent = new THREE.Group();
parent.position.set(1, 0, 0);
parent.rotation.y = THREE.MathUtils.degToRad(90);
scene.add(parent);

const child = new THREE.Mesh(geometry, material);
child.position.set(2, 0, 0); // 局部值始终是 (2, 0, 0)
parent.add(child);

const world = child.getWorldPosition(new THREE.Vector3());
// world 大致等于 (1, 0, -2)：父级先转 90°，再平移 1。
```

读取世界结果前先确保相关矩阵已更新：

```js
child.updateWorldMatrix(true, false); // 先更新祖先链
child.getWorldPosition(worldPosition);
```

拖动父级平移或旋转：`child` 局部坐标保持 `(2, 0, 0)`，读数里的世界位置和 `matrixWorld` 平移会变；棕色辅助线始终连到立方体的世界位置。

## 最佳实践

- 新场景里先加一个 `AxesHelper` 和 `GridHelper`，三色和网格能立刻指出朝向错误，避免在相机和物体都未确认时反复改坐标。
- 在项目早期就确定“1 单位表示什么”（米、厘米或场景自定义单位），让模型尺寸、相机距离和 `near/far` 都按这套约定设定。
- 度数和弧度转换统一走 `THREE.MathUtils.degToRad` / `radToDeg`，避免在代码里散落 `* Math.PI / 180`。
- 需要世界坐标、世界方向时显式调用 `getWorldPosition` / `getWorldQuaternion`，并在读取前 `updateWorldMatrix(true, false)`；不要假设局部值就是世界值。
- 跨引擎或与设计工具（Blender、Unity、glTF）交换数据时，先确认对方的轴约定和单位；必要时在导入层做一次轴与单位的转换。

## 常见问题

- 为什么 `rotation.x = 45` 物体转得过多？
  `rotation` 使用弧度，`45` 弧度约等于 2578 度。改用 `THREE.MathUtils.degToRad(45)` 或直接写 `Math.PI / 4`。
- 为什么相机和物体都设置在 `(0, 0, 0)`，看不到画面？
  相机默认朝 `-Z` 看，与物体重合时位于物体内部。把相机移到 `+Z` 一侧（例如 `camera.position.z = 5`）即可。
- 为什么同一个 `position.set(2, 0, 0)`，物体最终位置不一样？
  `position` 是相对父级的局部值。检查对象挂在哪个父级下，必要时用 `getWorldPosition()` 读取世界坐标。
- 为什么从 Blender / Unity 导入后模型朝向不对？
  这些工具的轴或单位约定可能与 three.js 不同。先核对来源工具的上方向与单位，再用导入器或场景层的旋转 / 缩放做一次性校正。
- 为什么 `camera.fov = 60` 看起来比预期的角度小？
  `fov` 接收度数，不是弧度；确认它没有被先 `degToRad()` 一次后又当度数使用。
- 为什么 `scale = (2, 1, 1)` 后子对象位置看起来偏了？
  父级的非均匀缩放会影响后代位置和方向。读数对不上时先排查父级链是否带非均匀缩放。

## 总结回顾

摘要：

右手坐标系、世界单位、弧度和局部空间四条维度共同决定 three.js 的空间状态：三色 `AxesHelper` 固定表达 `+X` 右、`+Y` 上、`+Z` 朝向观察者；世界单位是场景内部标量，不绑定屏幕像素；角度统一用弧度，常用值通过 `Math.PI` 表达；`position` / `rotation` / `scale` 是相对父级的局部值，跨层级判断最终位置时必须显式读取世界坐标并确认矩阵已更新。

一句话：

> 在 three.js 里描述空间状态，始终把轴方向、世界单位、弧度和“相对哪个父级”这四件事分开判断，再合到一起。

知识要点：

- three.js 的三条轴分别指向哪里？怎样用 `AxesHelper` 和视角切换验证？
- 绕 `+Y` 增大 `rotation.y` 时，俯视下物体朝哪转？这对应什么定则？
- 世界单位与屏幕像素有什么关系？为什么不能把模型尺寸直接写成像素？
- `rotation` 接收的是度数还是弧度？怎样在两者之间换算？
- 同一个 `position.set(2, 0, 0)` 在不同父级下世界位置为什么会不同？
- 读取 `getWorldPosition()` 之前为什么要先更新世界矩阵？
- 切换到其他引擎或导入设计工具数据时，最先要核对哪两件事？
