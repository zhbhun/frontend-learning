# TransformControls

`TransformControls` 在场景里渲染一个变换 gizmo，让你（或编辑器用户）用鼠标直接拖动 `Object3D` 的 `position`、`rotation`、`scale`——也就是 [Object3D](?path=/docs/object3d-transform-hierarchy--docs) 那三项局部 TRS。它改的是对象，不是相机；相机控制器（[相机控制器](?path=/docs/camera-controls--docs)）改的才是相机。

它和拾取（[拾取](?path=/docs/raycaster-pointer-interaction--docs)）配合形成编辑器的基本工作流：先用 `Raycaster` 点击选中一个对象，再 `attach()` 到 `TransformControls` 上，gizmo 出现，拖动 gizmo 即可变换对象。三件事必须分清：选哪个对象由应用的 `Raycaster` 决定，TransformControls 的内部 raycaster 只用来识别“指针压在了 gizmo 的哪条轴上”；变换的是 `attach()` 进来的对象，不是相机；gizmo 拖动期间必须暂停相机控制器，否则两者会抢同一组指针输入。

r165 起 `TransformControls` 不再继承 `Object3D`，自身不能 `add` 进场景。0.185.1 中要用 `transform.getHelper()` 取得 helper（一个 `Object3D`），再把它加入场景；旧教程里 `scene.add(transformControls)` 的写法已经失效。

## 快速上手

最小闭环：构造时传入相机和画布，取得 helper 加入场景，`attach()` 一个对象，监听 `dragging-changed` 暂停 OrbitControls，监听 `change` 按需重渲。

```js
import { OrbitControls } from 'three/addons/controls/OrbitControls.js';
import { TransformControls } from 'three/addons/controls/TransformControls.js';

const orbit = new OrbitControls(camera, renderer.domElement);
orbit.target.set(0, 0.8, 0);
orbit.update();

const transform = new TransformControls(camera, renderer.domElement);
// r165+ 必须用 getHelper() 拿到可加入场景的对象，不能直接 add(transform)。
scene.add(transform.getHelper());

// 拖动 gizmo 期间禁用相机控制器，避免两者同时响应同一组指针输入。
transform.addEventListener('dragging-changed', (event) => {
  orbit.enabled = !event.value;
});

// 没有动画循环时，按 change 事件按需重渲即可。
transform.addEventListener('change', () => renderer.render(scene, camera));

transform.attach(selectedMesh);
```

选中 `selectedMesh` 通常用一次 Raycaster 命中测试完成，详见本课“与 Raycaster 配合”一节。

| 输入或状态 | 默认值 | 改变后要注意什么 |
| --- | --- | --- |
| `new TransformControls(camera, domElement)` | `domElement` 默认 `null` | 传入 `renderer.domElement` 才会注册指针监听；不传要手动 `connect()` |
| `getHelper()` | 返回内部 `TransformControlsRoot` | r165+ 唯一可加入场景的对象；不要 `scene.add(transform)` |
| `.attach(object)` / `.detach()` | 未绑定 | `attach` 使 helper 可见；`detach` 隐藏 helper 并清空选中 |
| `.mode` | `'translate'` | `'translate' \| 'rotate' \| 'scale'`；改变后 gizmo 切换形态 |
| `.space` | `'world'` | `'world'` 沿世界轴；`'local'` 沿对象自身朝向 |
| `.size` | `1` | gizmo 的视觉尺寸，不影响变换幅度 |
| `.translationSnap` / `.rotationSnap` / `.scaleSnap` | `null` | 设为数值后按该步长吸附 |
| `.enabled` | `true` | `false` 停止响应指针，但保留监听 |
| `dragging-changed` 事件 | `event.value: boolean` | 拖动开始/结束触发；用来切换 OrbitControls |
| `change` 事件 | — | 模式、空间、拖动、选中对象变化都会触发 |
| `.dispose()` | 不会自动调用 | 卸载时调用以移除 DOM 监听并释放 gizmo 几何与材质 |

## 三种模式与坐标空间

`mode` 决定 gizmo 形态和改写的属性：`translate` 改 `position`、`rotate` 改 `rotation`/`quaternion`、`scale` 改 `scale`——正是 [Object3D](?path=/docs/object3d-transform-hierarchy--docs) 的三项局部 TRS。`space` 决定 gizmo 朝向：`'world'` 时 gizmo 三轴永远与世界坐标轴对齐；`'local'` 时 gizmo 跟随对象自身的旋转。

```js
transform.setMode('rotate');   // translate | rotate | scale
transform.setSpace('local');   // world | local
transform.setSize(1.2);
transform.setTranslationSnap(0.5);
transform.setRotationSnap(Math.PI / 12); // 15°
```

旋转和缩放在 `'local'` 空间下表现最直观；平移在 `'world'` 空间下更适合“沿屏幕方向拖动”。两者切换不会改变对象已有变换，只改变后续拖动的参照系。

在范例里点击任一物体选中它，再用参数面板切换 `模式`、`空间` 和 `gizmo 大小`：gizmo 形态与朝向随之改变，读数里的 `position` / `rotation` / `scale` 实时反映拖动结果。

## 与 OrbitControls 协调

`OrbitControls` 和 `TransformControls` 默认都监听同一个 `renderer.domElement`。如果不加协调，拖动 gizmo 时相机也会同时转动。标准解法是监听 `dragging-changed`：拖动开始时 `orbit.enabled = false`，结束时恢复。

```js
transform.addEventListener('dragging-changed', (event) => {
  orbit.enabled = !event.value;
});
```

`event.value` 是 `true`/`false`，分别表示拖动开始和结束。这个事件由 `dragging` 属性的 setter 触发——`TransformControls` 用一套统一的属性 setter 派发事件，每个属性变化都会发出 `<name>-changed` 和一个总的 `change`（见下一节）。

为什么不能在 `pointerdown` 里直接关 OrbitControls？因为点击是否命中 gizmo 要等控制器内部的 hover 检测决定，只有真的开始拖动才需要暂停相机；点击空白或物体本体时，输入应交给相机或选区逻辑。范例参数面板里的 `拖动时禁用 OrbitControls` 开关可以关掉这座桥，关掉后能直接观察到拖动 gizmo 时相机同时转动的冲突现象。

`TransformControls` 自身的 `pointerHover` 只在 `pointerType` 为 `mouse` 或 `pen` 时调用；触摸设备没有 hover，第一次 `pointerdown` 才会确定 axis。因此触摸交互在“按下时判定轴”，而鼠标可以悬停预选轴。

## 与 Raycaster 配合

`TransformControls` 的内部 `Raycaster`（可通过 `getRaycaster()` 取到，注意它是**所有实例共享**的模块级对象）只用来识别 gizmo 轴，不会选中场景里的物体。“点击哪个对象”由应用层决定，典型流程是一次 Raycaster 命中测试：

```js
const raycaster = new THREE.Raycaster();
const pointer = new THREE.Vector2();

canvas.addEventListener('pointerdown', (event) => {
  if (event.button !== 0 || transform.axis !== null) return;

  const rect = canvas.getBoundingClientRect();
  pointer.x = ((event.clientX - rect.left) / rect.width) * 2 - 1;
  pointer.y = -((event.clientY - rect.top) / rect.height) * 2 + 1;
  raycaster.setFromCamera(pointer, camera);
  const hits = raycaster.intersectObjects(pickable, false);

  if (hits.length > 0) {
    transform.attach(hits[0].object);
  } else {
    transform.detach();
  }
});
```

`transform.axis !== null` 的判断很重要：当指针正压在 gizmo 轴上时，应交给 `TransformControls` 处理拖动，不再做选区命中，避免一次按下既选对象又拖 gizmo。`pickable` 是应用维护的“可被选中和变换的物体”清单，通常排除 helper、gizmo、网格和地面。需要按 `layers` 过滤命中时配置应用自己的 Raycaster，不要改 `getRaycaster()` 返回的共享对象。

`attach()` 要求对象已经是场景图的一部分（`object.parent` 不为 `null`），否则 `updateMatrixWorld` 阶段会报 `The attached 3D object must be a part of the scene graph.`。新创建还未 `add` 到场景的对象要先挂载再 `attach`。

## 事件与按需渲染

`TransformControls` 把 `mode`、`space`、`size`、`dragging`、`object`、`axis` 等属性都通过同一个 setter 机制定义：每次赋值只要值变化，就派发 `<属性名>-changed`（带 `event.value`）和统一的 `change`。所以监听 `change` 就能覆盖“gizmo 因任何原因需要重画”的所有情况。

```js
transform.addEventListener('change', () => renderer.render(scene, camera));
transform.addEventListener('objectChange', () => updateInspector());
transform.addEventListener('dragging-changed', (event) => {
  orbit.enabled = !event.value;
});
```

| 事件 | 触发时机 | 典型用途 |
| --- | --- | --- |
| `change` | 任何属性变化、拖动每一帧、模式/空间切换 | 触发按需渲染 |
| `dragging-changed` | 拖动开始 / 结束（`event.value`） | 暂停 / 恢复 OrbitControls |
| `mouseDown` / `mouseUp` | gizmo 上按下 / 松开（`event.mode` 是当前模式） | 记录变换起点、提交撤销栈 |
| `objectChange` | 拖动改写了对象 TRS | 同步属性面板、序列化场景 |
| `object-changed` | `attach` / `detach` 切换选中对象 | 切换属性面板目标 |

没有连续动画的场景用 `change` 驱动按需渲染最省；有动画循环的场景继续用 `setAnimationLoop`，`change` 可省略。无论哪种，页面隐藏、Canvas 离屏或组件卸载时都要暂停循环并调用 `dispose()`。

## 加入场景与生命周期

r165 之前 `TransformControls` 直接继承 `Object3D`，`scene.add(controls)` 即可生效；之后它改为继承 `Controls`，自身不再是 `Object3D`，必须通过 `getHelper()` 取得内部的 `TransformControlsRoot`（一个 `Object3D` 子类）再加入场景。0.185.1 沿用新结构：

```js
const transform = new TransformControls(camera, renderer.domElement);
scene.add(transform.getHelper());
```

`TransformControlsRoot` 在 `updateMatrixWorld` 里会抵消父级变换，使 gizmo 始终对齐世界坐标并出现在选中对象的世界位置；因此把它直接挂在 `Scene` 下，或嵌套在某个 `Group` 下，视觉效果一致。`attach()` 会把 helper 的 `visible` 设为 `true`，`detach()` 设为 `false`，所以“有没有选中对象”直接决定 gizmo 是否绘制。

生命周期上，它和其它控制器一样继承 `Controls`：`connect(domElement)` / `disconnect()` 管理 DOM 监听，`dispose()` 结束使用。卸载流程要把 TransformControls、OrbitControls、渲染循环和应用自己注册的选区监听放在一起清理：

```js
function unmount() {
  transform.dispose();
  orbit.dispose();
  renderer.setAnimationLoop(null);
}
```

`dispose()` 内部会调用 `disconnect()` 并释放 gizmo 的几何与材质，所以不需要再单独 `scene.remove(transform.getHelper())`，除非你想在仍保留控制器实例的前提下临时隐藏 gizmo——这种情况用 `transform.detach()` 或 `transform.getHelper().visible = false`。

## 属性与回查

`TransformControls` 的可配置项远不止模式与空间。下表覆盖核心公开属性，便于回查：

| 属性 | 默认值 | 作用与边界 |
| --- | --- | --- |
| `camera` | 构造时传入 | 变换参照相机；切换相机用 `transform.camera = nextCamera` |
| `object` | `undefined` | 当前 `attach` 的对象；只读语义，用 `attach()` / `detach()` 改 |
| `mode` | `'translate'` | `'translate' \| 'rotate' \| 'scale'` |
| `space` | `'world'` | `'world' \| 'local'` |
| `size` | `1` | gizmo 视觉尺寸 |
| `enabled` | `true` | `false` 停止响应指针 |
| `axis` | `null` | 当前悬停/拖动的轴，只读 |
| `dragging` | `false` | 是否正在拖动，只读 |
| `translationSnap` / `rotationSnap` / `scaleSnap` | `null` | 数值步长；`null` 不吸附 |
| `showX` / `showY` / `showZ` | `true` | 隐藏单条轴的 gizmo |
| `showXY` / `showYZ` / `showXZ` | `true` | 平移模式的平面提示 |
| `showXYZE` / `showE` | `true` | 旋转模式的整体球与眼轴 |
| `minX` / `maxX` / `minY` / `maxY` / `minZ` / `maxZ` | `±Infinity` | 平移范围限制 |
| `viewport` | `null` | 子画布视口（逻辑像素，原点在左下）；`null` 使用整张画布 |

常用方法：`setMode()`、`setSpace()`、`setSize()`、`setTranslationSnap()`、`setRotationSnap()`、`setScaleSnap()`、`setColors(x, y, z, active)`、`reset()`（撤销本次拖动）、`getMode()`、`getRaycaster()`、`getHelper()`、`attach()`、`detach()`、`dispose()`。

`reset()` 只在 `dragging` 为 `true` 时有效，把对象恢复到本次拖动开始时的 TRS，常配合“撤销”按钮。`setColors()` 一次设置 X/Y/Z 轴和激活色；颜色改变不会派发 `change` 之外的事件。`getRaycaster()` 返回的是模块级共享对象，不要配置它的 `layers` 或 `firstHitOnly` 来做应用层选区——用应用自己的 `Raycaster`。

## 最佳实践

- 先用应用自己的 `Raycaster` 决定选哪个对象，再 `attach()`；不要让 TransformControls 承担选区职责。
- 始终监听 `dragging-changed` 暂停 OrbitControls，这是同 DOM 元素下两个控制器共存的最小必要协调。
- 把 `getHelper()` 的返回值加入场景，不要 `add(transform)` 本身；旧写法在 0.185.1 静默失效。
- 按需渲染用 `change`，连续动画场景用 `setAnimationLoop`；不要两边都驱动同一帧。
- 限定 `pickable` 清单，把 helper、gizmo、网格和地面排除在选区之外，避免点中不可见或不可变换的对象。
- 卸载时把 TransformControls、OrbitControls、渲染循环和选区监听一起 `dispose()`。
- 需要撤销时在 `mouseDown` 存 TRS 快照、`mouseUp` 提交；不要每帧序列化。

## 常见问题

- 为什么 `scene.add(transformControls)` 后 gizmo 不显示？
  r165 起 `TransformControls` 不再是 `Object3D`；0.185.1 必须用 `scene.add(transformControls.getHelper())`。
- 为什么拖动 gizmo 时相机也在转？
  没有监听 `dragging-changed` 暂停 OrbitControls。加上 `transform.addEventListener('dragging-changed', e => orbit.enabled = !e.value)`。
- 为什么点击物体没反应，但 gizmo 拖动正常？
  TransformControls 的内部 raycaster 只识别 gizmo 轴，不会选中场景物体；要由应用的 `Raycaster` 做 `intersectObjects` 并 `attach()` 命中对象。
- 为什么 `attach(obj)` 后控制台报 `must be a part of the scene graph`？
  被绑定的对象 `parent` 为 `null`；先把对象 `add` 进场景再 `attach`。
- 为什么换相机后 gizmo 方向对不上？
  `transform.camera` 仍指向旧相机；用 `transform.camera = newCamera` 同步，或在 `setCamera()` 类应用层封装里同时改 OrbitControls 的相机。
- 为什么触摸设备上 gizmo 第一次按下不亮？
  触摸没有 hover，`axis` 在 `pointerdown` 才确定；这是 TransformControls 的预期行为，不是 bug。
- 为什么吸附步长设了却没生效？
  `translationSnap` / `rotationSnap` / `scaleSnap` 为 `null` 时不吸附；设为正数值（旋转用弧度）后才按步长吸附，且仅对当前 `mode` 生效。

## 总结回顾

摘要：

`TransformControls` 用一个 gizmo 让鼠标直接改写对象的 TRS，和改相机的 OrbitControls、决定选中对象的 Raycaster 三者协作构成编辑器交互。模式、空间、吸附和尺寸控制 gizmo 形态与拖动参照；`dragging-changed` 用来暂停相机控制器，`change` 用来按需渲染。r165 之后必须通过 `getHelper()` 把 helper 加入场景，旧式 `scene.add(controls)` 已失效。

一句话：

> TransformControls 改对象不改相机，用 Raycaster 选对象、用 dragging-changed 让 OrbitControls 让路、用 getHelper() 把 gizmo 挂进场景。

知识要点：

- TransformControls 改的是对象的哪三项属性？它和 OrbitControls、Raycaster 各负责什么？
- r165+ 把 TransformControls 加入场景的正确方式是什么？为什么不能直接 `scene.add(controls)`？
- 拖动 gizmo 时怎样避免相机同时跟随？
- 点击选中对象的流程由谁负责？为什么不复用 `getRaycaster()`？
- `mode`、`space`、`size`、各类 snap 分别影响什么？
- `change` 和 `dragging-changed` 事件分别在何时触发，各适合做什么？
