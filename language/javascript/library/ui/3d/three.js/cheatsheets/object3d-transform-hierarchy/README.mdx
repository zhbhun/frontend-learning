# Object3D

`Object3D` 是 three.js 场景树中大多数对象的共同基类。`Mesh`、`Camera`、`Light`、`Group` 都沿用它的变换和层级规则：`position`、`rotation` / `quaternion`、`scale` 描述对象相对父级的局部变换，父级的世界矩阵再与它相乘，得到最终的 `matrixWorld`。

因此同一个 `child.position` 不足以说明物体最终在哪里。要先看它挂在哪个父级下，再看父级链的平移、旋转和缩放；需要把对象从一个局部空间搬到另一个局部空间时，还要明确是保留局部值，还是保留世界外观。

## 快速上手

创建父子层级后，只需变换父级就能整体移动所有后代：

```js
const rig = new THREE.Group();
const mesh = new THREE.Mesh(geometry, material);

mesh.position.set(2, 0, 0); // 相对 rig 的局部位置
rig.add(mesh);
scene.add(rig);

rig.position.set(0, 1, 0);
rig.rotation.y = Math.PI / 4;

const worldPosition = mesh.getWorldPosition(new THREE.Vector3());
```

| 输入或状态 | 默认值 | 改变后要注意什么 |
| --- | --- | --- |
| `position` | `(0, 0, 0)` | 局部平移，受全部父级变换影响 |
| `rotation` / `quaternion` | 欧拉角 `(0, 0, 0, 'XYZ')` / 单位四元数 | 两者保持同步；角度 API 使用弧度 |
| `scale` | `(1, 1, 1)` | 会影响后代的位置、尺寸和方向；非均匀缩放限制部分 `lookAt()` / `attach()` 场景 |
| `pivot` | `null` | 设置后，当前对象的旋转和缩放围绕该局部点进行；位置本身不绕 pivot 平移 |
| `matrixAutoUpdate` | `true` | 为 `false` 时改 TRS 后需调用 `updateMatrix()` |
| `matrixWorldAutoUpdate` | `true` | 为 `false` 时应用需直接管理 `matrixWorld` |
| `visible` / `frustumCulled` | `true` / `true` | 前者隐藏整棵可见子树；后者决定是否参加视锥体剔除 |

## 局部变换与世界变换

局部矩阵由平移、旋转、缩放和可选 `pivot` 组合；世界矩阵把祖先矩阵依次乘进来。读取世界结果前，先确保相关矩阵已经更新。

```js
object.updateWorldMatrix(true, false);
object.getWorldPosition(worldPosition);
object.getWorldQuaternion(worldQuaternion);
object.getWorldScale(worldScale);
```

调整父级旋转、缩放和子级局部 X，核对两个坐标读数。然后关闭 `matrixAutoUpdate` 与“手动调用 `updateMatrix()`”，属性会变化，而画面和世界矩阵保留上一次已提交结果。

## 父子层级

一个对象同时最多有一个 `parent`。`parent.add(child)` 会先把 `child` 从旧父级移除，再把它加入新父级；这会保留局部 TRS 数值，因此世界位置通常会改变。`parent.attach(child)` 则先换算局部变换，尽量保持世界外观。

```js
newParent.add(child);    // 保留局部值，世界外观可能跳变
newParent.attach(child); // 保留世界变换，重算局部值

child.removeFromParent();
parent.clear();
```

`attach()` 不支持层级中存在非均匀缩放的情况。需要跨这种层级重挂时，先消除非均匀缩放，或显式保存世界矩阵并自行分解到新父级空间。

| 方法 | 解决的问题 | 边界 |
| --- | --- | --- |
| `add(...objects)` / `remove(...objects)` | 建立或拆除直接父子关系 | 触发 `added` / `removed` 及父级对应事件 |
| `attach(object)` | 换父级但保持世界变换 | 非均匀缩放层级不受支持 |
| `traverse(callback)` | 深度优先访问自身与全部后代 | 遍历中不要修改场景树 |
| `traverseVisible(callback)` | 只访问可见分支 | 父级不可见时跳过整棵后代 |
| `getObjectByName()` / `getObjectByProperty()` | 在子树中查找首个匹配对象 | `name` 由应用维护，不保证唯一 |

## 坐标转换

`localToWorld()` 与 `worldToLocal()` 会原地修改传入的向量。它们适合把挂点、碰撞位置或标注坐标跨空间传递；不要忘记先更新世界矩阵，也不要复用仍需保留的原始向量。

```js
object.updateWorldMatrix(true, false);

const worldPoint = object.localToWorld(localPoint.clone());
const localAgain = object.worldToLocal(worldPoint.clone());
```

沿对象自身轴移动或旋转可使用 `translateX/Y/Z()`、`translateOnAxis()`、`rotateX/Y/Z()` 与 `rotateOnAxis()`；`rotateOnWorldAxis()` 使用世界轴，但不支持带旋转父级的通用情况。`lookAt()` 接收世界坐标目标，普通 `Object3D` 的正向是局部 `+Z`，相机和光源采用各自的观察方向约定。

## 矩阵更新

自动模式下，renderer 每帧从 TRS 更新局部矩阵并沿场景树计算世界矩阵。手动模式常用于确定不再变化的对象，但关闭开关本身不会替你提交当前状态：

```js
object.matrixAutoUpdate = false;
object.position.set(3, 0, 0);
object.updateMatrix();
object.updateMatrixWorld(true);
```

| 成员 | 用途 | 使用判断 |
| --- | --- | --- |
| `updateMatrix()` | 用 TRS 与 `pivot` 重建 `matrix` | `matrixAutoUpdate = false` 后每次改局部状态都调用 |
| `updateMatrixWorld(force)` | 从当前节点向后代更新世界矩阵 | 已知祖先状态正确时使用 |
| `updateWorldMatrix(updateParents, updateChildren, force)` | 可选择先更新祖先或再更新后代 | 读取某个深层节点世界结果时更精确 |
| `matrixWorldNeedsUpdate` | 请求下一次更新重算世界矩阵 | 默认 `false`；直接改矩阵时由应用置位 |
| `applyMatrix4()` | 把矩阵乘到对象并分解回 TRS | 分解受非均匀缩放与旋转组合限制 |

`static` 默认是 `false`，目前只与 `WebGPURenderer` 的静态对象优化有关；它不是 WebGL 场景中关闭矩阵更新的替代品。

## 共享状态与生命周期

`name`、`userData`、`layers`、`renderOrder`、`castShadow`、`receiveShadow` 与回调钩子都由 `Object3D` 提供。它们控制查找、业务元数据、相机/射线可见层、排序和渲染阶段行为，但不会改变几何数据。

`clone(true)` 和 `copy(source, true)` 默认递归复制后代；几何与材质等由具体子类决定是否共享。`toJSON()` 用于序列化，`onBeforeRender` / `onAfterRender` 只对可渲染对象执行，普通空 `Object3D` 不会因为设置回调就产生 draw call。

## 最佳实践

- 把局部状态与世界状态写进变量名，例如 `localOffset`、`worldTarget`，跨空间前显式转换。
- 用父级表示真实的整体关系，不用每帧手工把同一增量加到一组对象。
- 读取世界坐标前用 `updateWorldMatrix(true, false)` 保证祖先链有效。
- 只有静态规模足够大且性能分析证明矩阵更新有成本时，才关闭自动更新。
- 需要换父级时先决定保留局部值还是世界外观，再选 `add()` 或 `attach()`。
- 不把函数放进 `userData`；该对象需要能够安全序列化和克隆。

## 常见问题

- 为什么 `position` 数值正确，画面中的位置却不对？
  `position` 默认是相对父级的局部坐标；检查 `parent` 及祖先的变换，必要时用 `getWorldPosition()` 读取世界坐标。
- 为什么改了属性，世界坐标却没有变化？
  如果关闭了 `matrixAutoUpdate`，修改 TRS 后先调用 `updateMatrix()`，再调用 `updateWorldMatrix()` 或 `updateMatrixWorld()` 更新祖先链。
- 为什么换父级后对象突然跳走？
  `add()` 保留局部变换；如果要尽量保持对象当前的世界外观，使用 `parent.attach(object)`，并确认父级没有不支持的非均匀缩放。
- 为什么 `lookAt()` 的方向不对？
  检查对象或祖先是否存在非均匀缩放；`lookAt()` 不支持位于这类父级下的对象，必要时移除该缩放或直接设置 quaternion。
- 为什么设置了 `castShadow` 仍然没有阴影？
  同时确认 renderer 开启阴影、光源支持阴影、对象位于光源视锥内，并且场景中有设置 `receiveShadow` 的接收物；`castShadow` 只是其中一个开关。

## 总结回顾

摘要：

Object3D 用局部 TRS、可选 pivot 和矩阵描述自身变换，再通过单一父级把祖先变换传给后代。自动矩阵更新适合常规场景；关闭后应用必须显式提交局部矩阵并更新世界链。跨层级操作还要先决定保留局部值还是世界外观。

一句话：

> 判断一个 Object3D 的最终状态时，始终把局部变换、父级链和矩阵生效时机一起看。

知识要点：

- 局部 `position` 怎样经过父级链形成世界位置？
- `add()` 与 `attach()` 在重挂对象时分别保留什么？
- 关闭 `matrixAutoUpdate` 后哪些更新步骤由应用接管？
- 怎样在局部坐标和世界坐标之间安全转换？
