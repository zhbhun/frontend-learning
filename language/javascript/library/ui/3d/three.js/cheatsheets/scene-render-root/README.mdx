# Scene

`Scene` 是交给 renderer 的场景根容器。它继承 `Object3D`，所以能拥有子对象与变换；同时又保存本次场景渲染共享的背景、环境光照、雾和材质覆盖。`renderer.render(scene, camera)` 从这个根开始遍历可见对象，再结合相机决定最终画面。

背景只填充没有物体覆盖的像素，`environment` 为物理材质提供间接光照和反射，`fog` 按深度混合物体颜色，`overrideMaterial` 临时替换可覆盖对象的材质。这四项是独立控制维度，不要把“看起来更亮”“远处变淡”和“换材质”混成一个效果。

## 快速上手

把可渲染对象挂进 Scene，再设置背景和线性雾：

```js
const scene = new THREE.Scene();
scene.background = new THREE.Color('#dbe8e1');
scene.fog = new THREE.Fog('#dbe8e1', 6, 22);

scene.add(mesh, light);
renderer.render(scene, camera);
```

| 输入或状态 | 默认值 | 改变后要注意什么 |
| --- | --- | --- |
| `background` | `null` | 可设 `Color`、`Texture`、`CubeTexture` 或 WebGL render target texture；不照亮物体 |
| `environment` | `null` | 影响物理材质的环境光；不会自动成为背景 |
| `fog` | `null` | 使用 `Fog` 或 `FogExp2`；材质的 `fog` 需允许参与 |
| `overrideMaterial` | `null` | 非空时替换场景内允许覆盖的材质；`material.allowOverride=false` 可排除 |
| `backgroundBlurriness` | `0` | 只影响兼容的环境背景纹理，不影响纯色 |
| `backgroundIntensity` / `environmentIntensity` | `1` / `1` | 分别缩放背景纹理与环境光，不互相代替 |

## 场景根容器

Scene 的 `children` 只列直属对象，后代仍由 Object3D 层级管理。把一个 Group 加入 Scene，就会连同它的可见后代一起进入遍历；从 Scene 移除 Group，整棵子树都退出当前渲染入口。

```js
const root = new THREE.Group();
root.add(body, label);
scene.add(root);

scene.traverse((object) => {
  console.log(object.type, object.name);
});
```

相机不一定要加入 Scene：只要把它作为第二个参数传给 `renderer.render()` 就能使用。需要相机继承父级变换、用 helper 观察或统一管理时，再挂入场景树。

## 背景与环境

`background` 负责画布底色或背景贴图；`environment` 只为支持环境光的材质提供全局 `envMap`。同一张处理过的环境纹理可以同时赋给两者，但这仍是两次独立选择。

```js
scene.background = environmentTexture;
scene.environment = environmentTexture;
scene.backgroundIntensity = 0.8;
scene.environmentIntensity = 1.2;
```

| 成员 | 生效对象 | 边界 |
| --- | --- | --- |
| `backgroundRotation` | 环境背景纹理 | 不改变对象材质中的反射方向 |
| `environmentRotation` | 物理材质使用的全局环境 | 不旋转背景 |
| `backgroundBlurriness` | 兼容的 equirectangular / cube 背景 | 取值通常为 `0` 到 `1`；纯色无效 |
| 材质自身 `envMap` | 单个材质 | 优先于 Scene 的全局 `environment` |

背景与环境贴图的加载、color space 和 PMREM 处理留到 [纹理](?path=/docs/textures-and-maps--docs) 与 [PBR](?path=/docs/pbr-and-environment-maps--docs)。

## 雾

`Fog` 在 `near` 之前不混合，随后线性增加，到 `far` 完全变成雾色；`FogExp2` 从相机开始按密度指数增长。两者都不是体积光，也不会在空白处画出雾团，只会参与支持雾的材质着色。

调整背景、雾类型和参数，观察远处物体怎样融入背景。再切换 `overrideMaterial`，橙色球因为 `allowOverride=false` 保留原材质。

## 材质覆盖

`overrideMaterial` 适合深度、法线、遮罩或调试通道：renderer 遍历对象仍使用原几何和变换，但把允许覆盖的材质统一替换。

```js
scene.overrideMaterial = new THREE.MeshNormalMaterial();
renderer.render(scene, camera);
scene.overrideMaterial = null;
```

若某个材质必须保留，设置 `material.allowOverride = false`。覆盖是 Scene 状态，临时渲染后要恢复；否则下一帧和其他相机也会继续使用覆盖材质。

## 最佳实践

- 用一个 Scene 表示一次明确的渲染根，不把 Scene 嵌套当作普通 Group 使用。
- 背景、环境光与雾分别调试；相同颜色不代表它们是同一机制。
- Fog 颜色通常从背景主色开始，再根据美术目标调整，避免远处对象出现硬边。
- 临时设置 `overrideMaterial` 时使用 `try/finally` 或集中渲染函数恢复旧值。
- 环境纹理只加载和预处理一次，在多个材质间通过 Scene 共享。
- 清理场景时遍历并 dispose 几何、材质与纹理；`scene.clear()` 只解除子对象关系，不释放 GPU 资源。

## 常见问题

- 为什么 `scene.add()` 之后仍然看不到对象？
  Scene 只负责让对象进入场景树；继续检查相机是否看得到对象、对象是否被裁剪，以及材质和光照是否能让它显示。
- 为什么设置了背景，物体仍然很暗？
  `scene.background` 只负责背景像素，不会提供照明；需要添加 Light，或设置可用于照明的 `scene.environment`。
- 为什么设置了 `scene.environment`，画布底色却没有变化？
  `environment` 主要参与材质的环境光照；如果想改变画布底色，另外设置 `scene.background`。
- 为什么雾没有效果？
  检查对象与相机的距离、Fog 的范围，以及材质是否启用雾；对象距离没有进入雾的范围时，画面不会出现明显变化。
- 为什么临时设置 `overrideMaterial` 后，后续渲染一直使用法线材质？
  临时覆盖后恢复原值，最好用 `try/finally` 保证 `scene.overrideMaterial` 最终恢复为旧材质或 `null`。
- 为什么 `scene.clear()` 之后显存仍然没有下降？
  `clear()` 只移除场景树中的对象；确认资源不再被使用后，还要分别对 geometry、material 和 texture 调用 `dispose()`。

## 总结回顾

摘要：

Scene 既是 Object3D 场景树的根，也是一次渲染共享状态的容器。renderer 从它遍历对象，而 background、environment、fog 与 overrideMaterial 分别控制背景像素、环境光照、深度混合和临时材质替换；这些状态相互独立，并且移除对象不等于释放资源。

一句话：

> 把 Scene 当作渲染根，并分别管理对象树、背景、环境、雾和材质覆盖。

知识要点：

- Scene 作为根容器与普通 Group 的职责有什么不同？
- background 与 environment 分别影响哪部分结果？
- `Fog` 和 `FogExp2` 怎样根据深度产生不同过渡？
- 为什么 `scene.clear()` 不能替代资源释放？
