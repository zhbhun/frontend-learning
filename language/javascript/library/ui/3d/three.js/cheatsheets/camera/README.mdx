# 相机

相机是 three.js 场景的观察者。`renderer.render(scene, camera)` 每一帧都要传入它，由它决定这一帧画出什么。

它只负责三件事：从哪里看、能看见多大范围、看见的东西落在 canvas 的哪个位置。场景里的对象不会因为相机移动而改变，改变的只是它们被投到屏幕上的结果。

鼠标拖拽、滚轮缩放这类交互不在本课范围，见「相机控制器」。

相机把一帧画面分成两段互相独立的工作：

```text
相机变换  position / rotation / lookAt
  决定从哪里、朝哪个方向看
        ↓
视锥体  fov / aspect / near / far
  框出一块空间，只有落在里面的对象参与渲染
        ↓
投影矩阵  projectionMatrix
  把视锥体里的空间压成屏幕标准区间
        ↓
canvas 像素
  由 renderer 的尺寸和像素比决定最终落点
```

移动相机只影响第一段，改视野参数只影响第二段。这个分工解释了后面几乎所有规则，包括为什么只有第二段需要手动调用 `updateProjectionMatrix()`。

three.js 提供两种可直接使用的相机，区别只在视锥体的形状：

| 对象 | 投影方式 | 适合场景 |
| --- | --- | --- |
| `Camera` | 相机基类，不直接使用 | 理解相机也是 `Object3D` |
| `PerspectiveCamera` | 透视投影，近大远小 | 默认 3D 场景、模型查看器、游戏视角 |
| `OrthographicCamera` | 正交投影，远近不改变尺寸 | 编辑器视图、2D/等距视图、尺寸对比 |

相机可以放进 `scene`，例如挂在某个对象下面跟着它移动，但渲染时仍然要单独传给 renderer。

## 快速上手

一台够用的透视相机需要四件事：建相机、摆位置、跟随画布尺寸、传给 renderer。

```js
import * as THREE from 'three';

const camera = new THREE.PerspectiveCamera(50, width / height, 0.1, 100);

camera.position.set(8, 5, 8);
camera.lookAt(0, 0, 0);

// 画布尺寸变化后必须更新 aspect，否则画面会被拉伸
function resize(width, height) {
  camera.aspect = width / height;
  camera.updateProjectionMatrix();
}

function render() {
  renderer.render(scene, camera);
  requestAnimationFrame(render);
}
```

改完哪些属性要重算矩阵、哪些不用，是这一课最容易踩的一条。下表可以直接当速查用：

| 属性 | 所属相机 | 默认值 | 改完要 `updateProjectionMatrix()` |
| --- | --- | --- | --- |
| `fov` | 透视 | `50` | 要 |
| `aspect` | 透视 | `1` | 要 |
| `near` | 两者 | `0.1` | 要 |
| `far` | 两者 | `2000` | 要 |
| `zoom` | 两者 | `1` | 要 |
| `left` / `right` / `top` / `bottom` | 正交 | `-1` / `1` / `1` / `-1` | 要 |
| `position` | 两者 | `(0, 0, 0)` | 不要 |
| `rotation` / `lookAt()` | 两者 | 朝向 -Z | 不要 |
| `up` | 两者 | `(0, 1, 0)` | 不要 |
| `layers` | 两者 | 只启用第 0 层 | 不要 |

分界线就是上面那张流程图：投影参数在第二段，改了要重算；摆放属性在第一段，走 `matrixWorld`，每帧渲染本来就会更新。

## 位置和朝向

相机继承 `Object3D`，所以位置、旋转、父子层级和 `lookAt(...)` 都是同一套空间规则，没有相机专属的摆放 API。

```js
camera.position.set(8, 4.7, 8);
camera.up.set(0, 1, 0);
camera.lookAt(0, 0.7, 0);
```

红色小球标出的是 `lookAt` 的目标，它永远落在画面正中。拖 `posX`、`posY`、`posZ` 换站位，画面中心不会跟着跑；把 `posY` 压到 0 附近会从平视变成贴地视角，拖成负值则是从地面下方往上看。`up` 切到 `z` 之后整个画面会绕视线滚转，因为"上"的定义变了。

<Controls of={Camera.Placement} />

- `camera.position`：相机在父节点局部空间中的位置。
- `camera.lookAt(target)`：让相机朝向世界坐标中的某个点。它只在调用的那一刻算一次，改完位置要重新调用。
- `camera.up`：相机认为哪个方向是上，默认 `(0, 1, 0)`，决定 `lookAt` 之后的滚转角。
- `camera.matrixWorld`：相机在世界空间中的最终变换，由位置、旋转和父级层级共同决定。

`up` 与视线方向接近平行时朝向会退化，画面出现莫名翻转，正是这个原因。

## 视锥体

视锥体是相机能看见的那块空间。渲染前 three.js 先判断对象是否落在视锥体内，落在外面的直接跳过。`fov`、`aspect`、`near`、`far` 不是四个独立开关，它们合起来只描述一件事——这块空间的形状。

下面的示例把这块空间画出来了。左半边是相机自己看到的画面，右半边是另一台固定相机从外面看同一个场景，橙色线框就是左边那台相机的视锥体，红色线是从相机顶点连向四个角的边。

<Canvas of={Camera.Frustum} />

<Controls of={Camera.Frustum} />

切换 `type` 能直接看到两种形状的区别：

- 透视相机的视锥体是一个**截头四棱锥**：从相机向外张开，`fov` 定张开角度，`aspect` 定横竖比例，`near` 和 `far` 切掉锥体的头和尾。物体越远占的角度越小，所以近大远小。
- 正交相机的视锥体是一个**长方体盒子**：四面平行，`left`、`right`、`top`、`bottom` 直接定盒子的宽高，`near` 和 `far` 定深度。盒子不收窄，所以远近不改变屏幕上的大小。

拖 `near` 和 `far` 时注意两边是联动的：右边线框的端面往里收，左边画面里对应位置的物体同时消失。物体突然消失或被切掉一半，基本都是它跑到了视锥体外面，而不是材质或光照出了问题。

## 透视相机

```js
const camera = new THREE.PerspectiveCamera(55, width / height, 0.1, 40);
```

`near` 和 `far` 量的是沿视线方向的深度，不是到相机的直线距离。默认视角下四个物体的深度约为 8.3、10.9、13.6 和 16.1，所以把 `near` 拉到 9 以上，最近的圆环会先被切开再整块消失；把 `far` 收到 15 以下，最远的立方体会消失。`fov` 和 `distance` 都能让物体变小，但前者改的是视野范围，后者改的是相机站位。

<Canvas of={Camera.Perspective} />

<Controls of={Camera.Perspective} />

`near` 和 `far` 的比值还决定深度精度。比值过大时远处表面会出现闪烁重叠，因为深度缓冲的精度被摊薄了。

## 正交相机

```js
const camera = new THREE.OrthographicCamera(left, right, top, bottom, near, far);
```

拖动 `distance` 是这一节最值得做的操作：物体在屏幕上的大小完全不变，只有被裁剪的时机会变。这个示例的 `far` 定在 22，所以拖到 18 以上时最远的立方体会消失，而剩下的物体一个都没变小。这就是正交投影和透视投影最根本的区别。

<Canvas of={Camera.Orthographic} />

<Controls of={Camera.Orthographic} />

正交相机没有 `aspect`，宽高比藏在观察盒的边界里，所以响应式页面要自己保持比例：先定观察盒高度，再用画布比例推导宽度。

```js
const aspect = width / height;
const halfHeight = viewHeight / 2;
const halfWidth = halfHeight * aspect;

camera.left = -halfWidth;
camera.right = halfWidth;
camera.top = halfHeight;
camera.bottom = -halfHeight;
camera.updateProjectionMatrix();
```

`zoom` 是在观察盒之外再缩放一次，两种相机都有。改观察盒是换取景范围，改 `zoom` 是在既有取景上推拉，实现响应式布局时用前者，做交互缩放时用后者更方便。

## 更新投影

`camera.projectionMatrix` 是根据视锥体参数算好后缓存起来的。渲染每一帧直接用这个矩阵，不会回头检查参数有没有被改过。所以改完字段必须手动让它重算：

```js
camera.fov = 35;
camera.updateProjectionMatrix();
```

把下面的 `autoUpdate` 关掉再拖 `fov`：读数里 `camera.fov` 一直在变，"实际生效的 fov" 却卡住不动，画面也一动不动。这就是"改了参数没反应"的全过程。重新打开 `autoUpdate`，两个值立刻对齐，画面同时跳到新的视野。

## 最佳实践

- **`near` 和 `far` 按场景实际尺度收紧。** 不要用 `0.001` 到 `100000` 兜底。比值越大深度精度越差，远处表面会闪烁重叠。先量一下场景包围盒，再定这两个值。
- **模型查看器用 45–55 的 `fov`。** 更小会失去空间感，超过 90 边缘畸变明显。
- **响应式改观察盒，交互缩放改 `zoom`。** 前者维持宽高比不变形，后者不动取景范围只推拉，职责分开就不会互相干扰。
- **透视和正交的 resize 逻辑不一样。** 透视只需更新 `aspect`；正交没有 `aspect`，必须按画布比例重算 `left`/`right`。写成两个函数，不要共用一个。
- **需要相机跟着物体走时，把它挂进场景树。** 相机是 `Object3D`，`object.add(camera)` 之后它就在物体的局部空间里，第一人称和跟随视角都不需要每帧手算位置。
- **调不出想要的取景时，先把视锥体画出来。** `CameraHelper` 能显示任意相机的视锥体线框，用第二台相机观察它，比反复猜 `fov` 和 `near` 快得多。

## 常见问题

| 现象 | 先看哪里 | 判断 |
| --- | --- | --- |
| 画面被拉伸 | `camera.aspect` | 是否等于 canvas 的宽高比；正交相机则看观察盒比例 |
| 改了 `fov` 没反应 | `updateProjectionMatrix()` | 投影矩阵是缓存的，不重算就不会生效 |
| 近处物体被切掉 | `near` | 值太大，把物体挡在了视锥体外 |
| 远处物体消失 | `far` | 值太小，物体落在视锥体后面 |
| 远处表面闪烁重叠 | `far / near` 比值 | 深度精度不足，收紧范围 |
| 某个物体完全不显示 | `camera.layers` | 相机启用的层与物体所在层没有交集 |
| 画面莫名歪斜或翻转 | `camera.up` | 是否被改过，或者与视线方向接近平行 |
| 移动相机后画面没对准 | `camera.lookAt()` | 它只算一次，改完位置要重新调用 |
| 正交相机远近大小不变 | 投影方式 | 这是正交投影的预期行为，不是 bug |

## 总结回顾

摘要：

相机把工作分成两段：相机变换决定从哪里看，视锥体决定能看见多少。透视相机用 `fov` 张开截头四棱锥，产生近大远小；正交相机用观察盒围出长方体，远近不改变尺寸。只有投影参数改变后需要手动重算投影矩阵。

一句话：

> 透视相机像眼睛，正交相机像量尺。

知识要点：

- **关键词：** 相机变换、视锥体、透视投影、正交投影、`fov`、`aspect`、`near`、`far`、`zoom`、观察盒、`lookAt()`、`updateProjectionMatrix()`、深度精度。
- **关键问题：**
  - 相机变换和投影参数分别控制什么？
  - 哪些参数改变后必须调用 `updateProjectionMatrix()`？
  - `near` 和 `far` 如何测量，为什么它们的比值会影响深度精度？
  - 移动相机后，什么时候需要重新调用 `lookAt()`？
  - 正交相机如何在画布尺寸变化时维持正确的宽高比？
