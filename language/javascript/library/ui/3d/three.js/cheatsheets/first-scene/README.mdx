# 第一幅画面

three.js 不会替你自动创建“三维世界”。一幅最小画面需要五个角色协作：`Scene` 收纳要画的对象，`Camera` 决定观察范围，`Mesh` 把形状和外观组合成物体，`WebGLRenderer` 把场景从相机视角写进 canvas，渲染循环则在状态改变后反复调用渲染。

`renderer.render(scene, camera)` 只画当前这一帧。立方体是否出现在画面里，取决于它已经加入 `scene`、相机没有和它重合且朝向它、物体落在相机的裁剪范围内。立方体是否会动，则取决于下一帧渲染前是否更新了 `rotation`。

## 快速上手

把安装课的 `main.js` 替换成下面的代码。刷新页面后会看到一个持续旋转的彩色立方体：

```js
import * as THREE from 'three';

const scene = new THREE.Scene();
const camera = new THREE.PerspectiveCamera(50, 2, 0.1, 100);
camera.position.z = 3;

const geometry = new THREE.BoxGeometry(1, 1, 1);
const material = new THREE.MeshNormalMaterial();
const cube = new THREE.Mesh(geometry, material);
scene.add(cube);

const renderer = new THREE.WebGLRenderer({ antialias: true });
renderer.setSize(640, 320);
document.body.append(renderer.domElement);

renderer.setAnimationLoop((time) => {
  cube.rotation.y = time / 1000;
  renderer.render(scene, camera);
});
```

| 输入或对象 | 本课取值 / 默认值 | 改变后要注意什么 |
| --- | --- | --- |
| `Scene` | 空场景 | 物体必须通过 `scene.add(...)` 进入场景树，才会参与这次渲染 |
| `PerspectiveCamera` | `fov=50`、`aspect=2`、`near=0.1`、`far=100` | 默认位置是原点；本例沿 Z 轴移到 `3`，才能看见同在原点的立方体 |
| `BoxGeometry` | 宽、高、深默认都是 `1` | 它只提供形状数据，不能单独渲染 |
| `MeshNormalMaterial` | 根据表面法线显示颜色，不需要光源 | 适合第一幅画面；真实材质与光照留到后续课程 |
| `WebGLRenderer.antialias` | 默认 `false`；本例设为 `true` | 在创建上下文时决定，不能靠之后直接改同名属性启用 |
| `setAnimationLoop(callback)` | 回调接收毫秒时间戳 | 传 `null` 停止；循环里先更新状态，再 `render(...)` |

## 画面为什么能出现

每个角色只回答一个问题。排查空白画面时，也应按这条关系逐层检查，而不是同时改所有参数。

| 角色 | 本例对象 | 回答的问题 | 最小检查 |
| --- | --- | --- | --- |
| 渲染目标 | `renderer.domElement` | 画到哪里 | canvas 是否已经插入页面且有非零尺寸 |
| 场景根节点 | `scene` | 画哪些对象 | `scene.children` 中是否有目标物体 |
| 观察者 | `camera` | 从哪里、以什么范围看 | 相机是否离开物体，物体是否位于 `near` 与 `far` 之间 |
| 可渲染物体 | `cube` | 形状和表面是什么 | `Mesh` 是否同时持有 `geometry` 与 `material` |
| 绘制命令 | `renderer.render(scene, camera)` | 何时把当前状态写进画布 | 初始化后是否至少调用一次 |

`Geometry` 描述顶点和三角形，`Material` 描述这些表面怎样着色，`Mesh` 才把二者组合为场景中的一个 `Object3D`。只创建 `geometry` 或 `material` 不会自动生成画面。

## 相机为什么要离开原点

新建的 `PerspectiveCamera` 位于 `(0, 0, 0)`，默认沿自身 `-Z` 方向观察；新建的立方体也位于原点。两者重合时，相机在物体内部，不能得到预期的完整立方体。

```js
camera.position.z = 3;
```

相机仍朝 `-Z` 看，所以从 `z=3` 能看到原点。若改成任意斜向位置，还要明确朝向：

```js
camera.position.set(2, 1.5, 3);
camera.lookAt(0, 0, 0);
```

相机的 `fov`、宽高比和裁剪面会在 [相机](?path=/docs/camera--docs) 课程完整展开；这里先记住“移动相机”和“移动物体”都可能改变是否可见。

## 只画一次还是持续更新

静态画面只需在状态准备好后调用一次：

```js
renderer.render(scene, camera);
```

动画画面需要反复执行“更新状态 → 渲染”：

```js
renderer.setAnimationLoop((time) => {
  cube.rotation.y = time / 1000;
  renderer.render(scene, camera);
});
```

当前 three.js 建议应用通过 `renderer.setAnimationLoop()` 注册循环，它也能与 WebXR 的帧调度衔接。需要终止时传入 `null`。怎样用 `delta` 保证不同刷新率下速度一致、怎样暂停离屏画布和同步响应式尺寸，在 [循环与尺寸](?path=/docs/render-loop-and-resize--docs) 继续处理。

## 最佳实践

- 先用 `MeshNormalMaterial` 或 `MeshBasicMaterial` 排除光照变量，确认几何、相机和渲染链路正确后再换受光材质。
- 按“创建 renderer → 创建 scene → 创建 camera → 创建 mesh 并加入 scene → render”的顺序保留最小复现，复杂项目再拆函数。
- 初始化后先画一帧；动画需要时再启动循环，静态页面不必为了显示一帧常驻刷新。
- 把相机位置、物体位置和 `near/far` 一起检查，避免用不断放大几何体来掩盖视野问题。
- 组件或页面销毁时停止循环，并对自建的 geometry、material 与 renderer 调用 `dispose()`；场景移除对象本身不会释放 GPU 资源。

## 常见问题

- 为什么页面里没有 Canvas？
  创建 `WebGLRenderer` 后把 `renderer.domElement` 插入页面；如果传入已有 Canvas，确认传入的元素就是当前页面中的那个。
- 为什么 Canvas 有背景却看不到立方体？
  确认 Mesh 已加入 `scene`，并检查相机与物体的位置、朝向以及 `near/far`；相机和物体重合时也看不到正常结果。
- 为什么换成普通颜色材质后物体全黑？
  `MeshStandardMaterial` 等受光材质需要 Light；排查时可先换成 `MeshBasicMaterial`，再按[网格、几何体与材质](?path=/docs/mesh-geometry-material--docs)补回光照。
- 为什么改了 `cube.rotation`，画面却不变？
  修改对象后必须再次调用 `renderer.render(scene, camera)`；单次渲染不会自动监听对象属性变化。
- 为什么动画在不同刷新率的设备上速度不同？
  不要使用固定的每帧增量，把速度乘以帧间 `delta`；完整做法见[循环与尺寸](?path=/docs/render-loop-and-resize--docs)。

## 总结回顾

摘要：

第一幅 three.js 画面来自一条明确的协作链：`Scene` 收纳由 geometry 和 material 组成的 `Mesh`，`Camera` 选定观察范围，`WebGLRenderer` 把当前状态写进 canvas。单次 render 产生静态帧；循环在每帧先更新对象状态，再重新绘制，才产生动画。

一句话：

> 看到画面的最小条件是对象在场景中、相机能看见它，并且 renderer 已经用这组 scene 与 camera 绘制当前帧。

知识要点：

- `Scene`、`Camera`、`Mesh` 与 `WebGLRenderer` 在一帧中分别负责什么？
- 为什么 geometry 与 material 需要通过 `Mesh` 组合后再加入场景？
- 相机和立方体都在默认原点时，为什么看不到预期画面？
- 单次 `render()` 与 `setAnimationLoop()` 分别适合什么状态更新方式？
- 空白画面应该按哪条关系逐层定位？
