# 安装

three.js 以 ES Modules 发布。最小本地项目只需要安装 `three`：npm 负责把包放进 `node_modules`，浏览器通过 import map 把 `three` 和 `three/addons/` 这样的模块名解析到实际文件，HTTP 服务再把 HTML、JavaScript 和模块文件交给浏览器。

Vite、Webpack 或其他构建工具能自动处理模块解析和生产构建，但不是 three.js 的运行依赖。本课先保留最少项目依赖，并用 `THREE.REVISION`、官方 Addon 导入和 `WebGLRenderer` 清屏证明安装结果；场景、相机和动画从 [第一幅画面](?path=/docs/first-scene--docs) 开始。

## 快速上手

安装唯一的项目依赖：

```sh
npm install --save-exact three@0.185.1
```

在 `index.html` 中先声明 import map，再加载模块入口。映射末尾的 `/` 很重要：它让 `three/addons/` 后面的相对路径继续拼接到 `examples/jsm/`。

```html
<script type="importmap">
  {
    "imports": {
      "three": "./node_modules/three/build/three.module.js",
      "three/addons/": "./node_modules/three/examples/jsm/"
    }
  }
</script>
<script type="module" src="./main.js"></script>
```

`main.js` 只验证模块和渲染后端，不提前创建场景：

```js
import * as THREE from 'three';

console.log(THREE.REVISION);

const renderer = new THREE.WebGLRenderer();
renderer.setSize(640, 320);
renderer.setClearColor('#14213d', 1);
renderer.clear();
document.body.append(renderer.domElement);
```

ES Modules 和后续资产加载都应通过 HTTP 地址运行。使用任意已有的静态服务器；下面的命令会临时运行 `serve`，不会把它写进 `package.json`：

```sh
npx serve .
```

打开终端给出的地址。示例页应显示与安装包对应的 `THREE.REVISION`、两项绿色检查和一块深蓝色画布。

| 输入或状态 | 本课取值 | 改变后要注意什么 |
| --- | --- | --- |
| 项目依赖 | 只有 `three@0.185.1` | 升级时同时更新本地映射使用的包，并核对运行时 revision |
| 核心映射 | `three/build/three.module.js` | import map 必须出现在第一个使用这些模块名的 module script 之前 |
| Addons 映射 | `three/examples/jsm/` | 映射键和值都保留末尾 `/` |
| 服务根目录 | 包含 `index.html` 与 `node_modules` 的项目目录 | 从上级或子目录启动会让映射产生 404 |
| 渲染后端 | `WebGLRenderer` 使用 WebGL 2 | 浏览器或 GPU 不支持时，模块仍可能导入成功，但 renderer 会创建失败 |

## Addons

控制器、加载器和后处理等官方扩展随 `three` 包一起发布，不需要再安装一个名为 addons 的包。它们不在核心入口中自动导出，需要从完整路径显式导入：

```js
import * as THREE from 'three';
import { OrbitControls } from 'three/addons/controls/OrbitControls.js';
```

两条导入最终都来自当前安装的 `three@0.185.1`。Addon 内部也会导入 `three`，因此 import map 必须同时提供核心名称和 `three/addons/` 前缀。路径区分大小写，并保留文件扩展名 `.js`。

| 来源 | 导入方式 | 是否另行安装 |
| --- | --- | --- |
| three.js 核心 | `import * as THREE from 'three'` | 安装 `three` |
| three.js 官方 Addon | `three/addons/{category}/{Name}.js` | 不需要，已包含在 `three` 中 |
| 第三方插件 | 使用插件自己的包名和文档入口 | 通常需要，并要核对它支持的 three.js 版本 |

本课只验证 `OrbitControls` 类可以解析；它怎样控制相机留到 [相机控制器](?path=/docs/camera-controls--docs) 课程。

## CDN

不想创建本地 npm 依赖时，可以让 import map 直接指向 CDN。这种方式仍需要 HTTP 服务，但项目中没有 `node_modules`：

```html
<script type="importmap">
  {
    "imports": {
      "three": "https://cdn.jsdelivr.net/npm/three@0.185.1/build/three.module.js",
      "three/addons/": "https://cdn.jsdelivr.net/npm/three@0.185.1/examples/jsm/"
    }
  }
</script>
```

核心与 Addons 必须使用同一个 three.js 版本和同一个 CDN。不要让 `three` 指向本地包、Addon 却指向 CDN，也不要把 `0.185.1` 与其他 revision 混用；这种组合可能加载两份核心代码，或让 Addon 使用不兼容的 API。

CDN 适合最小演示、在线编辑器和无需构建的静态页面。它把可用性交给网络和 CDN；需要离线开发、稳定依赖安装或复杂生产构建时，改用本地包和合适的构建工具。

## 最佳实践

- 一个页面只采用一种来源策略：要么都来自当前本地包，要么都来自同版本 CDN。
- 学习范例固定 three.js 版本并显示 `THREE.REVISION`，排查教程差异时先比较 revision。
- import map 放在所有 module script 之前；路径前缀映射同时保留键和值的末尾 `/`。
- 始终通过 HTTP 地址打开示例，不把 `file://` 下偶然可用的结果当成正常运行环境。
- 本地 `node_modules` 映射适合无构建的学习项目；生产发布前根据部署目标选择 CDN 或构建工具。
- 官方 Addon 沿用 `three/addons/...`，第三方插件按其文档单独安装并核对兼容版本。

## 常见问题

- 为什么会报 `Failed to resolve module specifier "three"`？
  在所有 module script 之前放置有效的 import map，并确认 `"three"` 映射到了实际存在的 `three.module.js`；可参考 [Three.js Installation](https://threejs.org/manual/en/installation.html)。
- 为什么请求 `node_modules/...` 返回 404？
  用静态服务器从同时包含 `index.html` 和 `node_modules` 的目录启动，不要从项目的上级目录或错误的子目录启动。
- 为什么核心模块能导入，但 Addon 导入失败？
  检查 `three/addons/` 的前缀映射是否保留末尾 `/`，并核对路径大小写和 `.js` 扩展名。
- 为什么直接双击 HTML，以 `file://` 打开时加载失败？
  改用本地 HTTP 服务运行示例；浏览器模块和资源加载的安全限制不适合把 `file://` 当成正常环境。
- 为什么 `THREE.REVISION` 不是预期版本？
  检查本地包或 CDN 的实际 URL，确认核心模块和 Addons 使用同一版本，并排除缓存或页面加载了另一份 three.js。
- 为什么模块都能导入，但 `WebGLRenderer` 创建失败？
  这通常不是安装或 import map 问题，而是浏览器 WebGL 2、GPU 驱动或设备环境问题；先检查浏览器的 WebGL 支持和 GPU 状态。

## 总结回顾

摘要：

最小 three.js 项目只把 `three` 放进项目依赖，再由 import map 告诉浏览器怎样解析核心模块和官方 Addons。本地包与 CDN 都能工作，但同一页面必须保持来源和版本一致，并通过 HTTP 服务运行；最终用 revision、Addon 导入和 WebGL 清屏分别核对版本、模块解析与渲染环境。

一句话：

> three.js 不依赖 Vite；安装闭环是统一来源的模块映射、HTTP 运行和可观察的浏览器验证。

知识要点：

- npm、import map 和 HTTP 服务在最小 three.js 项目中分别负责什么？
- 为什么核心模块与官方 Addons 只需要一个 `three` 依赖？
- 本地包和 CDN 方案怎样保持版本与来源一致？
- 怎样从 404、模块解析错误、revision 和 WebGL 报错判断失败发生在哪一层？
