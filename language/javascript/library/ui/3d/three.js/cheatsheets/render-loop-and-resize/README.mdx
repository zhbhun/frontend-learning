# 循环与尺寸

动画和响应式画布是两条独立链路：时间链路决定“这一帧状态应前进多少”，尺寸链路决定“这一帧按多大的画布与怎样的投影来画”。两者最后都在 `renderer.render(scene, camera)` 汇合，但不要用帧数代替时间，也不要只用 CSS 拉伸已经渲染好的像素。

canvas 同时有 CSS 显示尺寸和 drawing buffer 像素尺寸。`renderer.setSize(width, height, false)` 接收逻辑像素，并结合 renderer 的 pixel ratio 设置 drawing buffer；透视相机还要使用同一个显示宽高比更新 `camera.aspect` 和投影矩阵。任何一段不同步，都可能出现模糊或拉伸。

## 快速上手

先让 CSS 决定 canvas 在页面中的大小，再在渲染前检查显示尺寸是否改变。动画速度使用秒制 `delta`：

```css
canvas {
  display: block;
  width: 100%;
  height: 100%;
}
```

```js
renderer.setPixelRatio(Math.min(window.devicePixelRatio, 2));

let lastTime = 0;

renderer.setAnimationLoop((time) => {
  const width = Math.max(1, Math.floor(renderer.domElement.clientWidth));
  const height = Math.max(1, Math.floor(renderer.domElement.clientHeight));
  const pixelRatio = renderer.getPixelRatio();
  const bufferWidth = Math.floor(width * pixelRatio);
  const bufferHeight = Math.floor(height * pixelRatio);

  if (
    renderer.domElement.width !== bufferWidth ||
    renderer.domElement.height !== bufferHeight
  ) {
    renderer.setSize(width, height, false);
    camera.aspect = width / height;
    camera.updateProjectionMatrix();
  }

  const delta = lastTime ? Math.min((time - lastTime) / 1000, 0.1) : 0;
  lastTime = time;
  cube.rotation.y += 1.2 * delta;

  renderer.render(scene, camera);
});
```

| 输入或状态 | 默认值 / 常用起点 | 改变后要注意什么 |
| --- | --- | --- |
| `time` | `setAnimationLoop()` 提供的毫秒时间戳 | 相邻两次相减后除以 `1000` 得秒制 `delta`；首帧设为 `0` |
| 业务速度 | 本例 `1.2` 弧度/秒 | 每帧累加 `speed * delta`，不要把速度写成“每帧多少” |
| CSS 尺寸 | 由布局和 `clientWidth/clientHeight` 决定 | 只改变它会拉伸旧 drawing buffer |
| `renderer.setSize(w, h, false)` | `false` 表示不覆盖 CSS style | 按当前 pixel ratio 重建 drawing buffer，并更新 viewport |
| `renderer` pixel ratio | 默认 `1`；常用 `min(devicePixelRatio, 2)` | 越高越清晰，也按平方量级增加像素工作量；改变后 renderer 会按现有逻辑尺寸重设画布 |
| `camera.aspect` | `PerspectiveCamera` 默认 `1` | 设为显示宽 / 显示高后，还要调用 `updateProjectionMatrix()` |

## 用 delta 表示每秒速度

渲染回调的触发次数受显示器刷新率、浏览器调度、页面可见性和机器负载影响。若每帧固定加 `0.01`，60 Hz 下一秒约增加 `0.6`，120 Hz 下一秒约增加 `1.2`，同一动画会快一倍。

用 `delta` 后，速度有稳定的物理含义：

```js
const delta = (time - lastTime) / 1000;
cube.rotation.y += angularSpeed * delta;
```

`angularSpeed = 1` 表示每秒约转 `1` 弧度。调整下面的角速度并观察 `delta`、累计时间与角度读数；暂停再恢复时，首帧 `delta` 会重置为 `0`。

## 分清两种画布尺寸

CSS 尺寸回答“页面上占多大”，drawing buffer 回答“WebGL 实际画多少像素”。二者可以不同：一个显示为 `640 × 360` CSS 像素、pixel ratio 为 `2` 的 canvas，drawing buffer 通常是 `1280 × 720` 像素。

| 读数 / API | 表示什么 | 是否计入 pixel ratio |
| --- | --- | --- |
| `canvas.clientWidth/clientHeight` | 当前 CSS 布局后的显示尺寸 | 否 |
| `renderer.getSize(target)` | renderer 保存的逻辑尺寸 | 否 |
| `canvas.width/height` | canvas 属性上的 drawing buffer 尺寸 | 是 |
| `renderer.getDrawingBufferSize(target)` | renderer 当前 drawing buffer 尺寸 | 是 |
| `renderer.getPixelRatio()` | 逻辑尺寸到 drawing buffer 的倍率 | 本身就是倍率 |

不要用 `canvas.width` 反过来当 CSS 布局来源，否则高 DPR 屏幕上会把物理像素又当逻辑像素使用。

## 同步 renderer 与相机

一次正确 resize 包含三个动作，而且它们使用同一组显示宽高：

```js
renderer.setSize(width, height, false);
camera.aspect = width / height;
camera.updateProjectionMatrix();
```

下面先把“尺寸策略”切为错误分支，再改变 CSS 宽高比：

- “只改 CSS”让 canvas 版面变化，但 renderer 的逻辑尺寸与 drawing buffer 保持旧值，旧像素会被 CSS 拉伸。
- “漏更新投影矩阵”会更新 renderer 和 `camera.aspect` 属性，却故意不调用 `updateProjectionMatrix()`；读数会出现“属性宽高比是新值，投影矩阵宽高比仍是旧值”。
- “完整同步”让 CSS、renderer、drawing buffer 和投影矩阵回到一致，圆环保持正确比例。

## 控制 pixel ratio

`renderer.setPixelRatio(value)` 会保存倍率，并使用 renderer 当前逻辑尺寸重新设置 canvas。高 DPR 提升边缘和细节清晰度，但宽高都乘以倍率：同样的 CSS 面积从 ratio `1` 提到 `2`，drawing buffer 像素数约变成四倍。

```js
const cappedPixelRatio = Math.min(window.devicePixelRatio, 2);
renderer.setPixelRatio(cappedPixelRatio);
```

上限 `2` 是常见性能策略，不是 three.js 默认值或硬性规则。移动端重场景可能主动使用 `1` 或动态降低；截图、离线渲染等质量优先任务也可能使用更高值。改变上方 resize 实例的 pixel ratio，核对 CSS 尺寸不变而 drawing buffer 读数按倍率改变。

## 何时检查尺寸

有两种常见入口，选择取决于页面结构：

| 入口 | 适合情况 | 注意 |
| --- | --- | --- |
| 每帧比较 `clientWidth/clientHeight` 与 drawing buffer | 已经持续动画；布局变化来源复杂 | 比较时计入 pixel ratio，只在确实变化时调用 `setSize()` |
| `ResizeObserver` 监听容器 | 静态或按需渲染；希望尺寸变化才重绘 | 监听真正控制布局的容器，并防止宽或高为 `0` |
| `window.resize` | canvas 只随窗口改变的简单全屏页面 | 侧栏、父容器、字体或面板变化不一定触发窗口 resize |

无论从哪里触发，都把 renderer 尺寸和相机投影更新放在同一个函数中。正交相机没有 `aspect` 属性，需要按新的宽高比重算 `left/right/top/bottom`；具体公式在相机课回查。

## 最佳实践

- 让 CSS 负责布局，调用 `renderer.setSize(width, height, false)` 时保留第三个参数 `false`，避免渲染代码反向覆盖页面样式。
- 所有速度都写成“每秒多少”，统一乘秒制 `delta`；恢复循环时清空旧时间戳，并按业务需要限制过大的单帧步长。
- 把 pixel ratio 当质量预算，不盲目等于设备 DPR；先设倍率，再同步 renderer 尺寸。
- resize 时用同一组非零宽高更新 renderer 和 camera；直接修改透视参数后统一调用一次 `updateProjectionMatrix()`。
- 静态场景在状态或尺寸改变时按需 render；持续动画在离屏、标签页隐藏或组件销毁时暂停。
- 销毁页面时停止 `setAnimationLoop(null)`、断开 observer，并释放 renderer、geometry 和 material。

## 常见问题

- 为什么动画在不同刷新率的设备上速度不同？
  不要使用固定的每帧增量，把每秒速度乘以帧间 `delta`，让动画与刷新率解耦。
- 为什么从后台回来后对象突然跳很远？
  恢复循环时重置 `lastTime`，并对异常长的 `delta` 做上限处理，避免一次性补算整段暂停时间。
- 为什么容器尺寸变了，画面被横向或纵向拉伸？
  用同一组非零宽高同步 CSS 显示尺寸、renderer drawing buffer 和相机投影；透视相机更新 `aspect` 后还要调用 `updateProjectionMatrix()`。
- 为什么画布尺寸看起来正确，画面却很模糊？
  检查 drawing buffer 是否按 pixel ratio 放大；只改变 CSS 宽高不会增加实际渲染像素。
- 为什么 `camera.aspect` 已经改变，画面仍然是旧比例？
  修改 `camera.aspect` 后调用 `camera.updateProjectionMatrix()`，否则 renderer 仍会使用旧的投影矩阵。
- 为什么高 DPR 设备明显掉帧？
  给 `renderer.setPixelRatio()` 设置合理上限；DPR 会同时放大 drawing buffer 的宽和高，像素工作量会按面积增长。
- 为什么侧栏开合后画布没有更新？
  不要只监听 `window.resize`；容器内部尺寸变化时使用 `ResizeObserver` 触发同一套 resize 更新逻辑。

## 总结回顾

摘要：

稳定动画用秒制 `delta` 把速度从刷新率中解耦，暂停和恢复时重置时间基准。响应式渲染则从 CSS 显示尺寸出发，用 pixel ratio 计算 drawing buffer，并用同一宽高比更新相机投影；CSS、renderer 或 projection 任一层停在旧状态，都会留下可由尺寸和矩阵读数定位的模糊或拉伸。

一句话：

> 每帧用 delta 推进状态，每次 resize 用同一尺寸同步 renderer、drawing buffer 与相机投影。

知识要点：

- 为什么固定“每帧增量”会让动画速度跟随刷新率变化？
- 循环暂停并恢复时，怎样避免第一帧补算整段暂停时间？
- CSS 尺寸、renderer 逻辑尺寸与 drawing buffer 分别表示什么？
- `setPixelRatio()` 怎样影响画质与像素工作量？
- 为什么修改 `camera.aspect` 后还必须更新投影矩阵？
- 怎样从尺寸和矩阵读数判断拉伸发生在哪一层？
