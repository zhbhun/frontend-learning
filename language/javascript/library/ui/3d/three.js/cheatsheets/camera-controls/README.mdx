# 相机控制器

相机控制器把鼠标、触摸或键盘输入转换成相机的 `position`、`quaternion`、`up`、`zoom`，有些控制器还维护一个观察中心 `target`。它不替代 `Camera`，也不负责渲染；`WebGLRenderer` 只会把控制器已经写入相机的结果画出来。

选择控制器时先分清三件事：相机是否围绕目标运动、画面是否必须保持朝上、输入是否要独占鼠标。`OrbitControls`、`MapControls`、`ArcballControls` 和 `TrackballControls` 都围绕目标观察，但允许的滚转和手势不同；`FlyControls` 与 `FirstPersonControls` 在空间中移动；`PointerLockControls` 只接管锁定后的观察方向，移动和碰撞仍由应用负责。

本页有多个 WebGL Canvas。每个实例先绘制一帧，只在进入视口前后 `200px` 时运行；离屏后暂停并保留最后画面。键盘型实例还要求先聚焦画布，`PointerLockControls` 离屏时会主动解锁，因此同一时刻通常只有当前阅读位置附近的实例占用渲染和输入。

## 快速上手

最常见的模型查看器先用 `OrbitControls`：构造时传入相机和接收输入的画布，设置 `target`，再调用一次 `update()` 让相机姿态与内部球坐标同步。

```js
import { OrbitControls } from 'three/addons/controls/OrbitControls.js';

const controls = new OrbitControls(camera, renderer.domElement);
controls.target.set(0, 1, 0);
controls.enableDamping = true;

camera.position.set(4, 3, 6);
controls.update();

function animate(time) {
  const delta = clock.getDelta();

  // 阻尼或 autoRotate 开启后，每帧都要继续推进控制器。
  controls.update(delta);
  renderer.render(scene, camera);
}

renderer.setAnimationLoop(animate);

// 页面卸载时移除控制器注册的 DOM 监听。
function dispose() {
  controls.dispose();
}
```

快速判断：

| 输入或条件 | 初始状态 / 默认值 | 改变后要注意什么 |
| --- | --- | --- |
| `object` / `camera` | 构造时传入 | 控制器直接改它的变换；不要同时让两个已启用控制器写同一相机 |
| `domElement` | 实际使用时传 `renderer.domElement` | 输入范围跟随这个元素；切换元素使用 `disconnect()` / `connect()` |
| `enabled` | `true` | `false` 只停止响应，不移除监听，也不释放资源 |
| `target` | 通常为 `(0, 0, 0)` | 适用于围绕目标的四种控制器；修改后调用 `update()` 同步 |
| `update()` | 各控制器不同 | 阻尼、自动旋转、速度积分或手动状态修改可能依赖它 |
| `dispose()` | 不会自动调用 | 控制器不再使用或页面卸载时调用，避免残留 DOM 监听 |

## 先选交互模型

| 控制器 | 相机与目标关系 | 是否保持朝上 | 主要输入 | 更新契约 | 典型用途 |
| --- | --- | --- | --- | --- | --- |
| `OrbitControls` | 围绕 `target` | 是 | 左键旋转、右键平移、滚轮缩放 | 手动变换后；阻尼/自动旋转时逐帧 | 模型查看器、产品展示、通用场景浏览 |
| `MapControls` | 围绕地图目标 | 是 | 左键平移、右键旋转、滚轮缩放 | 继承 `OrbitControls` | 地图、总平面、俯视编辑器 |
| `ArcballControls` | 围绕轨迹球中心 | 否，可滚转 | 轨迹球、双击聚焦、FOV 操作 | 内部动画不要求外部逐帧 `update()` | 复杂模型检查、自由姿态观察 |
| `TrackballControls` | 围绕 `target` | 否，可越过极点 | 左键旋转、右键平移、滚轮缩放 | 逐帧 `update()`；尺寸变化调用 `handleResize()` | 需要连续翻转的旧式轨迹球交互 |
| `FlyControls` | 没有固定目标 | 否，六自由度 | 键盘移动/旋转和指针观察 | 每帧 `update(delta)` | DCC 飞行模式、空间漫游 |
| `FirstPersonControls` | 没有固定目标 | 通常限制俯仰 | 键盘移动、拖动观察 | 每帧 `update(delta)` | 简单第一人称步行、场景巡检 |
| `PointerLockControls` | 没有固定目标 | 限制俯仰，不负责完整移动 | 锁定后的相对鼠标位移 | 观察不需 `update()`；移动由应用逐帧调用 | FPS、必须持续转向的第一人称体验 |

相似结果不代表机制相同。`OrbitControls` 和 `TrackballControls` 都能把物体转到背面，但前者维持 `camera.up`，后者允许画面倒置；`FirstPersonControls` 自带速度积分，`PointerLockControls` 则只提供锁定、朝向和平面移动方法。

## OrbitControls

`OrbitControls` 用球坐标描述相机相对 `target` 的方位和距离。旋转改变方位角与极角，dolly 改变透视相机到目标的距离，平移同时移动相机和 `target`；它不会把相机变成 `target` 的子对象。

```js
const controls = new OrbitControls(camera, renderer.domElement);
controls.target.set(0, 1, 0);
controls.minDistance = 2;
controls.maxDistance = 12;
controls.minPolarAngle = 0;
controls.maxPolarAngle = Math.PI / 2;
controls.update();
```

在实例里开启阻尼，拖动后松手；再关闭“逐帧 `update()`”重复操作。前者会继续平滑收敛，后者只保留事件处理阶段已经应用的姿态。

常用属性：

| 属性 | 默认值 | 作用与边界 |
| --- | --- | --- |
| `target` | `(0, 0, 0)` | 环绕中心；移动它会改变构图中心 |
| `enableRotate` / `enablePan` / `enableZoom` | `true` | 分别关闭旋转、平移或缩放输入 |
| `rotateSpeed` / `panSpeed` / `zoomSpeed` | `1` | 各输入通道的速度倍率 |
| `enableDamping` | `false` | 开启惯性；随后必须逐帧调用 `update()` |
| `dampingFactor` | `0.05` | 仅在阻尼开启时生效 |
| `autoRotate` / `autoRotateSpeed` | `false` / `2` | 自动环绕；逐帧传入秒单位 `deltaTime` 可与刷新率解耦 |
| `screenSpacePanning` | `true` | `true` 沿屏幕上下平移；`false` 沿垂直于 `camera.up` 的平面平移 |
| `zoomToCursor` | `false` | 缩放中心跟随指针，而不只朝 `target` 缩放 |
| `minDistance` / `maxDistance` | `0` / `Infinity` | 透视相机的 dolly 距离范围 |
| `minZoom` / `maxZoom` | `0` / `Infinity` | 正交相机的 `zoom` 范围 |
| `minPolarAngle` / `maxPolarAngle` | `0` / `Math.PI` | 垂直旋转范围；相等时锁定垂直轴 |
| `minAzimuthAngle` / `maxAzimuthAngle` | `-Infinity` / `Infinity` | 水平旋转范围；有限区间必须小于一整圈 |
| `cursor`、`minTargetRadius`、`maxTargetRadius` | 原点、`0`、`Infinity` | 限制 `target` 到另一个关注点 `cursor` 的距离 |

输入映射由 `mouseButtons`、`touches` 和 `keys` 保存。键盘平移需先调用 `listenToKeyEvents(element)`，不用时配对调用 `stopListenToKeyEvents()`；默认方向键步长由 `keyPanSpeed=7` 控制。

程序也可以调用 `rotateLeft()`、`rotateUp()`、`pan()`、`dollyIn()`、`dollyOut()`；`getPolarAngle()`、`getAzimuthalAngle()`、`getDistance()` 用于读回当前结果。`saveState()` 保存相机位置、目标与缩放，`reset()` 回到最近一次保存或构造时的状态。

`cursorStyle` 可选 `'auto'` 或 `'grab'`。`target0`、`position0` 和 `zoom0` 是保存/重置使用的公开快照，优先通过 `saveState()` 更新它们，不要分别写入导致状态不一致。交互开始、相机变化和交互结束分别触发 `start`、`change`、`end`。

## MapControls

`MapControls` 继承 `OrbitControls`，但把最频繁的地图操作交给左键：左键和单指平移，右键和双指旋转，中键/滚轮和双指缩放。默认 `screenSpacePanning=false`，当前版本会用射线求出光标与 `camera.up` 正交平面的交点，使拖动更像“抓住地图上的点”。

```js
const controls = new MapControls(camera, renderer.domElement);
controls.target.set(0, 0, 0);
controls.screenSpacePanning = false;
controls.maxPolarAngle = Math.PI * 0.48;
controls.update();
```

| --- | --- | --- |
| 左键 / 单指 | `PAN` | `OrbitControls` 默认旋转 |
| 中键 / 滚轮 | `DOLLY` | 相同 |

| 双指 | `DOLLY_ROTATE` | `OrbitControls` 默认 `DOLLY_PAN` |

地图不是因为类名就自动获得经纬度、瓦片或地球曲率；它仍在 three.js 世界坐标中移动相机。地理投影和地图数据是应用层的独立职责。

## ArcballControls

`ArcballControls` 把指针映射到虚拟球面，因此可以在三个旋转自由度中连续转动，并显示轨迹球 gizmo。构造函数的第三个 `scene` 参数可省略，但省略后无法显示 gizmo 和平移网格。

```js
const controls = new ArcballControls(camera, renderer.domElement, scene);
controls.enableAnimations = true;
controls.enableFocus = true;
controls.enableGizmos = true;
controls.target.set(0, 1, 0);
controls.update();
```

拖动观察自由滚转，双击彩色物体观察聚焦动画；`ArcballControls` 会为旋转惯性和聚焦自行安排动画帧，外部渲染循环只需继续绘制场景。

| `enableAnimations` / `dampingFactor` / `wMax` | `true` / `25` / `20` | 控制旋转惯性、衰减和起始最大角速度 |
| `enableFocus` / `focusAnimationTime` | `true` / `500` ms | 双击或双击触摸聚焦及其时长 |
| `enableGizmos` / `radiusFactor` | `true` / `0.67` | 是否使用 gizmo 及其相对画布尺寸 |
| `enableGrid` | `false` | 桌面平移期间显示网格 |
| `cursorZoom` | `false` | 让缩放以光标为中心 |

| `rotateSpeed` / `scaleFactor` | `1` / `1.1` | 旋转速度与每次缩放比例 |
| `minFov` / `maxFov` | `5` / `90` | 透视相机 FOV 操作范围 |
| 距离与 zoom 限制 | `0` 到 `Infinity` | 分别约束透视相机距离与正交相机缩放 |

`setMouseAction()` / `unsetMouseAction()` 可把 `PAN`、`ROTATE`、`ZOOM`、`FOV` 重新绑定到鼠标键、滚轮和修饰键。`saveState()` / `reset()` 保存与恢复状态；`copyState()` / `pasteState()` 使用系统剪贴板；`setCamera()` 在运行时切换相机；`setGizmosVisible()`、`setTbRadius()` 和 `disposeGrid()` 管理辅助显示。

`activateGizmos()` 临时加强或减弱 gizmo，通常由交互状态驱动；`getRaycaster()` 返回各 Arcball 实例共享的内部 `Raycaster`，需要按 `Layers` 过滤命中时可配置它，但不要把它当成实例私有对象。

被控制的相机不应挂在普通 `Object3D` 父级下面；只有直接位于场景下的相机变换符合该控制器的假设。

## TrackballControls

`TrackballControls` 与 `OrbitControls` 都围绕 `target`，但旋转时同时更新 `camera.up`。越过“北极”或“南极”后它不会自动扶正，所以能连续翻转，也更容易让用户失去方向感。

```js
const controls = new TrackballControls(camera, renderer.domElement);
controls.target.set(0, 1, 0);

function animate() {
  controls.update();
  renderer.render(scene, camera);
}

function resize() {
  controls.handleResize();
}
```

## FlyControls

`FlyControls` 不维护 `target`，而是沿相机自己的局部 X/Y/Z 轴移动，并直接累积四元数旋转。它可以俯仰、偏航和滚转，适合没有固定地面的空间浏览。

```js
const controls = new FlyControls(camera, renderer.domElement);
controls.movementSpeed = 4;
controls.rollSpeed = 0.7;
controls.dragToLook = true;

function animate() {
  controls.update(clock.getDelta());
  renderer.render(scene, camera);
}
```

先单击画布取得键盘输入：`W/S` 前后、`A/D` 左右、`R/F` 上下、方向键俯仰/偏航、`Q/E` 滚转。

<Canvas of={Examples.Fly} />
<Controls of={Examples.Fly} />

| 属性 | 默认值 | 作用与边界 |
| --- | --- | --- |
| `movementSpeed` | `1` | 每秒移动倍率，最终位移还乘 `delta` |
| `rollSpeed` | `0.005` | 俯仰、偏航和滚转的速度倍率 |
| `dragToLook` | `false` | `true` 时只有按住指针才观察；`false` 时左/右键兼作前进/后退 |
| `autoForward` | `false` | 一旦开始移动便持续向前，后退输入会暂时抵消 |

`FlyControls` 只做自由运动，不处理地面高度、重力、碰撞或房间边界。需要这些约束时，应在应用移动系统或物理系统中处理。

## FirstPersonControls

`FirstPersonControls` 同样没有 `target`，但交互更像第一人称步行：键盘给出目标速度，按住指针拖动观察，`dampingFactor` 让移动和视线速度逐渐追上输入。

```js
const controls = new FirstPersonControls(camera, renderer.domElement);
controls.movementSpeed = 4;
controls.lookSpeed = 0.05;
controls.dampingFactor = 0.12;
controls.constrainVertical = true;
controls.verticalMin = Math.PI * 0.25;
controls.verticalMax = Math.PI * 0.75;

function animate() {
  controls.update(clock.getDelta());
  renderer.render(scene, camera);
}
```

`W/S` 或上下方向键前后，`A/D` 或左右方向键横移，`E/Q` 上下移动。鼠标左键拖动同时可触发前进，右键拖动可触发后退；键盘前后键已按下时，拖动只改变视线。

| --- | --- | --- |
| `movementSpeed` / `lookSpeed` | `1` / `0.005` | 移动和观察速度 |
| `dampingFactor` | `0.1` | 越小惯性越重；`1` 禁用阻尼 |
| `lookVertical` | `true` | 是否允许垂直观察 |
| `constrainVertical` | `false` | 是否把垂直观察映射到给定范围 |
| `verticalMin` / `verticalMax` | `0` / `Math.PI` | 垂直观察范围，单位为弧度 |

| `mouseDragOn` | `false`，只读 | 当前是否正在拖动观察 |
| `lookAt()` | — | 设置初始观察方向并同步内部经纬角 |

在 `three@0.185.1` 中，`handleResize()` 已弃用且只会输出警告；当前实现根据指针按下位置计算偏移，不需要再调用它。

## PointerLockControls

`PointerLockControls` 基于浏览器 Pointer Lock API。锁定后鼠标可以无限移动并提供相对位移，适合持续转向；锁定必须由按钮或点击等用户手势触发，用户可用 `Esc` 退出。

```js
const controls = new PointerLockControls(camera, renderer.domElement);

startButton.addEventListener('click', () => controls.lock());

controls.addEventListener('lock', () => menu.hidden = true);
controls.addEventListener('unlock', () => menu.hidden = false);

function updatePlayer(delta) {
  if (moveForward) controls.moveForward(speed * delta);
  if (moveRight) controls.moveRight(speed * delta);
}
```

范例把 WASD 监听和移动积分明确写在应用层；控制器自身只根据鼠标相对位移旋转相机。

| 属性 / 方法 | 默认值 | 作用与边界 |
| --- | --- | --- |
| `isLocked` | `false`，只读 | 当前 `domElement` 是否拥有指针锁定 |
| `pointerSpeed` | `1` | 鼠标相对位移影响旋转的倍率 |
| `minPolarAngle` / `maxPolarAngle` | `0` / `Math.PI` | 俯仰范围，假设 Y 轴朝上 |
| `lock(unadjustedMovement)` | `false` | 请求锁定；`true` 尝试关闭系统鼠标加速度，浏览器可能不支持 |
| `unlock()` | — | 主动退出指针锁定 |
| `getDirection(v)` | — | 把当前单位观察方向写入传入向量 |
| `moveForward(distance)` | — | 沿 XZ 平面前后移动，假设 `camera.up` 为 Y 轴 |
| `moveRight(distance)` | — | 沿相机右方向移动 |

监听 `lock` / `unlock` 控制菜单、暂停状态和键盘输入；`change` 表示鼠标已经改变相机朝向。碰撞、跳跃、重力、速度和动画都不是该类的职责。

## 更新与渲染

控制器的 `update()` 不是统一含义，不能因为名字相同就机械地全都调用或全都省略。

| 控制器 | 何时调用 | 省略时的可见结果 |
| --- | --- | --- |
| `OrbitControls` / `MapControls` | 手动改相机或 `target` 后调用一次；阻尼/自动旋转开启后逐帧调用 | 初始球坐标不同步，或松手后的阻尼和自动旋转停止 |
| `ArcballControls` | 手动改 `target`、相机或限制后调用；内部交互动画自行推进 | 手动改动可能没有同步；内部旋转/聚焦动画不依赖外部循环调用它 |
| `TrackballControls` | 每帧调用，尺寸或位置变化再调用 `handleResize()` | 指针累积量和阻尼不会继续应用 |
| `FlyControls` | 每帧传秒单位 `delta` | 按键状态不会积分成位移与旋转 |
| `FirstPersonControls` | 每帧传秒单位 `delta` | 移动、观察与阻尼不会推进 |
| `PointerLockControls` | 观察不需要调用；应用按帧调用移动方法 | 鼠标仍能转向，但没有应用层移动 |

没有阻尼、自动运动或其他场景动画时，围绕目标的控制器可以利用 `change` 事件按需渲染。存在连续状态时使用统一渲染循环更直接，但要在页面隐藏、Canvas 离屏或组件卸载时暂停。

## 启用、切换与销毁

所有这些控制器都继承 `Controls` 的公共入口：`object` 是被控制对象，`domElement` 是输入元素，`enabled` 决定是否响应，`connect()` / `disconnect()` 管理 DOM 监听，`dispose()` 结束使用。`keys`、`mouseButtons`、`touches` 的具体形状由子类定义；`state` 是内部交互状态，不应用作业务状态机。

```js
let activeControls = orbitControls;

function switchControls(nextControls) {
  activeControls.enabled = false;
  activeControls.disconnect();

  activeControls = nextControls;
  activeControls.connect(renderer.domElement);
  activeControls.enabled = true;
}

function unmount() {
  activeControls.dispose();
  renderer.setAnimationLoop(null);
}
```

`enabled=false` 适合暂时让 UI、拖拽工具或另一个控制器取得输入；它不会移除监听。`disconnect()` 适合还会重新连接的实例；`dispose()` 表达不再使用，并应与渲染循环、应用自己的键盘监听和 WebGL 资源清理放在同一个卸载流程。

同一相机只保留一个输入所有者。若同时启用 `OrbitControls` 和 `TransformControls`，拖动 gizmo 时应暂时关闭相机控制器；若在两种相机浏览模式间切换，先断开旧控制器再连接新控制器。

## 最佳实践

- 先按交互模型选类，再调整速度；不要试图用一组极端参数把 `OrbitControls` 伪装成第一人称控制器。
- 始终把 `renderer.domElement` 或明确的容器作为输入边界，避免控制器监听整个 `document` 后抢走页面滚动和其他组件输入。
- 初始化顺序保持为：设置相机初始位置与 `up` → 构造控制器 → 设置 `target` 和限制 → `update()`。
- 所有速度积分使用秒单位 `delta`，并对页面恢复后的超大 `delta` 做上限夹取。
- 键盘型控制器只在画布聚焦、鼠标锁定或明确进入漫游模式后启用；退出模式时清空按键状态。
- 对透视相机限制 `minDistance` / `maxDistance`，对正交相机限制 `minZoom` / `maxZoom`，不要混用两套含义。
- 路由切换、组件卸载和重建渲染器前调用 `dispose()`；应用自己注册的键盘、可见性和尺寸监听也要配对清理。

## 常见问题

- 为什么拖动画布完全没反应？
  确认控制器接收的是实际可见的 `renderer.domElement`，且 `enabled` 为 `true`；如果上层元素遮住了 Canvas，要修正遮罩或指针事件设置。
- 为什么开启阻尼后松手就停止？
  在动画循环中持续调用 `controls.update()`；`enableDamping` 只开启惯性，不会自动启动更新。
- 为什么修改相机位置后第一次操作会跳动？
  修改相机位置或方向后调用一次 `controls.update()`，让控制器内部保存的球坐标或方向与相机当前状态同步。
- 为什么两个控制器会同时响应同一组输入？
  同一相机只保留一个启用的控制器；切换控制器时先把旧控制器设为 `enabled = false`，必要时再调用 `disconnect()` 或 `dispose()`。
- 为什么 MapControls 左拖方向不符合预期？
  检查 `screenSpacePanning`、`camera.up` 和 `target`；如果要沿屏幕平移，设为 `true`，如果要沿地图平面平移，保持与相机朝向匹配的设置。
- 为什么 FlyControls 或 FirstPersonControls 的按键没有反应？
  确认控制器已连接且处于启用状态；FirstPersonControls 先在画布上按下指针，再在每帧调用 `controls.update(delta)`，并在页面切换时清空残留按键状态。
- 为什么 Pointer Lock 的按钮没有效果？
  让 `lock()` 直接响应用户点击，并检查浏览器权限和嵌入页面限制；详见 [MDN Pointer Lock API](https://developer.mozilla.org/docs/Web/API/Pointer_Lock_API)。
- 为什么切页后旧控制器仍然响应鼠标或键盘？
  卸载时调用 `controls.dispose()`，并清理应用自己注册的键盘、可见性和尺寸监听。

## 总结回顾

摘要：

相机控制器是输入到相机变换的适配器。围绕目标、地图、自由轨迹球、六自由度飞行和指针锁定分别对应不同的空间约束；选对模型后，还要匹配它的更新契约，明确哪个 DOM 元素和哪个控制器拥有输入，并在切换或卸载时断开和销毁。

一句话：

> 先按相机与目标的关系选择控制器，再按该控制器的更新和生命周期契约接入渲染循环。

知识要点：

- 七种相机控制器分别适合什么交互目标？
- `OrbitControls`、`ArcballControls` 和 `TrackballControls` 的朝上约束有什么区别？
- 哪些控制器必须逐帧调用 `update()`，参数为什么有时需要 `delta`？
- `MapControls` 相比 `OrbitControls` 改变了哪些默认输入和移动平面？
- `FlyControls`、`FirstPersonControls` 和 `PointerLockControls` 各自负责哪部分第一人称体验？
- `enabled`、`disconnect()` 和 `dispose()` 分别应该在何时使用？
- 多个 Canvas 或多个工具共存时，怎样限制渲染成本和输入冲突？
