# 相机控制器

相机控制器不是相机。它监听鼠标和触控事件，把输入换算成 `camera.position` 和朝向的变化，让用户在画布上环绕、缩放、平移场景。场景对象始终不动，动的只有相机。

相机本身怎么摆、视锥体怎么定，见「相机」；本课只讲输入如何驱动那台已经建好的相机。

## 整体结构

```text
鼠标 / 触控事件
  落在 renderer.domElement 上
        ↓
控制器  OrbitControls 等
  按交互模式换算成相机姿态变化
        ↓
camera.position / 朝向
  场景对象不动，观察结果变了
        ↓
controls.update()
  阻尼、自动旋转等随时间推进的效果在这里走一步
```

控制器挂在相机和 canvas 之间：构造时传入两者，之后只改相机，不碰场景树。销毁时必须 `dispose()`，否则事件监听会留在 canvas 上。

常见控制器按交互模式选型：

| 控制器 | 交互模式 | 适合场景 |
| --- | --- | --- |
| `OrbitControls` | 绕固定 target 环绕、缩放、平移 | 模型查看器、默认 3D 预览 |
| `MapControls` | 地面平移为主，相机始终朝下 | 地图、俯视场景 |
| `TrackballControls` | 自由滚转，没有固定的"上" | 需要任意角度观察的查看器 |
| `FlyControls` / `FirstPersonControls` | 前进后退、抬头低头 | 漫游、第一人称 |
| `PointerLockControls` | 锁定指针后用鼠标看向 | FPS 类交互 |

本课以 `OrbitControls` 为主深入讲清；其他控制器只在选型时对照，不各自展开实例。

## 快速上手

```js
import { OrbitControls } from 'three/addons/controls/OrbitControls.js';

const controls = new OrbitControls(camera, renderer.domElement);
controls.target.set(0, 0.7, 0);
controls.enableDamping = true;

function render() {
  controls.update();
  renderer.render(scene, camera);
  requestAnimationFrame(render);
}

// 页面卸载时
controls.dispose();
```

| 属性 | 默认值 | 作用 |
| --- | --- | --- |
| `target` | `(0, 0, 0)` | 环绕、缩放、平移的观察中心 |
| `enableDamping` | `false` | 松开后继续滑一段再停；开启后必须每帧 `update()` |
| `dampingFactor` | `0.05` | 阻尼强弱 |
| `autoRotate` | `false` | 自动绕 target 旋转；开启后同样依赖每帧 `update()` |
| `enablePan` | `true` | 是否允许右键或双指平移 target |
| `enableZoom` | `true` | 是否允许滚轮缩放 |
| `enableRotate` | `true` | 是否允许拖拽环绕 |
| `minDistance` / `maxDistance` | `0` / `Infinity` | 透视相机下，相机到 target 的距离夹取 |
| `minZoom` / `maxZoom` | `0` / `Infinity` | 正交相机下，对 `camera.zoom` 的夹取 |
| `minPolarAngle` / `maxPolarAngle` | `0` / `π` | 上下俯仰角限制，防止翻转到地面以下 |

## OrbitControls

`OrbitControls` 围绕一个 `target` 点工作。左键拖拽环绕，滚轮缩放，右键平移 target。红色小球标出的就是 `target`。

在画布上拖拽、滚轮缩放、右键平移，读数里的 `target` 和距离会跟着变。滚轮滚到底能看到距离被夹在 `minDistance` 和 `maxDistance` 之间。关掉 `enablePan` 后 target 固定，更像一个模型查看器。

- `controls.target`：观察中心。改完后需要 `controls.update()` 让相机立刻对准新中心。
- `enableDamping` / `autoRotate`：随时间推进的效果，每次 `update()` 只推进一步，所以要放进渲染循环。
- `minDistance` / `maxDistance`：夹住的是相机到 target 的距离，不是相机的某个坐标分量。
- `controls.dispose()`：移除挂在 canvas 上的全部事件监听。

`controls.update()` 需要每帧调用的原因是：阻尼和自动旋转都是随时间推进的效果。这两项都关掉时，控制器在事件回调里就完成了相机更新，可以不用每帧调——但写成始终调用更稳妥，少一个分支。

## 和其他控制器的边界

- 需要相机始终朝下、以平移为主时，用 `MapControls`，不要硬改 `OrbitControls` 的极角范围去冒充。
- 需要任意滚转、不保留"上"方向时，用 `TrackballControls`。
- 第一人称或指针锁定交互走 `PointerLockControls` / `FirstPersonControls`，它们改的是相机朝向而不是绕 target 环绕。

这些控制器的构造方式与 `OrbitControls` 相同：传入 `camera` 和 `domElement`，用完 `dispose()`。

## 最佳实践

- **模型查看器：开阻尼、关平移。** `enableDamping = true`、`enablePan = false`，观察中心就固定在模型上，不会被右键拖跑。
- **`target` 对准要看的东西。** 加载模型后把 `controls.target` 设到模型中心，再 `controls.update()`；否则环绕会绕着原点转，模型可能在画面边缘。
- **距离限制按包围盒定。** `minDistance` 略大于模型半径，`maxDistance` 按场景尺度放宽，避免钻进模型内部或拉到看不见。
- **控制器和场景一起销毁。** `controls.dispose()` 和 `renderer.dispose()` 要成对出现在页面卸载路径上。
- **不要每帧 `new OrbitControls`。** 控制器只建一次；反复创建会叠多层事件监听。

## 常见问题

| 现象 | 先看哪里 | 判断 |
| --- | --- | --- |
| 阻尼或自动旋转不生效 | `controls.update()` | 是否每帧调用 |
| 控制器围绕奇怪的点转 | `controls.target` | 是否是想看的中心，改完是否 `update()` |
| 滚轮缩放到头了 | `minDistance` / `maxDistance` | 距离已被夹住 |
| 右键拖不动画面 | `enablePan` | 是否被关掉 |
| 切换页面后卡顿 | `controls.dispose()` | 旧控制器的事件监听没有移除 |
| 画布上拖拽没反应 | 构造参数 | 是否传入了正确的 `renderer.domElement` |
| 正交相机滚轮没效果 | `minZoom` / `maxZoom` | 正交下夹的是 zoom，不是 distance |

## 总结回顾

一句话记忆：

> 控制器改相机，不改场景。

相机控制器把输入翻译成相机的摆放变化。`OrbitControls` 以 `target` 为中心做环绕、缩放、平移；阻尼和自动旋转依赖每帧 `controls.update()`；用完必须 `dispose()`。

知识要点：

- 控制器不是 `Object3D`，不进场景树；它挂在相机和 canvas 之间。
- `target` 是环绕中心，红色小球标出的就是它。
- `enableDamping` 或 `autoRotate` 开启时，必须每帧调用 `controls.update()`。
- `minDistance` / `maxDistance` 夹的是相机到 target 的距离；正交相机对应 `minZoom` / `maxZoom`。
- 页面卸载时调用 `controls.dispose()`，否则事件监听泄漏。

覆盖边界：

- 本课覆盖 `OrbitControls` 的常用属性、更新时机和销毁，以及其他控制器的选型对照。
- 不覆盖：相机本身的投影与摆放（见「相机」）；`TransformControls`（它改的是场景对象而不是相机，见「TransformControls」条目）；自定义控制器的实现细节。
