# Sprite

`THREE.Sprite` 是一种始终面向相机的特殊 `Object3D`。它继承 Object3D 的 `position`、`scale`、`visible`、`renderOrder` 与父子层级，但渲染时被 renderer 当成一张贴在屏幕上的四边形：每帧根据相机方向重算朝向，让"正面"始终对着观察者，不会因相机移动而变形或露出侧边。

Sprite 没有 geometry 参数——构造函数只接收一个 `SpriteMaterial`，所有 Sprite 共享 three.js 内部的一张单位四边形几何。它的外观几乎全部由 material 决定：`map` 提供纹理（通常是用 `<canvas>` 生成的文字或图标），`color` 叠加色调，`rotation` 绕屏幕中心额外旋转，`sizeAttenuation` 决定是否按距离透视缩放，`transparent` / `opacity` / `alphaMap` 控制半透明，`depthTest` / `depthWrite` 控制与场景深度的合成。Sprite 不参与光照、没有 `side`（永远正面朝相机）、`sprite.rotation` 不会改变朝向。这些限制正是它最常用的原因——制作 3D 场景里的标签、图标、位置标注和光晕。

## 快速上手

用 `<canvas>` 写文字生成 `CanvasTexture`，把它作为 `SpriteMaterial.map`，再交给 `Sprite`：

```js
const texture = makeLabelTexture('原点');      // 返回 THREE.CanvasTexture
const material = new THREE.SpriteMaterial({
  map: texture,
  depthTest: false                              // 标签常关，避免被前景物体遮挡
});
const sprite = new THREE.Sprite(material);
sprite.position.set(0, 1.3, 0);
sprite.scale.set(1.6, 0.6, 1);                  // x、y 决定屏幕大小；z 保留 1
scene.add(sprite);
```

| 输入或状态 | 默认值 | 改变后要注意什么 |
| --- | --- | --- |
| `new THREE.Sprite(material)` | 内部固定四边形 | 不传 material 时使用默认 `SpriteMaterial`；不接受 geometry 参数 |
| `sprite.position` | `(0, 0, 0)` | 决定挂点；和其他 Object3D 一样受父级链影响 |
| `sprite.scale` | `(1, 1, 1)` | x、y 决定显示尺寸；z 不参与渲染，保留 1 便于整体缩放 |
| `sprite.center` | `(0.5, 0.5)` | 旋转和缩放的锚点（归一化 UV）；`(0, 0)` 把锚点移到左下角 |
| `sprite.material` | 默认 `SpriteMaterial` | 运行时可整体替换；多个 Sprite 共享同一份 material 是常见做法 |
| `SpriteMaterial.map` | `null` | 与 `color` 相乘作为最终颜色；为 `null` 时只显示 `color` |
| `SpriteMaterial.color` | 白色 `0xffffff` | 与 `map` 像素相乘；无 `map` 时即为底色 |
| `SpriteMaterial.transparent` / `opacity` | `true` / `1` | `transparent` 默认就是 `true`，区别于多数 Material |
| `SpriteMaterial.sizeAttenuation` | `true` | `false` 时 Sprite 在屏幕上保持恒定大小，适合 HUD 类标注 |
| `SpriteMaterial.rotation` | `0`（弧度） | 绕 Sprite 屏幕中心（即 `center`）的额外旋转；不影响 `position` |

## 始终面向相机

Sprite 的核心特征是 billboard：renderer 每帧把它的朝向对齐到相机，让"正面"始终正对观察者。因此：

- 相机绕到 Sprite 背后，看到的还是它的正面（文字仍可读，不会反字）。
- `sprite.rotation` / `quaternion` 不会改变它的朝向——这两个值描述的是它在世界中的额外旋转，但 billboard 覆盖了朝向；要绕屏幕中心旋转得改 `sprite.material.rotation`。
- 一张 Sprite 永远是屏幕对齐的矩形，不会因视角倾斜变成平行四边形或线段。

普通 Mesh 不具备这种行为。同样用 `PlaneGeometry` + `MeshBasicMaterial` 做的标签，只有相机正对它时才可读；相机绕到侧面或背面时会侧转、镜像或被剔除。

下面的实例把四个 Sprite 标签摆在中心四周，并在原点放一个使用同样 `CanvasTexture` 的 Mesh 平面做对照。开启"相机自动旋转"后，Sprite 始终可读，Mesh 平面则随相机方向逐渐侧转、绕到背面时变成镜像（本例开了 `DoubleSide`，否则会被剔除）。`SpriteMaterial.rotation` 是绕屏幕中心的额外旋转，不影响 `position`；`sizeAttenuation` 关闭后 Sprite 不再随距离变小。

## SpriteMaterial 关键属性

Sprite 的外观几乎全由 `SpriteMaterial` 决定。它继承自 `Material`，但只暴露与"屏幕空间四边形"相关的入口，因此没有 `side`、`metalness`、`roughness`、`emissive` 等光照属性。

| 属性 | 默认值 | 用途与边界 |
| --- | --- | --- |
| `map` | `null` | Sprite 的纹理；通常用 `CanvasTexture` 写文字或画图标。为 `null` 时只显示 `color` |
| `color` | `0xffffff` | 与 `map` 像素相乘的色调；为 `null` map 时即为底色 |
| `alphaMap` | `null` | 仅取其 alpha 通道作为额外遮罩；红色贴图常用作形状遮罩 |
| `rotation` | `0` | 绕 `sprite.center`（默认中心）的屏幕空间旋转（弧度）；正方向逆时针 |
| `sizeAttenuation` | `true` | `true` 按透视距离缩放（远小近大）；`false` 保持屏幕恒定大小，适合 HUD |
| `transparent` / `opacity` | `true` / `1` | `transparent` 默认就是 `true`；半透明感由 `opacity` 控制 |
| `depthTest` / `depthWrite` | `true` / `true` | 标签常关 `depthTest`，让它叠在所有 3D 物体之上；关 `depthWrite` 避免透明 Sprite 写入深度缓冲 |
| `fog` | `true` | 是否受场景 `Fog` / `FogExp2` 影响 |
| `blending` | `NormalBlending` | 光晕、加亮标注常用 `AdditiveBlending` |
| `toneMapped` | `true` | 配合 renderer 的 tone mapping；自绘 UI 一般关掉以保持颜色 |

```js
// HUD 类标注：屏幕恒定大小、不被深度遮挡。
const hud = new THREE.Sprite(new THREE.SpriteMaterial({
  map: iconTexture,
  depthTest: false,
  depthWrite: false,
  sizeAttenuation: false
}));
hud.renderOrder = 999;
```

`SpriteMaterial` 不参与光照——颜色直接取自 `map × color`。需要"会反光"或带材质的标签时，应当用 Mesh + `MeshStandardMaterial` 自行实现 billboard（让 mesh 每帧 `lookAt(camera.position)`），而不是 Sprite。WebGL 渲染路径下 material 类型是 `SpriteMaterial`；WebGPU 路径下对应的是 `SpriteNodeMaterial`，本课不展开。

## 标签、图标与光晕的常见做法

Sprite 最常见的用途是把 2D 信息贴在 3D 空间某点：

- **文字标签：** 用 `<canvas>` 画文字 + 圆角底色，生成 `CanvasTexture` 作为 `map`。文本变更时改画布再置 `texture.needsUpdate = true`，或直接重建纹理。
- **位置标注：** 在关键点上方放一个小 Sprite 图标，配合 `depthTest: false` 让它穿透遮挡显示。
- **HUD 元素：** 把 `sizeAttenuation` 关掉，让 Sprite 在屏幕上保持固定大小，用来标注屏幕坐标元素（前提是相机相对静止）。
- **光晕 / 精灵：** 用径向渐变的 alpha 纹理 + `AdditiveBlending`，做太阳光晕、粒子精灵、能量场等发光效果。

```js
function makeLabelTexture(text, color) {
  const canvas = document.createElement('canvas');
  canvas.width = 256;
  canvas.height = 96;
  const ctx = canvas.getContext('2d');

  // 圆角底色 + 白色描边，让标签在任意背景上都可读。
  ctx.fillStyle = color;
  ctx.strokeStyle = 'rgba(255,255,255,0.85)';
  ctx.lineWidth = 6;
  roundRect(ctx, 4, 4, 248, 88, 18);
  ctx.fill();
  ctx.stroke();

  ctx.fillStyle = '#fff';
  ctx.font = 'bold 44px system-ui, sans-serif';
  ctx.textAlign = 'center';
  ctx.textBaseline = 'middle';
  ctx.fillText(text, 128, 48);

  const texture = new THREE.CanvasTexture(canvas);
  texture.colorSpace = THREE.SRGBColorSpace;
  return texture;
}
```

`sprite.center` 是 Sprite 自身（不是 material）的属性，控制旋转和缩放的锚点，用归一化 UV 表示，默认 `(0.5, 0.5)` 即几何中心。需要把标签"挂在锚点上方"时改成 `(0.5, 0)` 会让 Sprite 从底部开始向上延伸；旋转角度时也绕这个点转。

## 与 Points 的边界

`Points` 和 `Sprite` 都能"在 3D 空间贴一张面片"，但形态与使用场景不同：

| 维度 | `Sprite` | `Points` |
| --- | --- | --- |
| 数量级 | 单个或少量，每个独立可控 | 大量顶点（数千到数百万），统一外观 |
| 几何输入 | 无，所有 Sprite 共享内部单位四边形 | `BufferGeometry` 的 position attribute |
| 材质 | 每实例一个 `SpriteMaterial` | 一份 `PointsMaterial` 批量使用 |
| 单独控制 | 每个 Sprite 独立 position、scale、rotation、map | 默认共享同一张 map 与外观；个别差异要靠 attribute 或 shader |
| 典型用途 | 文字标签、位置标注、HUD、独立图标、光晕 | 粒子系统、点云、星空、大批量点 |

需要"几十个独立可控的标签"时，用一组 Sprite；需要"几万个小点统一表现"时，用 Points。两者中间的"几百个图标"区间，取决于是否需要每个图标独立纹理——独立纹理用 Sprite 集合，统一外观用 Points。

## 资源与释放

Sprite 的资源生命周期与 Mesh 一致：从场景移除不会释放 GPU 资源，必须显式 dispose。`CanvasTexture` 也是 Texture，要单独释放。

```js
scene.remove(sprite);
sprite.material.map?.dispose();    // CanvasTexture 也要释放
sprite.material.dispose();
```

多个 Sprite 共享同一个 `SpriteMaterial`（包括它的 `map`）能减少内存和绘制状态——批量标签、批量图标常用做法。共享时修改任何一个 Sprite 的 material 属性会同时影响所有共享者；只想改一个 Sprite 时为它单独创建或克隆一份 material。释放共享资源前先确认没有其他 Sprite 还在引用它，否则会让其他标签的 `map` 失效变黑。

## 最佳实践

- 文字标签优先用 `<canvas>` + `CanvasTexture` 生成纹理；不要用 DOM 叠加层"贴标签"，会丢失深度合成和场景一致性。
- 半透明 Sprite 想覆盖前景时同时关 `depthTest` 并提高 `sprite.renderOrder`；只关一个可能仍被另一帧的绘制顺序覆盖。
- 多个相同外观的 Sprite 共享 `SpriteMaterial`；需要独立颜色、旋转或 map 时再分裂出独立 material。
- 改 `CanvasTexture` 画布后置 `texture.needsUpdate = true`；完全更换标签内容时直接新建纹理并 dispose 旧的，避免内存累积。
- 不要给 Sprite 调 `lookAt()`——它已经永远朝向相机，调用没有意义。
- 需要光照或复杂材质时改用 Mesh + 每帧 `lookAt(camera.position)` 自行实现 billboard，而不是 Sprite。
- 释放共享 material 前确认引用计数；多个 Sprite 共用同一份 material 时，dispose 一次会让所有引用者都失去 `map`。

## 常见问题

- 为什么 Sprite 看不到？
  先检查 `material.map` 是否有效（纹理是否已加载）、`material.color` 是否被设成纯黑、`material.opacity` 是否为 0；再确认 Sprite 的 `position` 是否在相机视锥内、`scale` 是否过小、`visible` 是否为 `false`。
- 为什么标签边缘有黑边或白边？
  检查 `CanvasTexture` 画布的 alpha 通道；标签底色应当完全不透明（alpha=1），让圆角外侧 alpha=0。`SpriteMaterial.transparent` 默认是 `true`，所以一般是画布本身边缘像素的颜色与 alpha 不匹配。
- 为什么多个 Sprite 改一个颜色其他也跟着变？
  它们共享了同一个 `SpriteMaterial`；需要独立外观时为每个 Sprite 创建独立的 material（`material.clone()` 或新建）。
- 为什么 Sprite 被前景物体挡住了？
  `SpriteMaterial.depthTest` 默认是 `true`。标签类用法常关 `depthTest` 并提高 `sprite.renderOrder`，让它叠在所有 3D 物体之上。
- 为什么 `sprite.rotation` 没效果？
  Sprite 的朝向永远跟相机；要绕屏幕中心额外旋转，改 `sprite.material.rotation`（弧度），锚点由 `sprite.center` 控制。
- 为什么改了 `scale.z` 没变化？
  Sprite 是平面，只有 `scale.x` / `scale.y` 影响显示尺寸；`scale.z` 一般保留 1。
- 为什么释放一个 Sprite 后其他 Sprite 的标签变黑了？
  这两个 Sprite 共享了 `SpriteMaterial`（或共享 `map`）；dispose 一份会让所有引用者失去 `map`。释放前先确认引用关系，或为每个 Sprite 拥有独立的 material。

## 总结回顾

摘要：

Sprite 是始终面向相机的特殊 Object3D。它没有 geometry 参数，构造只接收 SpriteMaterial，内部固定为单位四边形。renderer 每帧根据相机方向重算朝向，因此 Sprite 永远是屏幕对齐的矩形，不会因视角变形或露出侧边。外观由 SpriteMaterial 的 `map`、`color`、`alphaMap`、`rotation`、`sizeAttenuation`、`depthTest` / `depthWrite` 等属性控制；锚点由 Sprite 自身的 `center` 决定。Sprite 不参与光照，常用于文字标签、位置标注、HUD 和光晕。与 Points 的边界是"少量独立可控 vs 大量统一表现"；与 Mesh billboard 的差别是 Sprite 不需要应用层每帧 `lookAt(camera)`。

一句话：

> Sprite 是 3D 空间中的 2D 标签：它的位置在世界里，它的"正面"永远跟着相机。

知识要点：

- Sprite 与 Mesh 在"面向相机"这件事上的本质差别是什么？
- 为什么 `sprite.rotation` 不会改变它的朝向？要绕屏幕中心旋转该改什么？
- `sizeAttenuation` 开和关分别适合什么场景？
- 标签类 Sprite 通常要关 `depthTest`，原因是什么？
- 什么场景应该用多个 Sprite 集合，什么场景应该改用 Points？
