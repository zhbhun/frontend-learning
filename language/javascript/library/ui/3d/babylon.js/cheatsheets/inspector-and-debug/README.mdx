# 调试

Babylon.js 的调试不是凭感觉改参数，而是建立可观察的反馈环：改一个值，立刻在画面、读数或控制台看到结果。本课把日常排查归纳为四条互补的渠道，它们各自回答不同的问题，组合起来才能快速定位"为什么画面不对"或"为什么卡"。

四条渠道由不同的工具承载，出问题时先分清走哪一条：

- **Inspector 看场景全景。** `@babylonjs/inspector` 独立成包，`Inspector.Show(scene, { overlay: true })` 弹出全屏调试面板，可以查场景树、对象属性、纹理、性能计数和后处理——是头号工具。它也是 `scene.debugLayer` 的程序入口。
- **AxesViewer 把空间关系画出来。** 原点的三色世界轴（X 红、Y 绿、Z 蓝）让朝向、左手系和对象位置有视觉对照，[坐标与尺寸](?path=/docs/coordinate-system-and-units--docs) 已经用过。
- **性能计数看帧率与开销。** `SceneInstrumentation` 读 draw calls 与各类耗时，`EngineInstrumentation` 读 GPU 帧时间，`engine.getFps()` 读帧率。
- **日志与控制台查对象状态。** `Logger` 收集引擎级警告和错误，`console` 配合 `scene.getNodeByName(name)`、`scene.meshes` 确认对象是否真的在场景里、属性是否真的改了。

Inspector 是全屏覆盖层，不适合嵌在 Storybook Canvas 里——本课用代码片段展示它的用法；AxesViewer 和性能计数用下方范例的交互 Canvas 演示。

| 工具 / 入口 | 包 / 来源 | 默认值 / 起点 | 改变后要注意什么 |
| --- | --- | --- | --- |
| `Inspector.Show(scene, options)` | `@babylonjs/inspector`（独立包） | `overlay` 默认 false（推开画布） | 全屏覆盖层；需单独安装，[安装](?path=/docs/install-babylonjs--docs) 课已提及 |
| `scene.debugLayer.show()` | `@babylonjs/core`（渲染需 inspector 包） | 同 Inspector | 程序入口与 `Inspector.Show` 等价 |
| `new AxesViewer(scene, scaleLines)` | `@babylonjs/core/Debug` | `scaleLines` 控制线长 | 会向 `scene.meshes` 注入 LinesMesh，影响 Mesh 数与 draw calls |
| `new SceneInstrumentation(scene)` | `@babylonjs/core` | `drawCallsCounter` 始终可用 | 时间类计数器需 `capture* = true`；计数器每帧开头重置 |
| `new EngineInstrumentation(engine)` | `@babylonjs/core` | 默认不采集 | `captureGPUFrameTime` 依赖 EXT_DISJOINT_TIMER_QUERY，部分浏览器不可用 |
| `engine.getFps()` | `@babylonjs/core` | 滑动平均帧率 | 标签页失焦时浏览器节流 rAF，读数不可信 |
| `Logger` | `@babylonjs/core/Misc/logger` | 默认输出到 console | 上下文丢失、dispose 顺序等引擎级警告都走这里 |

## 快速上手

最小调试闭环：单独安装 `@babylonjs/inspector`，用 `Inspector.Show` 打开面板，加一个 `AxesViewer`，再在每帧读 `engine.getFps()` 和 draw calls。这一段同时点亮 Inspector、坐标轴和性能计数三条渠道。

```ts
import { AxesViewer, Engine, Scene, SceneInstrumentation } from '@babylonjs/core';
import { Inspector } from '@babylonjs/inspector';

const engine = new Engine(canvas, true);
const scene = new Scene(engine);

// 头号工具：弹出全屏调试面板，查场景树 / 属性 / 纹理 / 性能。
Inspector.Show(scene, { overlay: true });

// 原点三色世界轴：X 红、Y 绿、Z 蓝，让朝向和位置有视觉对照。
new AxesViewer(scene, 2);

// drawCallsCounter 始终可用；时间类计数器另需 capture 标志。
const instrumentation = new SceneInstrumentation(scene);
instrumentation.captureFrameTime = true;

scene.onAfterRenderObservable.add(() => {
  console.log('draw calls', instrumentation.drawCallsCounter.current);
  console.log('fps', engine.getFps());
});

engine.runRenderLoop(() => scene.render());
```

`Inspector.Show(scene, options)` 与 `scene.debugLayer.show(options)` 是同一个面板的两个入口：`scene.debugLayer` 是 Scene 上的调试层属性，内部委托给 Inspector，两者都依赖 `@babylonjs/inspector` 包。`onAfterRenderObservable` 在每帧 `scene.render()` 之后触发，此时计数器刚被填入本帧的值，是读 draw calls 的正确时机。

## Inspector 调试面板

Inspector 是排查的第一站——不用猜场景里有什么，打开面板直接看。它独立成包 `@babylonjs/inspector`，需要单独安装（`npm install @babylonjs/inspector`，[安装](?path=/docs/install-babylonjs--docs) 课已提及该包），再在代码里显式打开：

```ts
import { Inspector } from '@babylonjs/inspector';

Inspector.Show(scene, { overlay: true });
```

`overlay: true` 让面板覆盖在画布上方；默认行为是推开（resize）画布腾出空间。也可以用 Scene 上的入口，效果相同：

```ts
scene.debugLayer.show({ overlay: true });
scene.debugLayer.select(mesh); // 打开后直接选中某个对象
scene.debugLayer.hide();
```

### 面板能看什么

Inspector 是多 Tab 面板，对应"看场景全景"的几个维度：

| Tab / 区域 | 回答的问题 | 典型排查 |
| --- | --- | --- |
| 场景树（Scene Explorer） | 场景里到底有哪些对象、父子层级如何 | "我加的对象怎么没出现"——先在这里找它在不在树里 |
| 属性（Inspector / Properties） | 选中对象的 position、material、visibility 等实时值 | 改了代码但画面没变时，看属性有没有真的更新 |
| 纹理（Textures） | 当前贴图长什么样、UV 是否合理 | 贴图反了、颜色空间不对时直接预览 |
| 统计（Statistics） | draw calls、三角形数、顶点数、FPS | 卡顿时看哪个数字异常 |
| 后处理（Post Processes） | 当前管线挂了哪些后效 | bloom / SSAO 没生效时检查管线 |

Inspector 还能直接编辑属性、跳转到 Node Material Editor、保存场景状态。它覆盖了"看场景全景"的全部需求，日常排查优先打开它。

### panel 选项

`Inspector.Show`（与 `scene.debugLayer.show`）的第二个参数控制面板的弹出方式：

| 选项 | 作用 |
| --- | --- |
| `overlay` | `true` 覆盖在画布上；`false`（默认）推开画布腾出空间 |
| `popup` | `true` 在新窗口弹出，独立于当前页面 |
| `parentElement` | 指定面板挂载的 DOM 容器；默认从 engine 的 canvas 向上找 |
| `initialTab` | 打开时聚焦的 Tab，例如 `'Statistics'`、`'Inspector'` |

> 新版 Inspector（`@babylonjs/inspector-v2`）改用 `InspectorV2` 的 `layoutMode`（`'overlay'` / `'inline'`）、`themeMode`、`containerElement` 等选项，语义更明确；旧版 `Inspector.Show` 的 `overlay` / `popup` 在当前版本仍然兼容。

在官方 [Playground](https://playground.babylonjs.com/) 里也可以用快捷键 `Ctrl+Shift+Alt+I` 切换调试层，不必写代码。

## 坐标轴与 AxesViewer

AxesViewer 在原点画三色世界轴——X 红、Y 绿、Z 蓝，让"朝哪边""在哪儿""是不是左手系"有视觉对照。[坐标与尺寸](?path=/docs/coordinate-system-and-units--docs) 用它对照过默认左手系和局部/世界坐标，本课关注它的调试用法。

```ts
import { AxesViewer } from '@babylonjs/core';

new AxesViewer(scene, 2); // 第二个参数 scaleLines 控制线长
```

`scaleLines` 决定轴的视觉长度，不影响场景中其他对象。AxesViewer 内部用 `LinesMesh` 画线，因此会向 `scene.meshes` 注入若干 LinesMesh——这就是下方范例里"开关坐标轴"时 Mesh 数和 draw calls 会变化的原因。AxesViewer 还能跟随对象或自定义朝向（`axesViewer.update(position, xAxis, yAxis, zAxis)`，参数均为 `Vector3`），用来给移动对象挂局部轴。交付前如果不希望辅助轴出现在画面里，调用 `axesViewer.dispose()` 移除，不要只靠 `isVisible` 隐藏——它仍在场景树和 draw calls 里。

## 性能计数与帧率

性能排查有两种互补读数：时间维度（卡不卡）和内容维度（每帧干了什么）。Babylon 把它们分成 Scene 级和 Engine 级两套计数器。

### SceneInstrumentation

`SceneInstrumentation` 给出每帧的 draw calls 和各类耗时。`drawCallsCounter` 始终可用，时间类计数器需用 `capture*` 标志开启：

```ts
import { SceneInstrumentation } from '@babylonjs/core';

const instrumentation = new SceneInstrumentation(scene);
instrumentation.captureFrameTime = true;
instrumentation.captureRenderTime = true;

scene.onAfterRenderObservable.add(() => {
  console.log('draw calls', instrumentation.drawCallsCounter.current);
  console.log('render ms', instrumentation.renderTimeCounter?.lastSecAverage);
});
```

每个计数器是一个 `PerfCounter`，主要读法：`.current`（本帧值）、`.average`（滑动平均）、`.lastSecAverage`（上一秒平均）。单帧值跳动大，观察趋势用秒平均更稳。计数器在每帧开头重置，在 `onAfterRenderObservable` 里读到的是刚结束这一帧的值。

| 计数器 | capture 标志 | 含义 |
| --- | --- | --- |
| `drawCallsCounter` | 始终可用 | 每帧 draw call 数（目标越低越好） |
| `frameTimeCounter` | `captureFrameTime` | 处理整帧耗时（ms） |
| `renderTimeCounter` | `captureRenderTime` | 渲染一帧耗时（ms） |
| `interFrameTimeCounter` | `captureInterFrameTime` | 两帧之间间隔（ms） |
| `activeMeshesEvaluationTimeCounter` | `captureActiveMeshesEvaluationTime` | 评估活跃 mesh 耗时 |
| `renderTargetsRenderTimeCounter` | `captureRenderTargetsRenderTime` | 渲染目标纹理耗时 |

### EngineInstrumentation

`EngineInstrumentation` 给出 GPU 侧的帧时间和着色器编译时间，依赖浏览器的 `EXT_DISJOINT_TIMER_QUERY` 扩展，部分浏览器（尤其无 GPU 访问的环境）不可用：

```ts
import { EngineInstrumentation } from '@babylonjs/core';

const engineInstrumentation = new EngineInstrumentation(engine);
engineInstrumentation.captureGPUFrameTime = true;
engineInstrumentation.captureShaderCompilationTime = true;

// 读 GPU 帧时间滑动平均（扩展不可用时计数器不更新）。
console.log(engineInstrumentation.gpuFrameTimeCounter.lastSecAverage);
```

不可用时回退到 CPU 侧的 `SceneInstrumentation.frameTimeCounter`，它不依赖浏览器扩展。

### 帧率

`engine.getFps()` 返回引擎内部维护的滑动平均帧率，比手算 `1000 / deltaTime` 更稳——不需要自己维护帧历史。[渲染循环与时间](?path=/docs/render-loop-and-timing--docs) 用 `getDeltaTime` 推进状态，本课用 `getFps` 报告帧率，两者来自同一套引擎计时。

## 日志与控制台

控制台是最低成本的反馈渠道。Babylon 的引擎级消息走 `Logger`（`@babylonjs/core/Misc/logger`）——上下文丢失、dispose 顺序、WebGL 限制等警告都通过它输出，默认写到 `console`。调高日志级别能压噪：

```ts
import { Logger } from '@babylonjs/core';

// 只保留警告和错误，屏蔽普通 Log。
Logger.LogLevels = Logger.WarningLogLevel | Logger.ErrorLogLevel;
```

排查具体对象时，用 `scene` 的查询方法而不是凭记忆：

```ts
scene.getNodeByName('box');     // 按名查节点
scene.getMeshByName('box');     // 按名查 mesh（带类型）
scene.meshes.length;            // 当前 mesh 数（含 AxesViewer 的 LinesMesh）
scene.transformNodes.length;    // TransformNode 数
scene.lights.length;            // 光源数
```

避免在 `onBeforeRenderObservable` 里每帧 `console.log`——控制台会被刷爆。要观察随时间变化的值，用范例这样的 readout 区或 Inspector 的 Statistics 面板；要快照检查，用 `debugger` 暂停在事件回调里，再到 Console 直接查看当前作用域的对象和材质。

## 调试工作流

把上面的工具串成一条排查路径，比"同时改所有参数"快得多：

1. **先开 Inspector。** `Inspector.Show(scene, { overlay: true })`，在场景树里确认对象在不在、父子层级对不对——"对象没出现"绝大多数是它根本不在树里，或 parent 不对。
2. **定位对象，看属性。** 在场景树里选中它，看 position、rotation、scaling、visibility、material 是否如预期。改了代码但画面没变，先在这里验证属性有没有真更新。
3. **看纹理和材质。** 贴图反了、颜色不对、透明失效时，在 Inspector 的 Textures / 材质面板直接预览，确认 UV、color space、alpha mode。
4. **看 Statistics。** 卡顿时打开统计 Tab，看 draw calls、三角形数、FPS 哪个异常；再用 `SceneInstrumentation` 在代码里读同一组数字，做自动化告警。
5. **最小复现。** 把问题剥到最小——换基础材质排除光照、移除后处理排除管线、用 AxesViewer 对照朝向，直到原因唯一。

这套流程也是向社区提 issue 时最有效的附件：维护者没有你的项目，但能跑你的最小复现。

## 最佳实践

- 日常开发期一直开着 Inspector 和 AxesViewer，交付前 `dispose()` 辅助对象、关掉 Inspector——辅助工具不是最终画面的一部分。
- 性能排查用 `SceneInstrumentation`（draw calls、各类耗时）与 `engine.getFps()`（帧率）互补：前者看"每帧干了什么"，后者看"卡不卡"。
- 读 `PerfCounter` 用 `.current`（本帧）或 `.lastSecAverage`（上一秒平均）；单帧值跳动大，秒平均更稳。
- `captureGPUFrameTime` 依赖浏览器扩展，目标环境不可用时回退到 `frameTimeCounter`（CPU 侧）。
- 控制台 `console.log` 用于一次性快照，不用来观察每帧变化的值；后者用 Inspector 的 Statistics 或范例里的 readout。
- 最小复现是定位问题的核心习惯：一开始就剥离业务代码、后处理和复杂材质，而不是"最后没办法才用"。

## 常见问题

- 为什么 `Inspector.Show` 报错或面板不出现？
  Inspector 独立成包 `@babylonjs/inspector`，需要单独安装；只装 `@babylonjs/core` 不会带上它。`scene.debugLayer.show()` 同样依赖这个包。
- 为什么 `drawCallsCounter.current` 读到 0？
  计数器在每帧开头重置，必须在 `onAfterRenderObservable`（或 `scene.render()` 之后）读；在 `onBeforeRenderObservable` 里读到的是上一帧残留或 0。
- 为什么 FPS 突然跌到个位数？
  切到别的标签页或最小化窗口时，浏览器把 `requestAnimationFrame` 节流到每秒约 1 次；回到页面后会恢复。这不是性能问题，但会让 `getFps()` 读数暂时不可信。
- 为什么 Mesh 数比预期多？
  AxesViewer、HighlightLayer、阴影生成器等都会向 `scene.meshes` 注入内部 mesh（AxesViewer 用 LinesMesh）。`dispose` 这些工具后对应 mesh 才会移出。
- 为什么 `captureGPUFrameTime` 开了却读不到值？
  `EngineInstrumentation` 的 GPU 计时依赖 `EXT_DISJOINT_TIMER_QUERY` 扩展，部分浏览器（尤其隐私模式或无 GPU 访问的环境）不提供；改用 CPU 侧的 `SceneInstrumentation.frameTimeCounter`。
- 为什么改了对象属性，Inspector 里的值没更新？
  检查是否在操作同一个 scene、同一个对象实例（用 `scene.getNodeByName` 确认）；Inspector 显示的是实时值，但如果改的是脱离场景树的对象，面板不会反映。

## 总结回顾

摘要：

Babylon.js 的调试围绕一个反馈环和四条渠道展开。Inspector（`@babylonjs/inspector`，`Inspector.Show(scene, { overlay: true })` 或 `scene.debugLayer.show()`）是头号工具，覆盖场景树、属性、纹理、统计和后处理；AxesViewer 把坐标轴和朝向画成可见的三色线，并会向 `scene.meshes` 注入 LinesMesh；`SceneInstrumentation` / `EngineInstrumentation` 把 draw calls、各类耗时和 GPU 帧时间变成可读的 `PerfCounter`；`engine.getFps()` 报告滑动平均帧率；`Logger` 收集引擎级消息。读 `PerfCounter` 用 `.current` 或 `.lastSecAverage`，并在 `onAfterRenderObservable` 里读以拿到本帧值。串成"先开 Inspector 看场景树 → 定位对象看属性 → 看纹理材质 → 看 Statistics → 最小复现"的排查路径。

一句话：

> 调试是反馈环——Inspector 看场景全景、AxesViewer 看空间关系、计数器看开销、Logger 看引擎消息，先用 Inspector 定位对象再读数字。

知识要点：

- Inspector 的两个等价入口是什么？它由哪个独立包提供？为什么不能只装 `@babylonjs/core`？
- `SceneInstrumentation.drawCallsCounter` 为什么不需要 capture 标志，而 `renderTimeCounter` 需要？在哪个 observable 里读计数器才正确？
- `PerfCounter` 的 `.current` 和 `.lastSecAverage` 各适合什么场景？
- `EngineInstrumentation.captureGPUFrameTime` 依赖什么浏览器扩展？不可用时回退到哪个计数器？
- 为什么 `engine.getFps()` 比手算 `1000 / deltaTime` 更稳？
- AxesViewer 会对 `scene.meshes` 产生什么副作用？交付前应该如何处理？
- 调试工作流的标准排查路径是什么？为什么"最小复现"是核心习惯？
